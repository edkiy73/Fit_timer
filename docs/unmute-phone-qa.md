# UnMute — финальная проверка на телефоне

Этот чек-лист закрывает Этап 6 из `docs/unmute-audit-plan.md`.

## Что уже проверяет CI

Не повторяем вручную то, что стабильно ловится автоматически:

- layout-smoke на компактных ширинах 320 / 360 / 412 px;
- основные learner routes без горизонтального overflow;
- light / dark screen walk;
- `prefers-reduced-motion` для ключевых motion-сценариев;
- lesson / Review e2e;
- сохранение LessonRun и resume-логика unit/e2e;
- production readiness + Android build на каждом push в `main`.

Эти проверки не заменяют реальный Android WebView, системную клавиатуру, убийство процесса и системные настройки шрифта.

## Устройство — обязательные сценарии

### 1. Длинный ответ + клавиатура

1. Открыть задание со свободным вводом.
2. Ввести длинный ответ в 2–3 строки.
3. Переключить «чипы → клавиатура → чипы → клавиатура».
4. Проверить:
   - карточка не прыгает;
   - поле остаётся видно над клавиатурой;
   - кнопка «Проверить» доступна;
   - bottom feedback после ответа не перекрывается клавиатурой;
   - после morph фокус появляется только после перехода.

Результат: ⬜

### 2. Убийство приложения посреди урока

1. Начать новый урок.
2. Выполнить 3–5 заданий, одно специально ошибиться.
3. Свернуть приложение и принудительно закрыть процесс из recent apps.
4. Запустить снова и продолжить урок.
5. Проверить:
   - возврат на сохранённую позицию;
   - уже выполненные задания не повторяются как новые;
   - ошибочное задание остаётся в работе над ошибкой;
   - прогресс дня не засчитывается раньше времени;
   - после финального задания completion записывается один раз.

Результат: ⬜

### 3. Plus → возврат в приложение

1. Открыть действие, которое ведёт в Plus/paywall.
2. Пройти доступный тестовый/реальный сценарий подтверждения Plus.
3. Вернуться в приложение.
4. Проверить:
   - возврат именно в исходный контекст;
   - entitlement обновился без очистки кэша;
   - экран не зацикливается на paywall;
   - незаконченный урок/ответ не потерян.

Результат: ⬜

### 4. Крупный системный шрифт

Проверить минимум на 130–150% font size:

- «Сегодня»;
- «Курс» / roadmap;
- «Повтор»;
- карточка задания с чипами;
- карточка со свободным вводом;
- feedback bottom sheet;
- «Профиль» / статистика;
- настройки уведомлений.

Критерии:
- важный текст не обрезан;
- кнопки не налезают друг на друга;
- нет горизонтального скролла;
- controls остаются нажимаемыми.

Результат: ⬜

### 5. RU / EN

Переключить язык без переустановки и пройти по одному короткому уроку в каждом языке.

Проверить:
- нет смешанных RU/EN системных строк;
- названия типов заданий и feedback переведены;
- notification settings / paywall / Progress переведены;
- после перезапуска выбранный язык сохраняется.

Результат: ⬜

### 6. Status bar + light/dark

В обеих темах проверить:

- старт приложения;
- «Сегодня»;
- полноэкранный урок;
- открытый bottom sheet;
- экран с открытой клавиатурой.

Критерии:
- иконки status bar контрастные;
- нет отдельной грязной полосы сверху;
- safe area соблюдена;
- при смене темы status bar обновляется.

Результат: ⬜

### 7. Уведомления на реальном Android

После первого завершённого урока:

1. Убедиться, что системное разрешение не спрашивается до нажатия «Напоминать в 19:00».
2. Включить.
3. Проверить локальное уведомление и переход по тапу.
4. Прервать урок через «Выйти» и проверить unfinished reminder.
5. Проверить, что ночью уведомлений нет.
6. После занятия в этот день не должно приходить ещё одно учебное уведомление.

Результат: ⬜

## Когда Этап 6 считается закрытым

Все семь сценариев выше — ✅ хотя бы на одном реальном Android-устройстве production APK. Если найден баг, он получает отдельный PR и соответствующий сценарий прогоняется повторно.

Серверный push FCM сюда не входит: пункт 7.7 намеренно отложен, локальных учебных уведомлений для текущего продукта достаточно.
