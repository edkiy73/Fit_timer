# UnMute — финальная проверка на телефоне

Этот чек-лист закрывает Этап 6 из `docs/unmute-audit-plan.md`.

## Что уже проверяет CI

Не повторяем вручную то, что стабильно ловится автоматически:

- layout-smoke на компактных ширинах 320 / 360 / 412 px;
- основные learner routes без горизонтального overflow;
- light / dark screen walk;
- `prefers-reduced-motion` для ключевых motion-сценариев;
- lesson / Review e2e;
- сохранение LessonRun и resume-логика unit/e2e;
- production readiness + Android build на каждом push в `main`;
- Android emulator launch smoke **при 150% системном font scale**; WebView получает реальный `fontScale` через `setTextZoom` (#552);
- Android keyboard viewport contract: `interactive-widget=resizes-content`, чтобы IME уменьшала viewport вместо перекрытия контента (#552);
- system Back policy покрыта unit-тестом: sheet → history, tab → «Сегодня», double Back → minimize.

Эти проверки не заменяют **визуальный** прогон на реальном Android: клавиатура/IME, process kill посреди урока, фактическая верстка при 130–150% font size, system Back в WebView, status bar и реальная доставка push через FCM.

## Устройство — обязательные сценарии

### 1. Длинный ответ + клавиатура

1. Открыть задание со свободным вводом.
2. Ввести длинный ответ в 2–3 строки.
3. Переключить «чипы → клавиатура → чипы → клавиатура».
4. Проверить:
   - карточка не прыгает;
   - поле остаётся видно над клавиатурой;
   - кнопка «Проверить» доступна;
   - bottom feedback после ответа не перекрывается клавиатурой;
   - после morph фокус появляется только после перехода.

Результат: ⬜

### 2. Убийство приложения посреди урока

1. Начать новый урок.
2. Выполнить 3–5 заданий, одно специально ошибиться.
3. Свернуть приложение и принудительно закрыть процесс из recent apps.
4. Запустить снова и продолжить урок.
5. Проверить:
   - возврат на сохранённую позицию;
   - уже выполненные задания не повторяются как новые;
   - ошибочное задание остаётся в работе над ошибкой;
   - прогресс дня не засчитывается раньше времени;
   - после финального задания completion записывается один раз.

Результат: ⬜

### 3. Plus → возврат в приложение

1. Открыть действие, которое ведёт в Plus/paywall.
2. Пройти доступный тестовый/реальный сценарий подтверждения Plus.
3. Вернуться в приложение.
4. Проверить:
   - возврат именно в исходный контекст;
   - entitlement обновился без очистки кэша;
   - экран не зацикливается на paywall;
   - незаконченный урок/ответ не потерян.

Результат: ⬜

### 4. Крупный системный шрифт

Кодовая поддержка закрыта #552: Android `fontScale` прокидывается в WebView `setTextZoom`, emulator smoke запускает приложение при 150%. На устройстве остаётся проверить **визуальный результат** минимум на 130–150% font size:

- «Сегодня»;
- «Курс» / roadmap;
- «Повтор»;
- карточка задания с чипами;
- карточка со свободным вводом;
- feedback bottom sheet;
- «Профиль» / статистика;
- настройки уведомлений.

Критерии:
- важный текст не обрезан;
- кнопки не налезают друг на друга;
- нет горизонтального скролла;
- controls остаются нажимаемыми.

Результат: ⬜

### 5. RU / EN

Переключить язык без переустановки и пройти по одному короткому уроку в каждом языке.

Проверить:
- нет смешанных RU/EN системных строк;
- названия типов заданий и feedback переведены;
- notification settings / paywall / Progress переведены;
- после перезапуска выбранный язык сохраняется.

Результат: ⬜

### 6. Status bar + light/dark

В обеих темах проверить:

- старт приложения;
- «Сегодня»;
- полноэкранный урок;
- открытый bottom sheet;
- экран с открытой клавиатурой.

Критерии:
- иконки status bar контрастные;
- нет отдельной грязной полосы сверху;
- safe area соблюдена;
- при смене темы status bar обновляется.

Результат: ⬜

### 7. Локальные уведомления на реальном Android

После первого завершённого урока:

1. Убедиться, что системное разрешение не спрашивается до нажатия «Напоминать в 19:00».
2. Включить.
3. Проверить локальное уведомление и переход по тапу.
4. Прервать урок через «Выйти» и проверить unfinished reminder.
5. Проверить, что ночью уведомлений нет.
6. После занятия в этот день не должно приходить ещё одно учебное уведомление.

Результат: ⬜

### 8. Серверный remote push на реальном Android

Предусловия:

- production APK собран с `UNMUTE_GOOGLE_SERVICES_JSON_BASE64`;
- UnMute Vercel-проект имеет `FIREBASE_SERVICE_ACCOUNT_JSON` или `FIREBASE_SERVICE_ACCOUNT_BASE64`;
- пользователь вошёл в аккаунт и включил уведомления.

**Проверка 2026-10-05:** production `/api/health` показывает `push.android: true` и `firebaseEnvSeen: ["FIREBASE_SERVICE_ACCOUNT_JSON"]`. Серверный FCM backend **настроен**. `scripts/check-production.mjs` с #553 показывает `androidPush` / `firebaseEnvSeen`; для runtime-конфигурации источником истины считаем production health, а не список прямых project env в Vercel.

Проверить:

1. До явного opt-in приложение само не запрашивает push permission.
2. После включения уведомлений токен устройства регистрируется через общий AppBase Core `push_device`.
3. Отправить тестовый server push на это устройство.
4. Проверить доставку в фоне и при полностью закрытом приложении.
5. Нажать push с `route=/review` и проверить переход в «Повтор».
6. Нажать push с допустимым `/learn/<id>?resume=1` и проверить открытие нужного урока.
7. Push с неизвестным/опасным route не должен увести приложение на произвольный URL.
8. После выключения уведомлений устройство unregister-ится и новые server push на этот токен не приходят.
9. После logout и удаления аккаунта текущий push-token также unregister-ится.
10. После тапа на push сервер получает `notification_event=open`; повторный тап не ломает навигацию.

Результат: ⬜

## Когда Этап 6 считается закрытым

Первые семь сценариев выше — ✅ хотя бы на одном реальном Android-устройстве production APK. Если найден баг, он получает отдельный PR и соответствующий сценарий прогоняется повторно.

Remote push — отдельная release-проверка после реализации общего AppBase push-слоя (#513/#514). Для релиза с server push сценарий 8 также должен быть ✅.
