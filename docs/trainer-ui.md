# Кабинет тренера: план и устройство

## Принцип: сервера нет, а канал проверить надо

Кабинет тренера строится **до** бэкенда, потому что его задача — не хранить данные,
а выяснить, пользуются ли тренеры каналом вообще. Месяц на серверный кабинет ради
ответа «нет» — худший способ потратить месяц.

Поэтому v1 целиком локальная и держится на том, что в приложении **уже работает**:

```
тренер                                        клиент
──────                                        ──────
собирает программу (конструктор)
«Отправить клиенту» → ссылка FIT1   ────────▶  открывает, программа добавилась
запоминает: кому, что, когда                   занимается
                                               «Отправить отчёт тренеру»
карточка клиента пополнилась       ◀────────   ссылка FITR1 обратно
```

Обе стрелки — обычные ссылки в мессенджере. Ни аккаунта, ни регистрации, ни сети.

Когда появится сервер, экраны остаются те же — меняется только то, откуда берутся
клиенты и как приходят отчёты. Это и есть смысл делать кабинет сейчас: он
проектируется как витрина над источником данных, а не вокруг локального хранилища.

### Чего в v1 сознательно нет

- **Приватности программы.** Ссылка FIT1 несёт программу целиком, и кто угодно с
  ссылкой её откроет. Защищать нечего, пока нет платного контента, — разобрано в
  `fresh-take.md`. Тренеру это сказано прямо в интерфейсе, а не умолчано.
- **Автоматических отчётов.** Клиент отправляет отчёт сам, кнопкой. Это честно:
  приложение не следит за человеком и не отсылает ничего без его ведома.
- **Оплаты и тарифов.** Пока канал не подтверждён, тариф обсуждать нечего.

## Данные

Два ключа профиля (оба добавлены в `PROFILE_KEYS` — иначе не сотрутся при удалении
аккаунта):

```js
trainer = {on: true, handle: '@lena.doma', links: 'https://t.me/...'}

clients = [{
  id, name, note,
  programId, programName,      // что отправлено
  sentAt,                      // когда
  reports: [{
    at, n, sec, streak,        // тренировок, секунд, серия
    first, last,               // даты первой и последней
    ex: [{n, a, b}]            // упражнение: было → стало
  }]
}]
```

Программа тренера при отправке штампуется `by: '@ник'` — по нему приложение
клиента понимает, что программа пришла от тренера, и показывает кнопку отчёта.
`by` уже существует в каталоге (`STORE_ITEMS.by`), формат не новый.

Отчёт — код `FITR1.` + base64, ровно тем же приёмом, что `FIT1.` у программы.

## Экраны

### `scrTrainer` — «Клиенты»

Вход: карточка «Тренер» на экране аккаунта.

```
‹ Клиенты

  ┌ сводка ──────────────────────────┐
  │  4 клиента · 3 занимаются        │
  │  18 тренировок за две недели     │
  └──────────────────────────────────┘

  Список
  ┌──────────────────────────────────┐
  │ (М) Марина            6 занятий  │
  │     Кардио без прыжков · 3 дня   │
  │ (И) Игорь             ждёт       │
  │     Сила дома · отправлено вчера │
  └──────────────────────────────────┘
  + Добавить клиента

  Отчёт от клиента
  [ вставить ссылку FITR1 ]  [Добавить]
```

Сводка стоит первой не ради красоты: тренер открывает кабинет, чтобы за две
секунды понять, всё ли идёт. Строка «3 занимаются» отвечает на это, список —
уже подробности.

Строка клиента говорит **состоянием, а не цветом**: «6 занятий», «ждёт»,
«молчит 12 дней». Приглушённость строки — вторична.

### `scrClient` — карточка клиента

```
‹ Марина

  Имя          [Марина            ]
  Заметка      [колено, без прыжков]

  Программа
  Кардио без прыжков · отправлено 3 марта
  [Отправить ссылку]  [Другая программа]

  Занятия
  6 тренировок · последняя 12 марта · серия 3
  Приседания      15 → 18
  Планка          40 → 55 сек
  ↑ отчёт от 12 марта

  Удалить клиента
```

Поля сохраняются на лету — «Сохранить» здесь не нужна, а её отсутствие снимает
вопрос несохранённых изменений (`LEAVE_GUARDS` не трогаем).

## Навигация

Добавляются два экрана, оба **вложенные**: дока внизу у них нет, возврат — `goBackTo`.

```
scrAccount ──▶ scrTrainer ──▶ scrClient
     ◀── goBackTo ──┘   ◀── goBackTo ──┘
```

- `screens[]` += `'scrTrainer'`, `'scrClient'` (без этого `check.py` ругается,
  и `show()` не найдёт экран).
- `ROOT_TABS` не трогаем: кабинет — раздел аккаунта, а не шестая вкладка. Пятая
  вкладка дока стоила бы места главным разделам ради функции, которой пользуется
  меньшинство.
- `prepTab` не трогаем: вложенные экраны наполняются из `openTrainer()` /
  `openClient(id)`, как это уже сделано у `openUserEdit(id)`.

### Правки существующих экранов

| Где | Что добавляется | Условие |
|---|---|---|
| `scrAccount` | Карточка «Тренер»: тумблер, ник, ссылки, строка «Клиенты» | всегда |
| Меню программы (список и `scrStart`) | «Отправить клиенту» | только в режиме тренера |
| `scrStart` | Чип «от @ник» | у программы есть `by` |
| Меню `scrStart` | «Отправить отчёт тренеру» | у программы есть `by` |
| Параметры запуска | `?report=FITR1…` | ссылка от клиента |

## Порядок реализации

1. Данные, загрузка, `PROFILE_KEYS` — чтобы удаление аккаунта сразу было честным.
2. Карточка «Тренер» на аккаунте — вход в раздел.
3. `scrTrainer` и `scrClient` — разметка, стили, отрисовка.
4. Отправка программы клиенту: штамп `by`, попап выбора клиента, запись отправки.
5. Сторона клиента: чип, сбор отчёта, ссылка `FITR1`.
6. Приём отчёта тренером: вставка кода и параметр запуска.
7. Сценарий Playwright на весь круг: отправил → импортировал → отчитался → принял.

## Сделано

Всё, кроме одного: пункты 1–7 плана реализованы и проверены сквозным сценарием
`tests/trainer-flow.js` — тренер отправил, клиент импортировал и отзанимался,
отчёт вернулся, тренер его принял. `pageerror` чист.

Две вещи всплыли по ходу и стоят того, чтобы их помнить:

- **Имя `openTrainer` уже занято.** Так называется страница тренера из каталога
  (`TRAINERS`, попап `#trainerModal`), и весь префикс `tr*` в разметке принадлежит
  ей: `trName`, `trNick`, `trPhoto`, `trAbout`. Объявление функции с тем же именем
  ниже по файлу молча перекрыло первую — ошибки не было, просто кнопка перестала
  работать. Картотека переехала на префиксы `cls*` (экран клиентов) и `coach*`
  (карточка на аккаунте): `openClients`, `renderClients`, `#clsList`, `#coachHandle`.
- **Поля упражнения — `type` и `warmup`.** `kind` и `warm` есть у ШАГА тренировки,
  а не у упражнения, и отчёт с ними молча собирался пустым: рост нагрузки не
  попадал никуда, хотя тренировки считались.

`sw.js` поднят до `fittimer-v6`.
