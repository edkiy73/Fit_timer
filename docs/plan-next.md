## 1. Делегирование действий

### Зачем

Сейчас каждая кнопка привязывается к коду по имени:

```js
$('btnStart').onclick = () => { startWorkout(); };
```

Таких строк **258**, обращений вида `$('имя')` — **887**. Код ищет элемент в
момент запуска приложения. Нет элемента — `$('btnStart')` возвращает пустоту, и
попытка повесить на пустоту действие **роняет весь запуск**. Молча: белый экран,
никакой ошибки человеку.

Это не теория. Ровно так приложение падало, когда я убрал кнопки вместе с
переделкой экранов ИИ, а строки с обработчиками остались.

### Что делаем

Один общий обработчик на всё приложение. В разметке кнопка помечается тем, что
она делает:

```html
<button data-act="start">Начать тренировку</button>
```

В коде — одно место:

```js
const ACTIONS = {
  start: () => startWorkout(),
  // …
};
document.addEventListener('click', e => {
  const btn = e.target.closest('[data-act]');
  if (!btn) return;
  const fn = ACTIONS[btn.dataset.act];
  if (fn) fn(btn, e);
});
```

Что меняется на практике:

- кнопку можно удалить из разметки — ничего не сломается;
- кнопку можно добавить без единой строки кода, если действие уже описано;
- кнопки, которые рисуются из данных (строки списка программ, упражнений,
  профилей), работают сразу — сейчас для них приходится вешать обработчики
  заново после каждой перерисовки.

### Шаги

1. Добавить `ACTIONS` и один обработчик. Полчаса.
2. Перевести на него **новые** экраны — в первую очередь объединённый экран ИИ
   из работы 2.
3. Старое переводить по мере того, как трогаешь экран. Не отдельной задачей.

### Риски

Нет. Старый и новый способ живут рядом сколько угодно долго, переход можно не
заканчивать никогда. Единственное правило: `data-act` — только для кнопок,
которые ничего не хранят в себе. Тумблеры и поля ввода остаются как есть.

### Как проверить

`python3 check.py` — она и так ловит обращения к несуществующим именам.
Плюс обычный прогон: каждая переведённая кнопка должна нажиматься.

## 2. Пять экранов ИИ в один

### Зачем

Пять отдельных экранов делают одно и то же:

| Экран | Разметка | Шаги |
|---|---|---|
| `scrText` | 4193 симв | Какая тренировка нужна → Кто соберёт → Ответ из чата |
| `scrEditAI` | 3289 | Что изменить → Кто внесёт правки → Ответ из чата |
| `scrExAI` | 3291 | Что за упражнение → Кто подберёт → Ответ из чата |
| `scrYouTube` | 2765 | Ссылка на видео → Кто разберёт → Ответ из чата |
| `scrExEdAI` | 2434 | Что изменить → Кто внесёт правки → Ответ из чата |
| **Итого** | **15 972 симв** | одна и та же лестница из трёх шагов |

Отличаются они ровно двумя вещами: что человек вводит на первом шаге и что
уходит в промт. Всё остальное — общее.

Хорошая новость: **поведение уже вынесено в общую функцию** `setupAIAnswer(cfg)`
— она параметризована экраном и умеет показывать поле ответа только тогда, когда
его есть чем наполнить. Дублируется только разметка и обвязка вокруг неё. Это
сильно упрощает работу: логику писать заново не надо.

Дублирование уже проступило наружу: `ytCopyPrompt`, `exaCopyPrompt`,
`exeCopyPrompt` — три функции с одним телом.

Отдельный аргумент по времени: ключ Gemini — временный метод, он уйдёт с
серверным ИИ. **Когда сервер появится, эти экраны придётся переделывать в любом
случае.** Сделать объединение до него — переделывать одно место вместо пяти.

### Что делаем

Один экран `scrAI` со схемой:

```
[ ← ]  Через ИИ

┌─ Что нужно ───────────────────────────────┐
│  [ По описанию ][ Из видео ][ Доработать ] │   ← источник
│  поле ввода, подпись которого зависит      │
│  от выбранного источника                   │
└────────────────────────────────────────────┘

┌─ Кто соберёт ─────────────────────────────┐
│  ▸ Скопировать задание                     │
│  ▸ Скопировать саму программу (только      │
│    для «Доработать»)                       │
└────────────────────────────────────────────┘

┌─ Ответ из чата ───────────────────────────┐  ← появляется после копирования
│  поле для вставки                          │
└────────────────────────────────────────────┘

[ Создать программу ]
```

Упражнения — тот же экран в режиме «одно упражнение»: меняется набор источников
(«Описать» / «Доработать») и то, куда уходит результат.

Описание источника — одна таблица в коде:

```js
const AI_SOURCES = {
  text:   {label:'По описанию', field:'Чего хочешь от тренировки', prompt: buildTextPrompt, apply: applyProgram},
  video:  {label:'Из видео',    field:'Ссылка на тренировку',      prompt: buildYtPrompt,   apply: applyProgram},
  edit:   {label:'Доработать',  field:'Что изменить',              prompt: buildEditPrompt, apply: applyEditedCopy},
  // …
};
```

Добавить шестой источник потом = одна строка в этой таблице.

### Шаги

1. Собрать `AI_SOURCES` из того, что уже есть в пяти экранах. Ничего не
   переписывать — просто перенести.
2. Написать разметку одного экрана (на делегировании из работы 1).
3. Подключить `setupAIAnswer` — она уже умеет всё нужное.
4. Перевести точки входа: попап «Новая программа», меню программы, меню
   упражнения.
5. Удалить пять старых экранов и их обвязку. Прогнать `check.py` — она покажет
   осиротевшие обращения, если что-то забыто.

### Риски — здесь они настоящие

**Формат обмена с ИИ трогать нельзя вообще.** Промт (`AI_PROMPT`,
`EX_ANSWER_FORMAT`) и разборщик `parseProgramText` — одна система: ключи
«УПРАЖНЕНИЕ:», «ФОРМАТ:», «ШАГ:», «ПОТОЛОК:», «ЗАМЕНА:» должны совпадать с
точностью до буквы. Задача — перенести сборку промта, а не переписать её.

Проверять надо **каждым источником отдельно**: текстом, видео, доработкой
программы, созданием упражнения, доработкой упражнения. Один общий прогон ничего
не докажет — они отличаются именно тем, что уходит в промт.

Это работа не на вечер.

### Как проверить

По каждому источнику: ввести запрос → скопировать задание → вставить заранее
заготовленный ответ в правильном формате → убедиться, что программа или
упражнение собрались и открылись там, где должны. Пять прогонов, пять
результатов.

## 3. Экран упражнения: 18 полей → 5

### Зачем

Это узкое место всего создания программы. Чтобы собрать программу из пяти
упражнений, человек заходит на этот экран **пять раз**, и каждый раз видит:

- **18 полей ввода**
- **5 тумблеров**
- 4 карточки

Замер по разметке — 6678 символов, больше любого другого экрана редактирования.

Что там лежит сейчас, по порядку:

1. **Что за упражнение**: название, тумблер «Разминка».
2. **Сколько делать**: формат (3 кнопки), значение, подходов, вес (для формата с
   весом), тумблер «на каждую сторону», отдых — **чипами И числовым полем
   одновременно**.
3. **Рост нагрузки**: тумблер, потом **три пары «Прибавка / Максимум»** — для
   повторений, для веса, для времени. В разметке шесть полей, одновременно видно
   максимум четыре. Плюс тумблер двойной прогрессии, плюс тумблер «есть
   упражнение посложнее» с двумя своими полями.
4. **Детали** (уже свёрнуто): описание, частые ошибки, мышцы, видео, картинка.

### Что делаем

Принцип: **открытым остаётся только то, без чего упражнения не существует.**
Это название, формат, значение, подходы, отдых — пять контролов. Всё остальное
имеет рабочее значение по умолчанию и живёт в свёрнутых секциях со сводкой.

**а) «Рост нагрузки» сворачивается так же, как «Детали».**
Заголовок со сводкой: «+1 повт., максимум 15» или «не растёт». Человек, которому
это не нужно, видит одну строку вместо девяти контролов. Человек, которому нужно,
разворачивает и получает всё.

**б) Три пары «Прибавка / Максимум» — одной парой на активную ось.**
Сейчас в разметке три почти одинаковых блока, которые надо держать в синхроне
руками. Ось известна из формата: повторения → повторы, время → секунды,
«повторения и вес» → две пары (они растут независимо, это и есть двойная
прогрессия). Рисовать по формату, а не прятать заранее заготовленное.

Минус два поля в разметке и, главное, минус три места, которые правятся вместе.

**в) Отдых: один видимый контрол вместо двух.**
Сейчас и чипы (`без / 30 / 45 / 60 / 90`), и числовое поле — на одно значение.
Оставить чипы, добавить чип «своё», числовое поле показывать только по нему.

**г) «Есть упражнение посложнее» — внутрь «Роста нагрузки».**
Замена имеет смысл только тогда, когда есть потолок и до него дорастают. Сейчас
это отдельный тумблер посреди экрана, никак не связанный с потолком визуально.

### Что будет видно при открытии после правки

```
ЧТО ЗА УПРАЖНЕНИЕ
  Название                    [____________]
  Разминка                            (•  )

СКОЛЬКО ДЕЛАТЬ
  Формат   [Повторения][Повт. и вес][Время]
  Повторений [10]      Подходов [1]
  На каждую сторону                   (•  )
  Отдых  [без][30][45][60][90][своё]

  Рост нагрузки          +1 повт., до 15  ▾
  Детали                    не заполнено  ▾
```

Пять контролов и две строки вместо восемнадцати полей.

### Риски

Средние, и они не в вёрстке.

- **Прогрессия — самая сложная механика приложения.** Значения считаются как
  «база + шаги программы × шаг оси + ручная поправка, но не выше потолка».
  Переносить контролы можно, трогать расчёт — нельзя.
- **`progOn` / `trackWeight`.** Экран «материализует» новую модель при открытии
  (считает эти флаги из старых данных). Этот кусок трогать осторожно: именно на
  нём недавно обнаружилось, что вес не доходил до тренировки.
- Старые упражнения, созданные раньше, должны открываться и сохраняться без
  изменений смысла.

### Как проверить

Три формата × два состояния прогрессии = шесть прогонов: открыть упражнение,
поменять значение, сохранить, открыть заново, убедиться, что всё на месте. Плюс
один прогон на упражнении из старой программы. Плюс полный прогон тренировки:
значения на экране упражнения должны совпадать с тем, что показывает таймер.

## 4. Конструктор программы: быстрый путь

### Зачем

Сам конструктор небольшой: 1797 символов разметки, две карточки — название со
строками «Настройки программы» и «Картинки программы», и список упражнений.
Настройки после прошлой правки разложены по принадлежности и больше не свалка.

Осталась одна настоящая проблема: **чтобы добавить упражнение, надо уйти на
экран из 18 полей и вернуться.** Пять упражнений — пять уходов. Даже после
работы 3 это пять переходов туда-обратно ради пяти названий.

### Что делаем

**а) Добавление строкой, без ухода с экрана.**
«Добавить упражнение» создаёт строку прямо в списке с полем названия в фокусе.
Заполнил название, нажал «ещё» — следующая строка. Полный экран открывается
только по «Изменить» в меню строки, когда действительно нужны детали.

Значения по умолчанию у новой строки уже есть (`blankExercise()`: повторения, 10,
1 подход, отдых 45) — то есть строка сразу рабочая, программу можно сохранить и
запустить, ни разу не открыв экран упражнения.

**б) Сводка настроек должна включать круги и отдых.**
Сейчас `syncSettingsSum()` собирает время, дни, число вариантов и «нагрузка
растёт сама», но не круги и не отдых между кругами — хотя это первое, что человек
хочет проверить перед стартом. И когда не задано ничего, строка перечисляет
названия полей («дни недели, время, круги, прибавка нагрузки») вместо того, чтобы
сказать, что действует по умолчанию.

**в) «Картинки программы» — внутрь настроек.**
Сейчас это отдельная строка рядом с «Настройками программы», как равная по весу.
Но это оформление, а не устройство программы, и вдобавок премиум-функция. Место
ей — строкой внутри настроек, в разделе про обложку и описание.

### Риски

Низкие. Единственное, за чем следить: строка списка и полный экран правят **одно
и то же** упражнение. Нельзя допустить, чтобы правка в строке потерялась при
открытии полного экрана — у него своя копия `exDraft`, и она берётся из списка
при открытии.

### Как проверить

Собрать программу из трёх упражнений, ни разу не открыв полный экран, сохранить,
запустить тренировку. Потом открыть одно упражнение полным экраном, поменять
значение, вернуться — строка в списке должна показывать новое.

## Порядок и почему именно такой

1. **Делегирование** — первым, потому что работа 2 пишет много новой разметки с
   кнопками. Сделаешь основу сейчас — новый экран сразу ляжет правильно.
2. **Пять экранов ИИ в один** — самая крупная работа и самая большая экономия,
   и она дешевеет, если сделать её до серверного ИИ, а не после.
3. **Экран упражнения** — независим от первых двух, можно делать когда угодно,
   но он самый ценный для человека, который собирает первую программу.
4. **Конструктор** — последним: часть его смысла (быстрое добавление) появляется
   только после того, как экран упражнения перестанет быть страшным.

Работы 3 и 4 можно поменять местами или делать вместе — они про один и тот же
путь «собрать свою программу».

**Сборка склейкой по-прежнему отложена.** Пересмотреть, когда файл перевалит за
1,2 МБ (сейчас 916 КБ) или когда темп правок успокоится.
