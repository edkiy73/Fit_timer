# UnMute — план до запуска (решения владельца)

**Это единственный рабочий план UnMute.** Новый исполнитель (человек или ИИ) начинает отсюда:
«Как вести план» → «Этапы» (первый незакрытый пункт) → «Журнал выполнения» → «Справка для исполнителя».

Основа: `unmute-audit-2026-10-06.md` и `unmute-prelaunch-audit-2026-10-07.md` (номера пунктов аудита указаны в решениях).
Здесь записаны только принятые решения. Варианты обсуждаются в чате, в план попадает итог.
Пометка «по умолчанию» — решение исполнителя по очевидному техническому пункту; владелец может его поменять.

Статус: план согласован владельцем (2026-10-07). Идёт выполнение — текущее состояние в «Этапах» и «Журнале».

## Как вести план

- Пункт этапа — один PR. Порядок — по номерам, если владелец не сказал иначе.
- В том же PR, что делает пункт, обновить этот файл:
  - в «Этапах» поставить `[x]` и номер PR; если пункт сделан частично — `[~]` и что осталось;
  - добавить запись в «Журнал выполнения»: что изменилось для ученика, как сделано (ключевые файлы, подход), чем проверено, что осталось/риски.
- Новое решение владельца — записать в «Решения» (итог, без вариантов), затем делать.
- PR мержится сразу после зелёного CI без конфликтов и открытых замечаний (постоянное указание владельца, `CLAUDE.md` → Autonomy).
- Владельцу задаются вопросы только о продуктовых решениях, недостающих доступах и необратимых действиях с продом, подписью и деньгами.

## Решения

### 1. Дни с разговором с ИИ (дни 6, 15, 23, 31, 35) — аудит T3, R2, B4

- **С Plus:** разговор проходит прямо в приложении, как сейчас.
- **Без Plus (и без аккаунта):** приложение даёт готовый промпт, чтобы скопировать его в свой ИИ (ChatGPT, Gemini и т.п., лучше с живым голосовым режимом). Промпт ведёт диалог по теме дня, а в конце ИИ говорит, пройден урок или нужно повторить.
- После этого ученик сам нажимает «Готово, урок пройден» (вместо «я прошёл» — без рода, по правилу текстов) — день засчитывается. Для тех, у кого нет Plus, выполнение не проверяем: на совесть ученика.
- Значит, шаг с ИИ больше никогда не блокирует прогресс: ни без входа, ни без Plus, ни при сбое ИИ.

### 2. Модель продажи — аудит R3

- **Plus отдельно:** только два тарифа — на месяц и на год.
- **Курс:** два варианта — «курс целиком» и «курс целиком + Plus на год со скидкой».
- Вариант «курс + Plus на месяц» не предлагаем.
- Экран покупки курса показывает только эти два варианта курса; экран Plus — только два тарифа Plus.

### 3. Мгновенная выдача покупок — аудит B1

- Оставляем как есть до запуска (ссылку знает только семья).
- Перед публичным запуском — выключить в «Админка → Оплата» (пункт чек-листа запуска).

### 4. Бесплатные дни и темп — аудит T7

- Бесплатные дни задаются для каждого курса в админке (уже есть, вместе с плашкой «дальше — только после покупки»). Код не меняем.
- **Темп для купленного курса:** если за один календарный день пройдено 3 дня курса, то при попытке начать 4-й показываем окно: «Лучше закончить на сегодня — материал будет хуже откладываться. Лучше понемногу каждый день, чем всё за раз».
  - Кнопки: «Хорошо, я понял» → на главный экран; «Всё равно продолжить» → открыть день.
- В бесплатной части ограничения темпа нет (её длину задаёт админка).

### 5. Пробный разговор с ИИ — аудит B3

- Оставляем **один бесплатный разговор в приложении** для вошедших без Plus (показывает, что даёт Plus).
- Пробный разговор засчитывается только после первого успешного ответа ИИ; сбой ИИ его не сжигает. Id пробного разговора хранится надёжно (не в `sessionStorage`).
- Кроме пробного, у всех без Plus всегда есть путь «скопировать промпт в свой ИИ» (решение 1).

### 6. Цены курсов — аудит R4

- Цена задаётся **для каждого курса в админке**, как и цена/скидка варианта «курс + Plus на год». Конкретные цифры владелец выставит сам.
- Одна общая цена в `config/product.json` остаётся только значением по умолчанию.

### 7. Валюта и платёжный провайдер — аудит R5

- Сейчас не трогаем. Валюта и способ оплаты выбираются вместе с платёжным провайдером на отдельном этапе «Оплата».

### 8. Почта и домен — аудит T8, M2, M4

- До запуска вход — по коду из админки, как сейчас. Свой домен и почту на нём подключаем перед публичным запуском (пункт чек-листа запуска).

### 9. 52 задания без русской фразы — аудит C2

- Исправить импортёр (`source` берётся из `card.q`, а если его нет — из `card.ru`).
- Точечный скрипт: дописывает фразу **только этим 52 заданиям** в черновике основного курса и выпускает курс. Запуск через GitHub Actions с имеющимся `ADMIN_KEY`. Остальные правки из админки сохраняются; полный переимпорт не делаем.

### 10. Ответы маленькими буквами — аудит C3, 2.3 (06.10)

- Новое поле «как показывать ответ» (`displayAnswer`) у письменных заданий. Тот же скрипт заполняет его автоматически: заглавная буква, `I`, точка или вопросительный знак по типу задания.
- В админке поле можно поправить руками. Проверка ответа (`accepted`) не меняется.

### 11. Условия использования / оферта — аудит M1

- Исполнитель пишет готовый текст: покупка курса, подписка Plus (месяц/год), бесплатные дни, возвраты, ИИ-функции, «на совесть ученика» для разговоров вне приложения, данные продавца — местами для заполнения.
- **Текст редактируется в админке** (как документ), публикуется страницей в приложении; ссылки — в Настройках, на экранах покупки и в онбординге.
- Владелец потом сверяет текст с юристом и правит в админке.

### 12. «Повтор» и незаконченный урок — аудит 1.1, 1.2 (06.10)

- Ошибка в уроке исправляется самим уроком; в «Повтор» она приходит **завтра**.
- Неверный ответ в «Повторе» (после второй попытки в сессии) тоже переносится **на завтра**. «На сегодня всё» становится правдой: значок и «Нужно сегодня» гаснут.
- Урок не переспрашивает задания, которые уже решены где-то ещё (в «Повторе», на другом устройстве).

### 13. «Говорение» без микрофона — аудит 1.5 (06.10)

- Целевая платформа — приложение (веб не учитываем).
- При каждом входе в «Говорение» приложение **запрашивает разрешение на микрофон**. Если разрешение не дали — включается ручной режим: «Скажи вслух → Сверить → Совпало / Не совпало», без повторяющейся ошибки на каждой фразе.
- При следующем входе в «Говорение» снова спрашиваем разрешение (не запоминаем отказ навсегда).
- Итог раздела в ручном режиме: «Распознано X из N · сверено вручную M» (уже сделано в #616).

### 14. Онбординг — аудит 2.4 (06.10), T10

- Первый экран спрашивает, **с какого курса начать**. Курс по умолчанию — тот, что выбран в админке (он и отмечен заранее).
- Кнопка старта неактивна, пока курс не выбран (при курсе по умолчанию из админки — активна сразу), и называет курс: «Начать: <курс>».
- Дополнительные действия на экране: «Войти в аккаунт» и «Посмотреть приложение» — перейти на «Сегодня», не начиная урок.
- Оба курса после старта ведут одинаково: сразу в первый день выбранного курса.

### 15. День повторения без накопленных повторений — аудит T12

- Если повторять нечего, день даёт **«Фразы вперемешку»** по пройденным темам (10 фраз, уже есть в «Повторе»). День засчитывается после них.

### 16. Первые минуты — голосовая победа в день 1

- В конце дня 1 основного курса — 2–3 простые фразы сказать вслух с распознаванием (раздел «Говорение» на коротком наборе).
- Правка контента дня 1 — тем же точечным скриптом, что и решения 9–10.

### 17. Рост и удержание до запуска

- **Оценка в сторе:** после 3-го пройденного дня — системное окно Google Play.
- **«Пригласи друга»:** реферальная ссылка. Когда приглашённый вошёл и **прошёл 3 дня**, обоим даётся Plus на N дней. N настраивается в админке (по умолчанию 7).
- **Лендинг + превью ссылки:** одностраничный сайт с демо и кнопкой Google Play, OG-превью, иконка, `theme-color`. Живёт на том же сайте: корень — лендинг, веб-приложение переезжает на `/app` (в Android-приложении ничего не меняется). При покупке домена просто переключаем адрес.
- Недельную сводку до запуска не делаем.

### 18. База данных — аудит R8

- Сначала измерить: регион базы и реальную скорость сохранения в приложении. Переезд — только если реально медленно и после подтверждения владельца.

### 19. Порядок работ

- **Сначала блокеры, потом остальное.** Каждый пункт — отдельный PR, после зелёного CI мержится.

### 20. Выход из аккаунта на общем телефоне — аудит T9

- «Выйти» убирает прогресс этого аккаунта с телефона (на сервере он сохранён и вернётся при следующем входе). Следующий человек начинает с чистого листа.
- Если человек занимался без аккаунта и входит впервые, его прогресс добавляется в аккаунт, как сейчас.

## Справка для исполнителя

### Правила
- Прочитать `CLAUDE.md` (корень) и ADR `docs/appbase-stack-ci-strategy.md`. Правила FitTimer в `CLAUDE.md` относятся к `apps/fittimer`.
- UnMute: `apps/unmute` — React 19 + TypeScript + Vite, hash-роутер, TanStack Query, Capacitor 8; сервер — `api/*` на Vercel, Upstash Redis; общий код — AppBase Core (`packages/core`, `packages/ui-react`).
- Core не импортирует продукты и не содержит их названий: `packages/core/tests/boundaries.js` падает даже на название продукта в комментарии. Изменение Core/ui-react держит зелёными все приложения в том же PR.
- Новые браузерные тесты ждут условий, а не времени (`waitForTimeout` запрещён, ADR D6).
- Тексты для ученика — русский, на «ты», без рода, простым языком; все строки через `src/i18n/ru.ts` и `en.ts`.
- Секреты (`ADMIN_KEY`, ключи ИИ и почты, подпись) не попадают в код, PR и чат.

### Как проверять
```bash
cd apps/unmute && npm ci && npm run check   # typecheck, smoke, vitest, сборка
node tests/e2e.mjs                           # браузер на prod-сборке с api/* в памяти
node tests/day-progress-e2e.mjs              # прохождение дня
cd packages/core && npm ci && npm run check  # если трогали Core
```
Браузер: Playwright с `/opt/pw-browsers/chromium`. Тестовые серверы работают на памяти (`ALLOW_MEMORY_STORE=1`): `/api/auth` отдаёт `devCode`, вход проверяется без почты. CI: «UnMute — e2e» (`.github/workflows/unmute.yml`).

### Инфраструктура
- Vercel-проект `unmute`, адрес `https://unmute99.vercel.app`, регион `sin1`. Проверка прода — workflow «UnMute — production readiness».
- Курсы из кода выпускаются сами после изменения в main: «UnMute — выпуск курсов из кода» (`scripts/release-courses.mjs`); основной курс — «UnMute — выпуск основного курса». Вручную: `ADMIN_KEY=… node scripts/release-courses.mjs`. Импорт старого контента: `ADMIN_KEY=… node scripts/import-legacy-content.mjs --publish`, затем `#/admin` → «Словарь» → «Обновить транскрипцию» → «Выпустить словарь».
- APK — workflow «UnMute — APK для установки».
- Почта: пока нет своего домена в Resend и `MAIL_FROM`, письма доходят только владельцу аккаунта Resend; остальным — вход по коду: `#/admin` → «Пользователи» → email → «Выдать» → «Код для входа» (одноразовый, 15 минут), на экране входа «У меня есть код».
- ИИ: провайдер, модель и лимиты — в Vercel/админке; пробный разговор — `lib/unmute-ai-trial.js`.

### Оплата (как устроена)
- Провайдер подключается адаптером `{id, testOnly?, checkout?({email, sku, product}) → {url}|{events}, verifyWebhook({headers, body, query}) → {ok, events}}` в `createBillingHandler({adapters})` (`apps/unmute/api/billing.js`). Сейчас есть `instant` (включается в «Админка → Оплата», до запуска) и `test` (только при `ALLOW_MEMORY_STORE=1`).
- Событие `{orderId, email, sku, status: paid|refunded|canceled, until?, autoRenew?}` применяет `applyBillingEvent`: идемпотентно, SKU только из каталога `config/product.json → products`. `paid` → покупка навсегда (`acc.owned`) или Plus (`acc.sub`); `refunded` → забрать; `canceled` у подписки → выключить продление. Журнал — `bill:log:YYYY-MM`, вкладка «Платежи».
- Провайдерам с подписью по «сырому» телу (Stripe/Paddle) нужен доступ к исходным байтам — проверить в Vercel до подключения.

### Прогресс (подробно — `docs/unmute-progress-model.md`, `docs/unmute-day-progress-contract.md`)
- Документы scope `account`, `free:true`: `progress:course:<setId>` (пройденное, SRS карточек и практики, дни), `progress:stats:<setId>`, `progress:words`, `settings`. Слияние по сущностям через Core `document-sync.ts`; без аккаунта — только на устройстве, при входе сливается с сервером.
- Незаконченный урок: `localStorage` `unmute.lesson-run:<set>:<node>`, позиции практики `unmute.pattern-run:…`.
- Контент: `docs/unmute-content-model.md`, словарь — `docs/unmute-lexicon.md`, `docs/unmute-lexical-coverage.md`, нейтральные тексты — `docs/unmute-gender-neutral-content.md`. Нагрузка «Повтора» моделируется `scripts/simulate-review-load.mjs` (workflow «UnMute — review load analysis»).

### Подводные камни
- Документы scope `profile` сервер без Premium не синхронизирует; бесплатные данные — только scope `account` с `free:true`.
- `document-sync` всегда шлёт `base`, иначе правки с другого устройства теряются.
- Команды в песочнице агента иногда временно блокируются — это не ошибка кода, повторить.
- `pkill -f` в песочнице может убить собственный shell — освобождать порт через `fuser -k <port>/tcp`.
