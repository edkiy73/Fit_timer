# Почему так сделано

Этот файл хранит только актуальные инженерные причины, которые легко сломать при будущих правках.
Текущая архитектурная карта — в `.ai/project-map.md`, продуктовые правила — в `CLAUDE.md` / `AGENTS.md`.

## Canonical frontend и generated-файлы

Интерфейс редактируется в `src/html/`, `src/styles/`, `src/app/`.
Корневые `index.html`, `style.css`, `app.js` генерируются через `npm run build:sources`.

Причина: раньше приложение жило одним огромным файлом, из-за чего агенты читали и переписывали
слишком много кода за одну задачу. Split-source уменьшает область изменений и позволяет проверять
соответствие generated-файлов отдельно.

## Один аккаунт, несколько профилей, тренер внутри аккаунта

Email-account — единица авторизации и серверных прав. Профили — люди внутри аккаунта.
Trainer mode не отдельный аккаунт и не отдельный логин.

Причина: отдельная trainer identity уже приводила к дублированию состояния и рассинхронизации.
Handle закреплён за аккаунтом и повторно используется для trainer page.

## Аккаунт бесплатный, Premium — отдельное право

Регистрация/вход не должны зависеть от подписки. Premium-проверки выполняются сервером для
платных возможностей, а не только клиентским UI.

Причина: клиент можно модифицировать; entitlement, AI и будущий billing должны оставаться
server-authoritative.

## Sync: документами, с revision-first конфликтами

Синхронизация работает документами, а не одним большим blob всех программ.
Для документов сравнивается `rev`; timestamp устройства не используется как главный арбитр.
Manifest update сериализуется server-side lock, чтобы параллельные push не теряли изменения.

Причина: часы телефона ненадёжны, а обычный read-modify-write без lock терял документы при
одновременной синхронизации двух устройств.

Профильные tombstone/metadata имеют отдельную семантику — не менять их конфликтную логику
механически без проверки удаления профилей.

## Локальные данные — в IndexedDB, не в localStorage

`kvGet`/`kvSet` пишут в IndexedDB (`fittimer` / `kv`). Старые значения из localStorage
переезжают сами при первом чтении. localStorage — запасной путь и зеркало для ключей,
которые читаются синхронно на старте (`KV_MIRROR`, сейчас только `account`).
`kvSet` возвращает false, если записать не удалось, а человек видит сообщение
`storage.full`; `savePrograms`/`saveDoc` в этом случае не ставят изменения в очередь
синхронизации.

Причина: программы хранятся вместе с картинками (data URL по 60–120 КБ), фото прогресса
тоже. Лимит localStorage (~5 МБ) кончался после нескольких программ с картинками, ошибка
записи проглатывалась, и правки молча пропадали после перезапуска. Удаление всех данных
чистит и базу (`kvClearAll`).

## Браузерные тесты идут в CI

`.github/workflows/browser-tests.yml` запускает `scripts/run-browser-tests.mjs`: все
сквозные тесты против `tests/dev-server.js`. Скрипт падает, если какой-то `tests/*.js`
не запускается ни им, ни другим workflow. Тестовый сервер повторяет rewrites из
`vercel.json` и отдаёт `.css` как `text/css`.

Причина: вне CI тесты месяцами ломались незаметно — сервер не отдавал стили, тренерские
сценарии падали на `no_trainer`, а тесты ИИ — на новой проверке ответа.

## Фото прогресса и аватары остаются локальными

Они не входят в server sync.

Причина: это наиболее чувствительные пользовательские данные, а текущий продукт не требует
серверного хранения для своей основной функции.

## Удаление аккаунта должно чистить все ключи

Любой новый persisted key обязан быть включён в соответствующий cleanup path.

Причина: забытый ключ после удаления аккаунта может восстановить часть старого состояния и
нарушить обещание полного удаления данных.

## AI protocol — единая система

Промты, `lib/ai-protocol.js`, клиентский parser и validators меняются согласованно.
Встроенный AI проходит server validation и повторную client validation перед применением.
`exercise.create` может вернуть несколько упражнений; `modify/replace` — строго одно.

Причина: HTTP 200 от модели ещё не означает корректный результат. Обрезанный ответ не должен
частично перезаписывать программу. Malformed primary response считается ошибкой и может уйти
на backup provider.

## Правка программы без запроса на структуру сохраняет структуру

Если пользователь просит изменить технику/описание/нагрузку, но не просит добавлять,
удалять или перестраивать упражнения, клиент проверяет shape исходной программы после AI merge.

Причина: модель может случайно удалить упражнение или вариант, даже если формально вернула
валидный протокол.

## UI: существующие patterns важнее новых компонентов

Новые контролы должны переиспользовать существующие modal/card/icon/navigation patterns.
Иконки берутся из внутренней icon system.

Причина: раньше точечные задачи быстро создавали несколько почти одинаковых компонентов,
которые затем расходились по поведению и стилю.

## Навигация и modal stack

Screens переключаются существующим navigation layer, modals закрываются через общий stack.
Системная кнопка «назад» должна сначала закрывать верхний modal и возвращать на предыдущий
экран/таб, а не сбрасывать пользователя на произвольный root tab.

Причина: Android back и browser history раньше расходились и создавали пустые экраны либо
возвращали не туда, откуда пользователь пришёл.

## Прогрессия нагрузки

Прогрессия считается по завершённым тренировкам. Weight/time/reps axes независимы; нулевой
step означает, что конкретная ось не растёт. Наличие веса в упражнении не зависит от того,
включён ли рост веса.

Причина: старый fallback превращал step=0 в 1 и незаметно менял нагрузку.

## PWA удалён намеренно

Fit Timer теперь поддерживает обычный web и Android/iOS через Capacitor.
Service worker, manifest, PWA icons и старый TWA удалены.

Причина: поддержка третьего install/runtime пути создавала отдельную cache/update модель,
которая больше не нужна продукту. Не возвращать PWA частично без отдельного решения владельца.

## CSP и ключ админки

`vercel.json` отдаёт на все пути Content-Security-Policy (`script-src 'self'`, без
`unsafe-inline`/`unsafe-eval`, внешние — только Google Fonts), `nosniff`, `X-Frame-Options: DENY`.
Поэтому в `index.html`/`admin.html` нельзя встроенные `<script>` и атрибуты `onclick="…"` —
браузер их молча заблокирует. Скрипт админки живёт в `admin.js`. Новый внешний домен
(шрифты, картинки, API) — сначала добавить в CSP. Ловит это `tests/csp.js`; dev-server
повторяет заголовки из `vercel.json`.

Ключ админки хранится в `sessionStorage` (живёт до закрытия вкладки), старый ключ из
`localStorage` при загрузке переносится и стирается.

## Проверка после изменений

Минимальный порядок:
1. `npm run ai:index`
2. `npm run check:sources`
3. `npm run check:ai-index`
4. targeted tests
5. `python3 check.py`
6. `npm run build` / `npm run check:mobile` когда затронут mobile/web bundle

Не считать изменение завершённым только потому, что сборка синтаксически прошла: для sync,
auth, AI и release-flow нужны соответствующие regression tests.
