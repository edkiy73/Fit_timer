# Что нажать, чтобы заработали ссылки

Один раз, мышкой, минуты две. Ничего писать в коде не надо.

## Сначала — посмотреть, что сейчас

Открой в браузере:

**https://fittimer99.vercel.app/api/health**

Эта страница прямым текстом говорит, работает хранилище или нет, и что делать,
если нет. Она ничего не меняет и не показывает ни одного пароля. Возвращайся к ней
после каждого шага — она и есть проверка.

## Если написано «ХРАНИЛИЩЕ: НЕ ПОДКЛЮЧЕНО»

1. Зайти на **vercel.com**, войти своим аккаунтом.
2. Открыть проект **fittimer99**.
3. Наверху вкладка **Storage**.
4. Кнопка **Create Database**. Откроется список: там будет **Upstash** —
   выбрать его, тип **Redis**.
5. Имя — любое, например `fittimer`. Регион — **Frankfurt**, если люди в России
   и СНГ (он ближе всех, ссылки будут открываться быстрее).
6. План — **Free**. Дальше **Continue** → **Connect** (подключить к проекту
   fittimer99). Если спросит, для каких окружений — оставить все.
7. Vercel сам пересоберёт проект, это примерно минута.
8. Обновить страницу `/api/health`.

Должно стать: **«ХРАНИЛИЩЕ: подключено и работает»**. Всё, больше ничего не нужно.

## Что это вообще такое и зачем

Ссылка вида `fittimer99.vercel.app/?p=k3n8sd21` — короткая, потому что самой
программы в ней нет. В ней только номер. По этому номеру приложение спрашивает
программу у сервера.

Значит, программу надо где-то держать. Место, где сервер хранит такие вещи, и
называется хранилищем. Upstash — это оно; «Redis» — его разновидность, быстрая и
простая. Бесплатного плана хватит очень надолго: одна программа весит килобайты.

Раньше программа ехала внутри самой ссылки, и на десяти упражнениях ссылка
разрасталась до 19 тысяч символов — такой адрес Vercel отклонял, не доходя до
приложения (`URI_TOO_LONG`). Поэтому теперь так.

## Пока не подключено

Приложение работает целиком, ничего не сломано. Не работает ровно одно: **ссылки
на программы не создаются**. Тренер увидит честное «ссылки пока не работают» и
подсказку передать программу файлом.

## «Я всё подключил, а страница пишет «не подключено»»

Это нормальный и самый частый случай. Переменные от базы попадают в функцию
**в момент сборки**, а не в момент, когда базу подключили. Работающая сейчас
сборка сделана раньше и про новую базу не знает.

Лечится пересборкой:

1. **Deployments** (вкладка рядом со Storage).
2. У самого верхнего деплоя справа кнопка **«...»**.
3. **Redeploy** → снять галочку **Use existing Build Cache** → **Redeploy**.
4. Дождаться **Ready**, примерно минута.
5. Обновить `/api/health`.

Внизу страницы `/api/health` всегда написано, что функция видит на самом деле:
список имён переменных и какая сборка запущена. Если после пересборки список
по-прежнему пустой — значит, база не привязана к проекту, а не к сборке.

## Если что-то пошло не так

| Что на `/api/health` | Что это значит |
|---|---|
| «переменные есть, но база не отвечает» | База удалена или отключена от проекта. Storage → проверить, что она на месте и связана с `fittimer99` |
| «база подключена не тем способом» | Подключили что-то, дающее `REDIS_URL`. Нужен **Upstash for Redis** — он даёт доступ по HTTP, а функции ходят только так |
| «переменных про базу: (ни одной)» | Нужна пересборка — см. раздел выше |
| «адрес базы есть, а токена для записи нет» | Подставился только `KV_REST_API_READ_ONLY_TOKEN`. Нужен `KV_REST_API_TOKEN`, без `READ_ONLY` в имени |
| Страница не открывается вовсе | Проект не пересобрался. Deployments → последний деплой должен быть зелёный |

Имена переменных приложение принимает любые из трёх наборов
(`KV_REST_API_*`, `UPSTASH_REDIS_REST_*`, `REDIS_REST_*`) — какой бы из них ни
подставил Vercel, работать будет.

## Админка каталога

**https://fittimer99.vercel.app/admin.html**

Ключ спрашивается один раз и хранится в браузере. Это тот же `ADMIN_KEY` из
переменных окружения Vercel; если он не задан, страница сразу так и скажет.

Четыре вкладки:

| Вкладка | Что там |
|---|---|
| **На проверке** | Заявки от тренеров: состав программы, автор, кнопки «Взять», «Отклонить», «Закрыть автора» |
| **В каталоге** | Всё принятое. Можно поправить любое поле или убрать из каталога |
| **Тренеры** | Ник, имя, стаж, сколько программ и сколько раз их брали, когда появился и когда последний раз давал о себе знать. Приём программ закрывается и открывается обратно |
| **Добавить** | Своя программа в каталог, минуя очередь: тем же текстом, каким программы приходят от нейросети и от тренеров |

**Каталог пуст при первом заходе — это нормально.** В приложении не осталось ни
одной зашитой программы: раньше десяток ехал в загрузке к каждому человеку, хотя
нужен был однажды. На пустой вкладке «В каталоге» есть кнопка **«Залить пять
тестовых программ»** — это набор из `api/_seed.js`. Повторное нажатие ничего не
портит. Когда появятся настоящие программы, файл можно удалить целиком.

Ключ уходит заголовком, а не в адресе: адрес попадает в историю браузера и в
журналы, заголовок — нет. Страница закрыта от поисковиков (`noindex`).

## Почта и аккаунты (Resend)

Зачем. Аккаунт один на человека, и на нём висит всё: подписка, ник тренера, право
править свою страницу. Без почты аккаунт завести нечем — а значит, ник и страница
теряются вместе с телефоном.

Без неё всё остальное работает: и ссылки, и отчёты, и каталог. Не работает только
вход.

### Что нажать

1. **resend.com** → зарегистрироваться. Бесплатный план — 3000 писем в месяц,
   карта не нужна.
2. Слева **API Keys** → **Create API Key** → имя любое, права **Sending access** →
   скопировать ключ. Показывается он один раз.
3. **vercel.com** → проект **fittimer99** → **Settings** → **Environment
   Variables** → **Add**:
   имя `RESEND_API_KEY`, значение — скопированный ключ, окружение **Production**.
4. **Deployments** → у самого верхнего кнопка **«…»** → **Redeploy**.
5. Открыть `/api/health` — вверху видно, какой коммит сейчас работает, внизу должно
   появиться «ПОЧТА: настроена».

### Важное про отправителя

Пока своего домена нет, письма уходят с `onboarding@resend.dev`, а с этого адреса
Resend разрешает писать **только на почту, на которую зарегистрирован сам ключ**.
Всем остальным он откажет. Это не поломка и не ошибка настройки — так устроен
бесплатный Resend без домена. Для проверки своими руками этого хватает; для живых
людей — нет.

Чтобы писать кому угодно, нужен свой домен (домен третьего уровня от Vercel не
подойдёт — записи в его DNS не прописать):

1. Resend → **Domains** → **Add Domain** → свой домен.
2. Resend покажет несколько записей DNS (`TXT`, `MX`, `CNAME`) — прописать их там,
   где домен куплен, и дождаться галочки «Verified». Обычно минуты, иногда часы.
3. В Vercel добавить вторую переменную: имя `MAIL_FROM`, значение вида
   `Fit Timer <hi@твойдомен.ru>`.
4. Снова **Redeploy**.

### Как это выглядит у человека

«Другое» → вкладка **Аккаунт** → **«Завести или войти»**. Вводит адрес, получает
шестизначный код, вводит его — готово. Отдельной формы регистрации нет: если аккаунта
с этой почтой не было, он заводится тем же кодом. Пароля нет намеренно — его пришлось
бы придумать, запомнить и где-то восстанавливать, то есть завести вторую такую же
задачу поверх первой.

**Аккаунт бесплатный.** Подписка — про синхронизацию тренировок и каталог, а не про
право иметь себя.

Отдельного входа для тренеров НЕТ. Ник тренера принадлежит аккаунту: на новом телефоне
достаточно войти той же почтой, и ник, имя, фото, «о себе» и стаж вернутся сами.
**Прежний телефон при этом теряет право править страницу** — вернуть её себе и означает
забрать её у устройства, где её уже нет. В приложении об этом сказано прямо. Если
человек вошёл на том же телефоне, где ключ и так рабочий, ничего не перевыпускается.

Ограничения стоят на адресе, а не на телефоне: пять писем в сутки на один адрес,
пять попыток на код, код живёт 15 минут. Иначе чужой ящик заваливается письмами с
любого количества устройств.

## Что происходит при удалении

**Программы из каталога не удаляются никогда.** Ни при каком объёме. Программа,
которую уже взяли себе люди, — это не сведения о человеке, а сделанная им вещь;
выдёргивать её задним числом значит ломать каталог тем, кто на неё смотрит. На
странице тренера просто не будет данных.

Объёма два.

**«Другое» → Тренер → «Удалить данные о себе».** Со страницы уходят имя, фото, «о себе»,
стаж и ссылка. Ник остаётся за человеком, право править — тоже: он убрал сведения, а
не перестал быть тренером. Страницу можно заполнить заново хоть завтра.

**«Другое» → Аккаунт → «Удалить все данные».** То же самое плюс сама запись аккаунта и
все ссылки, отправленные подопечным, вместе с их отчётами: это личная переписка, и
без хозяина ей лежать незачем. Ник остаётся закреплённым, но управлять им уже нечем —
его носят программы в каталоге, и чужой человек, назвавшись так же, унаследовал бы их
автора.

Если сервер в этот момент не ответил, приложение НЕ стирает телефон молча: ключ
удаления хранится только там, и, стерев его, убрать данные с сервера не сможет уже
никто. Человека спрашивают прямо.

## «Я всё сделал, а ничего не изменилось»

Первым делом открыть `/api/health`: **вверху написано, какой коммит сейчас работает и
чем он помечен.** Код и переменные попадают в функцию в момент сборки, поэтому
работающий деплой может ничего не знать о том, что уже лежит в репозитории.

| Что видно | Что делать |
|---|---|
| коммит старый | Vercel не пересобрал: Deployments → верхний деплой должен быть Ready |
| собирается не та ветка | Settings → Git → Production Branch |
| коммит правильный, а в приложении по-старому | это кэш телефона: приложение обновляется само при следующем открытии, но можно закрыть вкладку целиком и открыть заново |

## Почему функций именно восемь

Бесплатный план Vercel собирает **не больше двенадцати Serverless-функций на деплой**.
Тринадцатая роняет не эндпоинт, а **весь выкат целиком**:

```
Build Failed
No more than 12 Serverless Functions can be added to a Deployment on the Hobby plan.
```

Снаружи это выглядит хуже, чем есть: приложение продолжает работать на прошлой
сборке, и человек просто не видит своих изменений. Ни `/api/health`, ни версия в
приложении тут не соврут — они покажут старый коммит, — но сама причина лежит в
журнале сборки, куда никто не смотрит.

Два правила, из-за которых это больше не повторится:

**Вспомогательным файлам в `api/` не место.** Vercel считает функцией каждый `.js`
в этой папке. Общий код живёт в `lib/` — `store`, `util`, `mail`, `seed`.

**Один ресурс — одна функция.** Глаголы и параметры внутри, а не новый файл:

| адрес | что делает |
|---|---|
| `GET /api/p/:id` | без ключа — программа по ссылке; с `?key=` — открытия и отчёты |
| `GET/POST /api/trainer/:handle` | GET — страница глазами подопечного, POST — правка |
| `GET/POST /api/catalog` | GET — витрина (`?item=`, `?status=`), POST — заявка |
| `POST /api/auth` | `send`, `verify`, `forget` |
| `POST /api/share` | положить программу, получить ссылку |
| `POST /api/report` | отчёт подопечного |
| `POST /api/admin` | всё управление каталогом |
| `GET /api/health` | это самая страница диагностики |

Страницы `/api/catalog/review` больше нет: ту же очередь показывает `admin.html`,
где она лежит рядом с каталогом, тренерами и картинками.

Счёт держит `check.py`: выше десяти функций он предупреждает, выше двенадцати —
ошибка, и вспомогательный файл в `api/` называет отдельно. То есть узнать об этом
можно до пуша, а не из упавшей сборки.

## Supabase foundation

AppBase can now see a Supabase project through a server-only adapter, but production data still stays in Upstash.

For the current FitTimer migration add these Vercel Production variables:

- `SUPABASE_URL` — Project URL from Supabase Connect.
- `SUPABASE_SECRET_KEY` — Supabase server secret key (recommended for new setup).
- Legacy fallback only: `SUPABASE_SERVICE_ROLE_KEY`.

Never put the secret key into `app.config.js`, browser code or the APK.

After redeploy, `/api/health` shows Supabase connection status. This only checks connectivity; it does not switch storage and does not create tables.

The current Supabase project `FitT` is intentionally left without application tables until the document schema/shadow-write migration is reviewed.

## OpenRouter

To enable OpenRouter as an optional text AI provider:

- add `OPENROUTER_API_KEY` in Vercel Production;
- optionally add `OPENROUTER_APP_URL` and `OPENROUTER_APP_NAME`;
- redeploy;
- in Admin AI settings choose `openrouter` for a **text** primary/backup route and specify an OpenRouter model id.

Existing Gemini/OpenAI routes remain available and the default route does not change automatically.
