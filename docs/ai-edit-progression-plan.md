# План: AI-редактирование и прогрессия

Статус: план, не реализовано. Сверено с кодом на 2026-09-23.

## 1. Факты из кода

### AI-редактирование программы
`createEditedProgram()` (`src/app/40-programs-ai.js`) идёт одним из двух путей в зависимости от `aiStructureChangeRequested(wish)` (regex в `src/app/60-builder.js`):

- **regex сработал** → ответ ИИ принимается целиком. Проверяется только наличие обязательных меток (`validateProgramResponse`).
- **regex не сработал** → `aiMergeProgramEdit()` накладывает ответ на исходник: порядок, набор упражнений и все строки берутся из исходника, от ИИ приходят только значения. Упражнения сопоставляются по имени, иначе по номеру. Потом `sameProgramShape()` требует те же имена в том же порядке.

Прогон реального кода (regex + merge):

| Запрос | ИИ вернул | Итог |
|---|---|---|
| «Замени отжимания на подтягивания» | переименовал №2 | merge пропустил, `sameProgramShape` → ошибка «не удалось разобрать» |
| «Сделай тренировку короче, на 10 минут» | убрал «Выпады» | merge: `Присед, Отжимания, Планка, Планка` (значения сдвинулись по номеру) → ошибка |
| «Поменяй порядок: отжимания первыми» | переставил | тихо ничего не изменилось, сохранена копия «(обновлённая)» |
| «Добавь скручивания в конец» | добавил | тихо выброшено, сохранена копия без изменений |

Та же логика продублирована на сервере для модерации каталога: `structureChangeRequested` / `mergeProgramEditText` в `api/admin.js`.

Правка одного упражнения (`applyExEdit`) через `aiMergeExerciseBlock` возвращает любую строку, которую ИИ убрал: удалить поле нельзя, можно только выставить 0.

### Прогресс после AI-правки обнуляется
`createEditedProgram` делает **новую** программу: новый `id`, `stats.completions = 0`, `progStepsAdj` не переносится. `programToText` передаёт ИИ **базовые** значения (`ex.value`, `ex.weight`), а не текущие. Кто сделал 4 шага прогрессии, после любой AI-правки вернётся к стартовым числам. ChatGPT этого не заметил.

### Прогрессия
- Один счётчик на программу: `floor(completions / progression) + progStepsAdj` (`progSteps`). Итоговые числа считаются на лету: `getExProgValue`, `progressedRepsRange`, `dualCycleLen`.
- `completions` растёт после любой завершённой тренировки программы. При чередовании A/B упражнения варианта A растут на каждой тренировке, в том числе на днях B. Фактически каждое упражнение повышается вдвое чаще, чем задано.
- Выполнение упражнения не проверяется никак. На экране завершения есть только заметка. Нагрузка растёт, даже если человек не справился; поправить можно только общей кнопкой «±» на экране старта, и она сдвигает сразу все упражнения.
- `progWeights`, `progDelta`, `setExWeight`, `bumpProgDelta` — мёртвые заглушки.

### Вес 0
`parseKg` превращает 0 в «не задано». Если у упражнения формат с весом, вес 0 и шаг веса 2, `getExProgValue` отдаст `0 + шаги × 2`: сначала вес не показывается совсем, после двух повышений появляется «4 кг», взятые из воздуха. `exProgToLines` не выводит `ВЕС: 0`.

### Идентичность упражнения
Упражнение нигде не имеет `id`. Всё завязано на имя: merge, `sameProgramShape`, `carryMedia`, снимок тренера `origEx`/`exKey` (вариант + имя), `history.exercises`.

### Что уже есть и пригодится
`estimatedWorkoutMinutes(p, planIdx)` в `00-core.js` оценивает время тренировки. `exerciseLoad(p, ex)` считает текущую нагрузку, через него удобно делать миграцию. `renderStartOverview` уже показывает нагрузку каждого упражнения перед стартом.

## 2. Оценка советов ChatGPT

| # | Совет | Вердикт | Почему / поправка |
|---|---|---|---|
| 1 | Свободный ответ ИИ + проверка результата (вариант C) | **Да** | Проверять только то, что можно проверить по данным: разбор, ≥1 вариант, в каждом ≥1 основное упражнение, время. «Запрещённый инвентарь» и «травмы» автоматически не проверить: у упражнения нет поля инвентаря. Это остаётся на промте. |
| 2 | Узкий запрос остаётся узким | **Да** | Одно правило в `editRules`. Нарушения станут видны в резюме изменений (п. 4). |
| 3 | Убрать merge | **Да** | Доказано таблицей выше. Для правки одного упражнения всё же переносить описательные поля (ОПИСАНИЕ/МЫШЦЫ/ОШИБКИ/ВИДЕО/картинку), если ИИ их не вернул. Числовые поля и поля прогрессии не переносить никогда. |
| 4 | Резюме изменений перед «Применить» | **Да, главное по пользе** | Сейчас человек видит только сырой протокол. Одна строка: «−1 упр · +2 · переставлено 3 · отдых изменён в 4 · время 20 → 26 мин». |
| 5 | Перестановка = структурное изменение | **Да** | Сейчас перестановка молча ничего не меняет. Исправится само, когда уйдёт merge и появится сопоставление по id. |
| 6 | Стабильный `ex.id`, скрытый от ИИ | **Id — да; прятать от ИИ — нет** | ИИ не вернёт id, который не видел, а угадывать «переименовал или заменил» по тексту ненадёжно. Предлагаю в тексте для правки строку `КОД: e7k2`: около 5 токенов на упражнение, парсер её вырезает. ИИ сохраняет КОД у того же движения и не ставит у нового. Защита: если у упражнения с тем же КОД сменился формат (повторы ↔ время, с весом ↔ без), считаем его новым. Если КОД не вернулся, сопоставляем по точному имени. |
| 7 | «Повысить через N» → «проверить через N» | **Да, но только вместе с 9–10** | Без обратной связи «проверка» ничем не отличается от нынешнего поведения. |
| 8 | Прогрессия у каждого упражнения | **Да** | Это исправляет реальный баг с чередованием A/B. Смысл есть даже без обратной связи. |
| 9 | Отзыв после последнего подхода упражнения | **Отзыв — да; место — другое** | Вопрос посреди тренировки ломает таймер отдыха и режим без рук (голос/гарнитура). Спрашивать на экране завершения: там уже есть заметка, и показывать только упражнения, у которых подошла проверка (обычно 0–3). |
| 10 | Тяжело / Нормально / Легко; «Легко» даёт максимум +1 шаг | **Да** | Нет ответа или упражнение пропущено → нагрузка остаётся, в следующий раз спросим снова. |
| 11 | Двойная прогрессия с реальным состоянием | **Да** | Отказаться от `dualCycleLen`/`progSteps` и хранить текущие повторы и вес. |
| 12 | Разные стратегии по осям | **Уже есть** | Меняется только то, откуда берётся разрешение на шаг: не счётчик программы, а состояние упражнения. |
| 13 | `ВЕС: 0` → отдельный флаг `weightPending` | **Суть да, флаг не нужен** | У формата с весом при 0 кг нет законного смысла. Правило `hasWeight(ex) && !(вес > 0)` означает «вес не задан». Нужно запретить шагам прибавляться к нулю и выводить `ВЕС: 0` в протокол. |
| 14 | Спросить стартовый вес перед первым упражнением | **Спросить — да; где — на экране старта** | `renderStartOverview` уже перечисляет упражнения с нагрузкой. Строка «вес не задан» с полем ввода не прерывает таймер и сразу закрывает случай с 5 упражнениями на гантелях. Если оставить пустым, упражнение идёт без веса, а вес не растёт. |
| 15 | Сохранять прогресс при AI-правке, если это то же упражнение | **Да + сначала починить обнуление** | Сейчас сбрасывается всё (см. факты). Решение: отдавать ИИ **текущие** значения. Числа из ответа ИИ становятся новой базой, а от старого упражнения с тем же КОД переносится только состояние (счётчик до проверки). Так не бывает конфликта «кто прав — ИИ или прогрессия». |
| 16 | Пересчитывать время после правки | **Да, как предупреждение** | Отклонять правку по «человек явно просил больше объёма» — это снова классификатор запроса, тот же костыль. Показывать «время 20 → 37 мин» в резюме, выделять при выходе за ±5 мин / ±20 %. Решает человек. |
| 17 | Миграция: текущую нагрузку записать базой | **Да + ловушка со старыми клиентами** | Старый APK, получив синхронизированную программу, прибавит `floor(completions/N)` шагов к уже перенесённой базе, и шаги посчитаются дважды. При миграции ставить `progStepsAdj = -floor(completions/N)`, тогда у старого клиента смещение 0. |
| 18 | Промт менять последним | **Частично** | Правила правки (разрешить добавлять, удалять, переставлять) нужно менять **вместе** с удалением merge, иначе промт запрещает то, что приложение уже умеет. Промт про прогрессию («проверять через N») — вместе с обратной связью. |

**Надумано / убрать:** проверка инвентаря и травм после генерации; отклонение правки по «намерению» запроса; смысловое сопоставление переименованных упражнений (КОД надёжнее); отдельный флаг `weightPending`; хранить «дату последнего повышения» (не нужна ни одному решению).

## 3. Модель данных

```text
ex.id        'e' + 4-6 символов; создаётся при разборе/миграции; в протокол не входит,
             кроме строки КОД: в тексте для AI-правки
ex.value / ex.weight / sets …   без изменений: БАЗА (то, что в протоколе, в ссылках, в каталоге,
             в снимке тренера origEx)
ex.ps        состояние прогрессии, лежит внутри программы и синхронизируется вместе с ней:
  n          выполнений упражнения с последней проверки
  cur        {reps|sec, kg} — текущая нагрузка; нет поля = равна базе
  r0         нижняя граница повторов для сброса в двойной прогрессии
p.progression   как было: интервал проверки по умолчанию (N)
```

База отделена от текущей нагрузки, поэтому прогрессия не трогает `origEx` у программ тренера: подопечный не выглядит «изменившим» программу, и через ссылки уходит база, как сейчас.

## 4. Порядок работ

### Пачка 1 — AI-правка без merge (исправляет баги из таблицы)
1. `ex.id`: создавать в `parseProgramText`/`normalizeExercise`; одноразово проставить существующим программам (`applyProgressionAll` — там уже живёт миграция).
2. `programToText(p, {forEdit:true})`: добавить `КОД:` и **текущие** значения (через `exerciseLoad`). Тот же вариант использует `copyEditPrompt` в `90-events.js`. Парсер принимает и отбрасывает `КОД:`.
3. Удалить `aiStructureChangeRequested`, `aiMergeProgramEdit`, `sameProgramShape` и их серверные копии в `api/admin.js`. `aiMergeExerciseBlock` заменить переносом только описательных полей.
4. В `lib/ai-protocol.js` (общий для браузера и сервера) добавить `diffPrograms(old, new)`: сопоставление по КОД → по имени; added / removed / moved (минимум перемещений через LIS, а не «№2 ↔ №2») / changed по полям; время через `estimatedWorkoutMinutes`. Здесь же жёсткие проверки: разбор, ≥1 вариант, в каждом ≥1 основное упражнение.
5. Резюме изменений над кнопкой «Применить» (существующие чипы/классы, ключи RU+EN).
6. Перенос в новую программу: `stats.completions`, `ex.ps` для упражнений с тем же КОД и тем же форматом, `media`, `cover`.
7. `editRules`: одна версия без флага. Можно добавлять, удалять, переставлять и менять связанные поля; объём изменений соразмерен запросу; КОД сохранять у того же движения и не ставить новому.

Тесты: unit на `diffPrograms` + 4 сценария из таблицы; `tests/ai-generation-guards-unit.js`, `tests/program-actions.js`.

### Пачка 2 — неизвестный вес (маленькая, независимая)
1. Формат с весом при весе ≤ 0 = «не задан»: `getExProgValue` не прибавляет шаги к нулю; `exProgToLines` выводит `ВЕС: 0`.
2. Строка на экране старта: «вес не задан» + поле ввода кг → записывается в `ex.weight`.

Тесты: `tests/start-overview.js`.

### Пачка 3 — состояние у каждого упражнения + миграция (поведение почти прежнее)
1. Миграция: `ps.cur` = `exerciseLoad(p, ex)`, `ps.n` = `completions % N`, `progStepsAdj = -floor(completions/N)` для старых клиентов. Флаг версии, повторный запуск ничего не меняет.
2. После тренировки: `ps.n++` только у упражнений, которые реально выполнялись в этом варианте (исправляет баг A/B). Когда `ps.n ≥ N` — шаг по своей оси (как сейчас), `ps.n = 0`.
3. Удалить `progSteps`/`progAutoSteps`/`exProgSteps`/`dualCycleLen`/`progFrom`/заглушки `progWeights`. Общая кнопка «±» на экране старта заменяется правкой текущей нагрузки строки (то же поле, что в пачке 2).
4. Обновить места, завязанные на общий счётчик: `renderStartOverview` («через N тренировок»), уведомление «нагрузка выросла» в `80-platform.js`, `history.step`.

Тесты: unit на миграцию (результат совпадает с текущими числами), A/B, двойная прогрессия; `tests/sync-*.js` на круговой путь с синхронизацией.

### Пачка 4 — проверка вместо автоповышения
1. На экране завершения: упражнения с `ps.n ≥ N` → три чипа «Тяжело / Нормально / Легко».
2. «Нормально» или «Легко» → +1 шаг. «Тяжело», нет ответа или упражнение пропущено → остаётся, спросим в следующий раз.
3. `progressionRules`: ПРОГРЕССИЯ = «проверять через N выполнений упражнения».

## 5. Решения, которые нужны от тебя

1. Отзыв на экране завершения, а не посреди тренировки — **рекомендую**.
2. Строка `КОД:` в тексте для AI-правки вместо «спрятать id от ИИ» — **рекомендую**.
3. AI-правка по-прежнему создаёт копию «(обновлённая)», но уже с переносом прогресса. Альтернатива — править программу на месте. **Рекомендую оставить копию**: это привычное поведение и откат бесплатно.
4. Время вне бюджета — предупреждение в резюме, а не отказ — **рекомендую**.
