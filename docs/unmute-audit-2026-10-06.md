## 1. Логика урока и «Повтора»

### Что сохраняется и где (как устроено сейчас)

| Что | Где хранится | Синхронизируется | Когда пишется |
|---|---|---|---|
| Ответ на задание (`seen`, карточка SRS, статистика) | IndexedDB, документ `progress:course` | да, при входе | сразу после ответа, до показа шторки |
| Практика фраз (скорость/слушание/говорение), интервалы по фразам | там же | да | по каждой фразе и в конце раздела |
| Позиция в уроке, очередь работы над ошибками, раздел, набранный текст | `localStorage` `unmute.lesson-run:<курс>:<день>` | **нет** | на каждое изменение |
| Позиция внутри практики | `localStorage` `unmute.pattern-run:…:<runId>:…` | **нет** | на каждое изменение |
| Дневной лимит «Повтора» (20 + 10) | `localStorage` `unmute.review-budget:<день>` | **нет** | после каждой карточки |
| Позиция внутри сессии «Повтора» | только память React | нет | — |

Итого: **ответы не теряются** ни при выходе, ни при закрытии приложения. Теряется только «где я был» — при смене устройства или очистке данных браузера; урок тогда начинается с первого нерешённого задания, а это корректно. Выход из «Повтора» посередине возвращает только то, что ещё на сегодня (уже правильно отвеченное не повторяется).

### Что уходит в «Повтор» (как устроено сейчас)

| Событие | Что происходит с интервалом |
|---|---|
| Задание верно с первого раза | карточка, коробка 1, вернётся **завтра** |
| Задание неверно с первого раза | карточка, коробка 0, срок **сегодня**; в уроке задание вернётся в конец |
| Исправлено в работе над ошибками | интервал не меняется (остаётся «сегодня»), задание засчитывается для дня |
| Опечатка (near miss) с первого раза | засчитывается, **карточка не создаётся** |
| Повторное прохождение пройденного дня | интервалы не меняются |
| Фраза в практике: верно / неверно | интервалы по фразам (`practiceItems`); «Совпало» после ручной сверки = нейтрально |
| Карточка в «Повторе»: верно / неверно | коробка +1 / коробка 0 со сроком **сегодня** |

### 1.1. P1 — ошибки незаконченного урока сразу в «Повторе», а урок потом спрашивает их ещё раз

**Воспроизведение (проверено):** день 1, три первых ответа неверно → выйти из урока. На «Сегодня» появляется блок «Нужно сегодня · Повтор 3», на нижней панели значок «3». Пройти «Повтор» верно → на «Сегодня» день становится «4 из 12» (значит, «Повтор» засчитал задания уроку). Нажать «Продолжить» в уроке → после основного прохода начинается «Работа над ошибками» и **снова** задаёт те же три задания, хотя они уже решены.

**Почему:** неверный первый ответ ставит карточке срок «сегодня» (`gradeCardSrs`, коробка 0), а `review-session.ts → dueCardIds` берёт все карточки со сроком ≤ сегодня, не глядя, что урок ещё идёт. При этом очередь урока (`order` в `unmute.lesson-run`) после восстановления (`remapLessonRun` в `learn.tsx`) не сверяется с сохранённым `seen`.

**Почему плохо:** человек делает одно и то же дважды за 10 минут; «Нужно сегодня» конкурирует с самим уроком; счётчик «осталось N» в работе над ошибками врёт.

**Как решать:**
1. В `remapLessonRun`/гидрации урока и при каждом шаге в фазе исправления выкидывать из `order.slice(pos)` задания, у которых уже есть живой `seen` (кроме текущего, если на нём открыта шторка). Тот же фильтр уже есть в `day-progress-local.ts → readActiveTasks` — использовать общий хелпер, чтобы урок и «Сегодня» считали одинаково.
2. Не показывать в «Повторе» карточки, которые сейчас висят в незаконченном уроке этого же дня: собирать их из `readActiveDayProgress`/`unmute.lesson-run` и исключать в `buildCourseReviewSession` (или в счётчике и в сессии одновременно). Альтернатива проще: неверный **первый** ответ в уроке ставит срок «завтра» (интервал 1), потому что сегодня его и так исправит урок.
3. Тест: «3 ошибки → выход → Повтор не показывает их / либо урок их больше не спрашивает» + e2e в `tests/day-progress-e2e.mjs`.

### 1.2. P1 — «На сегодня всё», но очередь на сегодня не пуста

**Воспроизведение (проверено):** 3 неверных ответа в уроке → «Повтор» → ответить неверно на все 3 (каждая возвращается в конец один раз и снова неверно) → экран «На сегодня всё · Повторено: 3 · На сегодня очередь разобрана». На этом же экране на панели значок «3 к повтору»; на «Сегодня» — «Нужно сегодня · Повтор 3»; открыть «Повтор» — снова «На сегодня: 3».

**Почему:** неверная карточка в «Повторе» получает коробку 0 и срок «сегодня»; сессия возвращает её только один раз (`advanceCard` в `review.tsx`), а после сессии она снова «должна» сегодня.

**Как решать (выбрать одно):**
- Рекомендация: карточка, неверно отвеченная в «Повторе» дважды за сессию, получает срок **завтра** (коробка 0, но `due = today + 1`). Так ведёт себя и старый English Trainer по смыслу «сегодня уже было».
- Или хранить «уже показано сегодня» и не считать такие карточки в значке/«Нужно сегодня»; тогда текст экрана итога должен честно говорить «Трудные вернутся завтра».
- Тест на `review-session` и `today-model`: после сессии с ошибками счётчик «на сегодня» = 0.

### 1.3. P2 — ответ с опечаткой никогда не приходит в «Повтор»

`learn.tsx → handleText`: опечатка (`nearMiss`) засчитывается и вызывает только `saveSeen`, без карточки. Комментарий объясняет это как «не создавать долг», но последствие — фраза **вообще не попадает** в интервальное повторение (верный ответ создаёт карточку с завтрашним сроком, а опечатка — нет). Пройденный день потом открывается как «повторное прохождение», где интервалы не трогаются, то есть шанса уже нет.

**Как решать:** при опечатке создавать карточку как при верном ответе, но без повышения коробки сверх 1 (или коробка 0 со сроком «завтра»). Это одна строка в `handleText` + тест в `learn.test.tsx`.

### 1.4. P2 — серия и «дни занятий» за простое открытие урока

После онбординга и одного открытия теории (без единого ответа) «Профиль» показывает «1 дней занятий / 1 дней подряд». Причина: при гидрации урок тихо отмечает карточку-план как просмотренную (`learn.tsx`, цикл `for(const plan of activities.filter(isPlan))`), а теория — при открытии; `markActivitySeen → withLearningDay` записывает день занятий.

**Как решать:** `markActivitySeen` для `theory`/`plan` не должен вызывать `withLearningDay`; день занятий — с первого ответа, практики, «Повтора» или ИИ-разговора. Проверить, что уведомление «серия под угрозой» после этого не начнёт врать в обратную сторону (`notification-policy.ts`).

### 1.5. P2 — «Говорение» без микрофона

**Воспроизведение (проверено, микрофон запрещён):** на каждой фразе: «Нажми и скажи» → красная плашка «Микрофон запрещён…» → «Готово — сверить» → «Совпало». 3 нажатия + одна и та же ошибка 8 раз подряд. «Показать ответ» в этом режиме = «сдался», фраза уходит в работу над ошибками. Итог раздела после 8 ручных «Совпало»: **«0 из 8 распознано»** — звучит как провал, хотя день засчитан.

**Как решать:**
- Запомнить на время урока, что распознавание недоступно (`unsupported`/`permission`), и сразу показывать режим ручной сверки: «Скажи вслух → Сверить» с одной строкой «Микрофон выключен — сверяй сам».
- Итог: «8 из 8 сказано · сверено вручную» вместо «0 из 8 распознано»; «распознано» показывать только когда распознавание реально работало.

### 1.6. P2 — письменную ошибку нельзя пропустить

Работа над ошибками для `text-input`/`translation` повторяет задание, пока не будет введено правильно. Правильный ответ показан в шторке, поэтому тупика нет, но если человек не понял, он просто переписывает. Договор продукта — «ошибки блокируются до исправления» (`unmute-day-progress-contract.md`), поэтому это решение владельца, а не баг.

**Предложение:** на втором неверном исправлении одного и того же задания включать сборку из слов (как в `build`-режиме) вместо пустого поля — задание остаётся обязательным, но становится посильным.

### 1.7. P2 — данные устройства

- Позиция урока и очередь ошибок не синхронизируются: на втором устройстве урок начнётся с первого нерешённого — это нормально, но текст шторки выхода «Продолжишь с этого места» верен только на этом устройстве. Можно оставить, можно уточнить «на этом телефоне».
- Лимит «Повтора» (20 + 10) считается на устройство: на двух устройствах получится 40 в день. Если это важно — хранить в документе `settings`/`stats`.
- Ключи `unmute.review-budget:<день>` и `unmute.pattern-run:…:<runId>` брошенных попыток никогда не удаляются. Добавить уборку при старте (оставлять только сегодняшний бюджет и ключи текущего `runId`).

## 2. Вёрстка

### 2.1. P1 — шторка ответа закрывает задание

`.learn-feedback.is-sheet{max-height:70vh}` + объяснение целиком в шторке.
- **320×568:** шторка «Ответ неверный» закрывает и вопрос, и поле ответа — непонятно, на что был дан ответ.
- **360×640:** вопрос виден, но варианты ответа и собранная фраза под шторкой: нельзя сравнить свой вариант с правильным. В шторке нет строки «Твой ответ».

**Как решать:** шторка = заголовок + «Подходящий ответ» + «Твой ответ» (для неверного) + кнопки; объяснение свернуть в «Почему так» (раскрывается внутри шторки); `max-height` ~45vh; у `.runner` при открытой шторке `padding-bottom` = высоте шторки, чтобы задание можно было докрутить. Для выбора вариантов — не прятать выбранный и правильный вариант (подсветка уже есть в `learn.tsx`, её просто не видно).

### 2.2. P1 — цифры в «Профиле» мелкие + падежи

В «Профиле» у «дней занятий / дней подряд» `<strong>` имеет 22–23 px, а само число — **12 px** (измерено на 320, 360 и 390 px): число одного размера с подписью и не читается как главное. Причина в CSS: правило `.progress-metric span{font-size:13px}` и его версия `font-size:12px` в медиазапросе (`styles.css`, стр. 461 и 484) цепляют `<span class="animated-number">` внутри `<strong>`.

Плюс `progress.learningDays: 'дней занятий'`, `progress.streak: 'дней подряд'` без склонения → «1 дней». В проекте уже есть `src/plural.ts`.

**Как решать:** заменить селектор на `.progress-metric>span:not(.progress-metric-icon)` или явно `.progress-metric strong .animated-number{font-size:inherit}`; подписи через `plural` (RU/EN). Тест в `progress-screen.test.tsx` на «1 день занятий».

### 2.3. P1 — ответы маленькими буквами без знаков

В заданиях `text-input`/`translation` основного курса шторка показывает «Подходящий ответ: i didn't go there yesterday», «can you come tomorrow»; фишки сборки фразы тоже в нижнем регистре («i»). Причина: импорт из English Trainer хранит в `answer.accepted` нормализованные строки, а UI показывает `accepted[0]`. В диалогах уже есть `displayAnswer` (`dialogue.tsx`), в заданиях — нет. Во фразах практики регистр нормальный.

**Как решать:** добавить в схему задания необязательный `displayAnswer` и заполнить его в импортёре (по `source`/правилу: заглавная первая буква, `i` → `I`, `?` для «Сделай вопрос», точка иначе); до выпуска нового контента — функция отображения в UI с теми же правилами. Сверку ответа (`checkAnswer`) не трогать.

### 2.4. P1 — онбординг: выбранный курс не виден

На 360×640 первый экран показывает только карточку «A1: первые шаги», а выбран по умолчанию **второй** курс (галочка у «Общего английского» скрыта под прилипшей кнопкой «Начать день 1»). Человек нажимает кнопку, думая что начинает A1, и попадает в «Основу фразы».

**Как решать (любое):** подпись кнопки с названием курса («Начать: Общий английский»); или без выбора по умолчанию — кнопка неактивна, пока не выбран курс; или поставить выбранный курс первым. Сократить первый блок (иконка + заголовок занимают половину экрана).

### 2.5. P2 — навигатор разделов урока

На ≤390 px в строке «Теория / Задания / На скорость / Слушание / Говорение» видны три первых; в «Слушании» и «Говорении» **активный раздел за краем экрана**, и нет подсказки, что строку можно листать.

**Как решать:** при смене раздела `scrollIntoView({inline:'center',block:'nearest'})` для активного чипа; мягкий градиент по краям; либо на узком экране — короткие подписи/иконки.

## 3. Анимации и производительность

Замер: CPU ×4, production-сборка. Холодный старт до кнопки «Начать» ~1,0 с, long tasks 246 + 122 мс (разбор бандла и проверка курса). Открытие урока ~0,6 с, ответ → шторка ~140 мс, переход к следующему заданию без long tasks, прокрутка теории 3300 px без потерянных кадров. В headless-Chromium blur считается программно, поэтому ниже — риски по устройству, а не измеренные рывки.

### 3.1. P1 — blur в переходах на всю высоту экрана

`filter: blur()` есть в ключевых кадрах:
- `screen-enter` — на **весь** `.app-screen` при каждой смене экрана (теория дня 1 — 3300 px высотой);
- `activity-view-in/out` — снимки View Transition на каждое задание;
- `answer-mode-in`, `content-ready-in`, `number-pop`, `chip-settle` (brightness).

`filter` переводит элемент в отдельный слой и заставляет растрировать его целиком с размытием каждый кадр анимации. На 3× экране слой 360×3300 — это ~120 МБ текстур; на бюджетных Android WebView это первый кандидат на «подтормаживает при переходе» и на мигание.

**Как решать:** во всех экранных и «задание → задание» переходах оставить только `opacity` + `transform` (на глаз разница с blur 1–1,5 px почти не видна). Blur, если он нужен, — только на маленьких элементах (иконка, число) и без `will-change` навсегда.

### 3.2. P2 — нижняя панель и вечные анимации

- `.tabbar{backdrop-filter:blur(16px)}` поверх прокручиваемого контента — пересчёт размытия на каждый кадр прокрутки. На Android сделать непрозрачный фон (уже есть fallback-ветка `@supports not`), например по `data-platform="android"`, или уменьшить радиус до 8 px.
- Бесконечные: `here-pulse` у текущей станции «Маршрута» (compositor-only, но крутится, пока экран открыт), `shimmer` у скелетонов (`background-position` = перерисовка каждый кадр), `voice`, `speaking-pulse`. Пульс станции ограничить 3 итерациями; shimmer — через `transform` псевдоэлемента.
- `prefers-reduced-motion` учитывается почти везде — хорошо.

### 3.3. P2 — размер бандла

`index-*.js` 841 КБ (245 КБ gzip). По sourcemap основной вклад: код приложения ~660 КБ исходника, `react-dom`, **`zod` ~360 КБ**, `react-router` ~355 КБ, `@tanstack/query-core`. Админка уже вынесена в отдельный чанк.

**Как решать:** `zod/mini` или проверка схемы курса только на сервере/при выпуске (клиент получает уже проверенный выпуск); `lazy()` для редких экранов (ИИ-разговор, справочник, настройки, юридические страницы, уведомления); английский словарь интерфейса грузить по требованию. Цель — < 500 КБ основного чанка.

### 3.4. P3

- `AnimatedNumber`/`AnimatedProgress` анимируют через `requestAnimationFrame` + `setState` (перерисовка React каждый кадр на 0,5–0,8 с); полоска прогресса анимирует `width` (layout каждый кадр) и держит бесполезный `will-change:width`; у каждого числа постоянный `will-change: transform, filter, opacity` (лишний слой на число). Перевести полоски на `transform: scaleX()` с CSS-переходом, кольцо — на `@property --course-progress`, `will-change` только на время анимации.
