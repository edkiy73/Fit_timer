# Аудит V20 — раздел «Люди / Профили других / Доступы» (people)

Готово: findings-people.json (46: P0 1, P1 3, P2 17, P3 25), coverage-people.json, скриншоты в screens/issues/people/.
Скрипты: scratchpad/pw/people/*.mjs (deck, likes, filt*, hist, states, pair, prof1/2, menu*, links, access, grant, block*, p10*, p05, misc, resp, couple2, key*, r04, extra).

## Важно знать
- QA.autoApprove по умолчанию = true: любая симпатия сразу взаимна, запросы одобряются через 1.2 с. Для реальных сценариев ставить QA «Мои запросы → Ждать ответа».
- Глобальный S недоступен из page.evaluate; всё проверялось через UI.
- Подсказки координатора: кнопки на карточке подборки («Подписаться», «Полный профиль», счётчики) нажимаются после прокрутки карточки — ложное срабатывание краулера (он цеплял кнопки следующей, inert-карточки). pView в шапке профиля действительно перекрыт .pc-info → PRF-004.
- Ключ в подборке при открытом доступе прокручивает карточку к приватной части — работает.

## Не проверено
- Тёмная тема и EN в этом разделе; оплата подарка Premium; подтверждение «Прекратить общение» (раздел чатов); реальный touch на устройствах (только CDP touch-события).
- Состояния вуали «Прежний доступ закончился» и «Решили не открывать · через N дн.» на профиле — недостижимы в демо (PRF-018).

## Мелочи, не оформленные находками
- X01 Видимость: выбор «Выключены» для пары даёт тост «Пара скрыта из знакомств» (текст про скрытие, а режим — выключены) — раздел «Я».
- Док «Комьюн…» обрезан на 320 — общий компонент дока.
- После QA-перехода (FT_QA.go) открытый диалог может остаться поверх нового экрана — артефакт QA-навигации.
