# FetUre — разработка только на подписках ChatGPT и Claude (12.10.2026)

**Политика владельца: отдельные платные OpenAI/Anthropic API не используются.** Никаких `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, платных API-runner'ов в GitHub Actions или автоматических покупок кредитов. Старые API-based workflows удалены. Настроенные GitHub/Vercel/Supabase остаются как есть. Существующий AppBase CI остаётся.

## Единый источник задач
- Текущее состояние MVP: [STATUS](mvp-plan/STATUS.md), требования: [карточки](mvp-plan/README.md). Исторический ~97 KB план **не читать целиком**.
- Мелкие независимые задачи — GitHub Issues `[FetUre Queue 01] ...` и далее. Начальная очередь: #826, #827, #829. В PR указывать `Closes #номер` — Issue закроется после merge.
- `STATUS.md` фиксирует проверенные вехи и handoff; открытый PR ≠ выполненная задача. Не переписывать чужие текущие работы.

## Автоматический исполнитель без API
**Claude Code Routines — предпочтительный плановый исполнитель.** Это отдельная официальная функция облачного Claude Code для Pro/Max/Team/Enterprise; задачи по расписанию используют **лимиты подписки**. Доступность зависит от аккаунта, функция в preview.
- Открыть с телефона: https://claude.ai/code/routines → New routine.
- Рутинa: `FetUre — next safe issue`. Репозиторий: `edkiy73/Fit_timer`. Поставить **Schedule: daily** для первой проверки. Повысить частоту только после успешных запусков и оценки лимитов.
- Вставить **весь текст** из [claude-routine-prompt.md](claude-routine-prompt.md) в Instructions. Model — сильнейшая доступная **в рамках подписки**, без платных опций.
- Доступы: только репозиторий GitHub и необходимые стандартные средства для сборки; убрать ненужные подключённые connectors. Не выдавать производственные секреты Supabase/Vercel, не подключать платёжные сервисы, не разрешать произвольные сторонние веб-адреса.
- Запуск: Run now → убедиться, что Claude выбрал Issue #826, сделал отдельную ветку и PR, выполнил проверки. Включить расписание после пробного результата. Если нет доступа к Routines — использовать облачный Claude Code вручную, передавая тот же prompt.
- Запуск нового Issue только **если нет уже открытого Claude/FetUre PR, ожидающего проверки**, чтобы не было конфликтов и двойной траты квоты. Один запуск — одна маленькая задача, никаких автослияний.

## Второй независимый исполнитель/ревьюер на подписке ChatGPT
- **Codex Cloud:** можно давать отдельные небольшие задачи из очереди вручную, вход через ChatGPT-подписку, без API-ключа. https://chatgpt.com/codex
- **ChatGPT Work:** при наличии в интерфейсе GitHub event-triggered Scheduled Tasks можно настроить проверку нового PR FetUre (без API). Промпт: `Review newly opened FetUre pull requests against apps/feture/AGENTS.md and docs/ui-quality.md. Check privacy/auth risks, data loss and app responsive behavior. Report actionable file/line findings and explicitly untested conditions. Do not merge, deploy or rewrite other apps.` Запускается по событиям PR, если этот триггер реально доступен в подписке. Альтернатива — открыть PR вручную в новом ChatGPT/Codex чате.
- ИИ-разработчик и ИИ-ревьюер должны по возможности быть разными моделями; GitHub CI подтверждает сборку, а не UX/privacy-приёмку.

## Ограничения расхода и безопасности
- **Подписки имеют лимиты**, поэтому не обещать круглосуточную непрерывность; при исчерпании квоты задачи ждут. Выключить Claude **Extra usage / overage** и любые необязательные платные кредиты. Контролировать счётчик подписки.
- GitHub Actions и Vercel могут потреблять **свои** минуты/квоты даже без модельных API. Продолжаем существующую политику экономии деплоев.
- Никаких сырых OAuth / session cookies или скриптов, обходящих механизм подписки. GitHub workflow не запускает ИИ и не содержит модельных секретов.
- Без auto-merge. Серверная приватность, возрастная проверка, продакшн SQL и Core shared-изменения — отдельная ручная проверка, ни одному плановому агенту нельзя самостоятельно применять их в live.
- При падении/потере чата восстановление: новый агент читает `AGENTS.md`, `apps/feture/AGENTS.md`, [STATUS](mvp-plan/STATUS.md), одну карточку, открытые Issues и PR. Не пересказывать прошлые чаты.
