# A05 — документы и согласия

Публичный `GET /api/catalog?resource=documents&locale=ru|en` читает только проверенные опубликованные версии через anon key. История конкретной версии доступна по `id`; пользовательские согласия и редакционные черновики не входят в ответ. React отображает разрешённые абзацы, заголовки и списки как текст, без HTML/eval.

Продуктовый раздел общего AppBase Admin хранит черновики с CAS revision, показывает предпросмотр и требует явного одобрения точной сохранённой редакции. Девять начальных текстов содержат список незаполненных юридических условий; они не публикуются автоматически. Отмена публикации/возврат текста — новая версия, предыдущая неизменяема.

`documents.accept` принимает только ID актуальных вступивших в силу версий; owner, hash и время определяет сервер. Receipt неизменяем; повтор запроса сохраняет исходное время. Обязательные terms/privacy/community/adult-content нельзя сделать необязательными. Начальная каноническая редакция RU; EN не заменяет новые обязательные RU документы. Изменение каждого обязательного документа требует отдельного повторного согласия. Срок будущей версии не закрывает доступ преждевременно.

Чувствительные методы проверяют возраст и актуальные согласия в handler и repository. При отсутствии зависимости документы не считаются принятыми. Проверка на следующем запросе закрывает доступ после новой публикации. Уже полученные клиентом сведения нельзя технически отозвать.

Проверка `tests/documents-postgres.mjs`: собственные receipts трёх аккаунтов, stale revision, явное review, идемпотентная публикация и согласие, новый обязательный текст, будущая версия, immutable SQL triggers, запрещённые типы rich text, actor spoof и запрет anon/authenticated на drafts/receipts/RPC.

Схема применена в FitT в prelaunch; по умолчанию нет опубликованных документов и receipts. Live OTP, production adult provider и финальная юридическая редактура остаются внешними условиями приёмки. Стартовые тексты нельзя считать юридическим заключением.
