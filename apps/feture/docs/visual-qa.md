# FetUre — быстрые реальные React-снимки (Issue #826)

После `npm ci` из `apps/feture` запусти `npm run test:visual`. Этот режим сам собирает `dist`, запускает существующий локальный E2E HTTP/API стенд с **memory store** и Chromium через `playwright-core`; при отсутствии Chromium задай `FIT_CHROME=/path/to/chromium`. Не требуется email-домен, живой Supabase, персональные сотрудники или production secrets.

Команда делает настоящие скриншоты React маршрутов `/`, `/explore`, `/account` (гость и тестовый Core аккаунт), `/profile`, `/admin` (экран входа). Для каждого — ширины **320, 390, 768, 1024, 1440** и контроль горизонтального переполнения, дополнительные тёмные варианты на 390/1440. Папка `.artifacts/visual-qa/` локальная, исключена из Git и не попадает в `dist`/production; никакие снимки не отправляются наружу. Снимки тестовой сессии показывают **лишь фактически открывшееся состояние**; например, недоступный age-gated profile — это не проверка успешно сохранённого профиля.

В обычном `npm run check` изображения **не создаются**: только дешёвая проверка синтаксиса E2E. Обычный `npm run test:browser` продолжает прежний smoke без визуального режима. Сами картинки проверяет человек или независимый агент: обрезание, ломаные формы, нужные действия, фокус/Tab/Escape/Back, safe-area и 200% zoom — **не доказываются** только флагом «no overflow». Реальные две учётные записи, staff permissions, Android/iOS/fold, авторизация по внешней почте, публикации и производственная приватность требуют отдельной приёмки. Не использовать инструмент для снимков реальных личных данных.

Проверено 12.10.2026: Chromium Headless Shell, 42 снимка (6 состояний × 7 размеров/тем), overflow и видимость навигации passed. QA API обслуживает настоящий публичный каталог; вход ожидает завершения перехода, тема загружается из сохранённого предпочтения. Локальный memory OTP — не доставка внешней почты. Профиль без adult proof показывает защитное состояние; это не приёмка сохранения профиля.
