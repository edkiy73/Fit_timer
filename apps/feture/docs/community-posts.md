# C01.1 — текстовые публикации

`Сообщество` читает ленту и собственные публикации через `/api/domain`, Core email session и закрытую `feture_post_command`. Никаких статических людей, счётчиков и постов. Форматы: мысль, история, вопрос; текст до 3000, явно указанное имя до 80 символов. Приватный профиль и ответы опросников не копируются.

Жизненный цикл: `draft` → явное согласие в форме → `pending` → ручная проверка C01.2a → `published`/`rejected`/`hidden`. Клиентской команды публикации/одобрения нет. До одобрения текст видит только автор. Одобренная общая лента требует действующего adult/consent права обеих сторон и отсутствия блокировки/ограничений. `private` — черновик; `public` — заявленная аудитория после проверки. Выбранные получатели пока не реализованы, `granted` не принимается.

Сохранение правок снимает старую публикацию с ленты, возвращает в приватный черновик и требует повторной проверки. Изменения проходят CAS; UUID операции и хеш команды защищают повторы от дубликатов. Повтор возвращает текущую запись, никогда не оживляет удалённый текст. Удаление очищает текст/имя; чтение и список собственных черновиков и удаление остаются доступны при потере adult/consent. Доступ к чужому тексту повторно проверяется при каждом запросе. Cursor: время и ID, 20 записей; никакого total/count скрытых публикаций.

Форма привязана к сессии, не сохраняет чувствительный текст в localStorage, предупреждает перед уходом. После неопределённого ответа команда заморожена для точного повтора; обновление собственных записей помогает проверить конфликт, текст остаётся в форме. Лента обновляется при возврате к экрану и очищается при отказе.

SQL `20261011133134` применён к prelaunch FitT. RLS и grants: только service_role, SECURITY INVOKER; anon/authenticated не читают таблицы и не вызывают RPC. Миграция требует пустую старую таблицу публикаций, проверено live: 0. Данные других продуктов не затронуты.

Проверено: typecheck/build, существующий check, API identity/guard/closed DTO, PostgreSQL ACL/CAS/replay/erase, live rollback без сохранённых fixture документов/профилей/proofs/постов. Chromium fixture: сохранение, отдельное согласие, own pending, правки, удаление; 320/390/768/1024/1440 без horizontal overflow. В браузере ответы подставлены, SQL проверен отдельно. Независимый Sol 6.1 privacy audit, два настоящих аккаунта и native QA открыты. Настоящие документы и production proof пока не настроены.

Решения управляющего реализованы C01.2a. Остаются C01.2b жалоба на пост, C01.3 выбранная аудитория, безопасные photo uploads и отдельный whitelist выбранного результата теста. C01 целиком не закрыт.

## C01.2a — личная проверка публикаций

`/#/operator` → «Публикации»: управляющий с действующим adult/consent правом читает только явно отправленные `pending`/`published`/`hidden` тексты, принимает approve/reject/hide/reopen с CAS и причиной. Собственный пост одобрить нельзя. Reopen возвращает скрытый текст в pending, затем требуется отдельное одобрение. Черновики/удалённые тексты в очередь не попадают. При отзыве/смене роли или сессии экран очищается.

`feture.posts.queue/audit/decide` в существующем `/api/admin` требует личную Core сессию; ключ не заменяет её. RPC `feture_post_review_command` проверяет роль через существующую bound staff функцию и ту же блокировку назначений. SECURITY INVOKER: новые привилегии чтения staff таблиц не добавлены. Роль привязана к поколению Core аккаунта. QA оператор не получает UGC доступ; аудитор читает только журнал с ID/версией/причиной/временем без текста, профиля или ответов. Внутренний журнал дополнительно фиксирует actor/generation без email и сырого текста. Повтор того же решения возвращает текущий статус без восстановления прежней версии; отзыв роли запрещает даже повтор.

Проверки: полный check, PostgreSQL цепочка submit→approve→hide→reopen→approve→edit→delete, stale generation/CAS/replay/role revoke, self-review denial и auditor privacy; live rollback и grants. Browser fixture: явная отметка перед approve, hide/reopen, очистка при 403, auditor/QA ограничения, 320/390/768/1024/1440 без overflow (API подставлен). Real staff+author аккаунты, независимый Sol 6.1 и native QA остаются. C01.2b жалобы на конкретный пост пока отсутствуют; авторские апелляции/права moderator отдельно от manager и очереди с приоритетом — следующие срезы, не заявлены реализованными.
