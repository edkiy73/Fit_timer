# Опросники и приватные результаты

W03.1: `/#/tests` и `/#/tests/:attemptId`; продуктовый admin «Опросники FetUre». Сохранение, возврат к черновику, явный пропуск, завершение, отдельное повторное прохождение, удаление. Шесть начальных опубликованных опросников по восемь вопросов: динамика, близость, ощущения, границы/приватность, формат отношений и темп. Черновики не видны пользователю; старые 18 описателей каталога не считаются наполненными опросниками.

## Версии и расчёт

Admin-конструктор редактирует заголовок, вопросы single/multi/scale, варианты и веса 0–4, направления и тексты low/mid/high. JSON — данные, нет eval/HTML/исполняемых формул. В каждом направлении не менее двух вопросов. Шкала — пять последовательных весов. Публикация конкретной сохранённой редакции требует reviewed. Published version не имеет UPDATE/DELETE grant даже для service_role; новое редактирование создаёт новую редакцию. Retire скрывает новые прохождения, не удаляя старые ответы.

Attempt закреплён за version_id. Владелец имеет не более одного активного черновика данного опросника и не более 100 неудалённых прохождений. Повтор start возвращает текущий черновик. Retake завершённого создаёт отдельный attempt по текущей версии. PostgreSQL рассчитывает результат из закреплённого definition и answers; client score отклоняется. Один вопрос имеет один вес; multi использует среднее выбранных весов. Пропуски не нули. При менее половины ответов направления вывод insufficient; иначе средний вес <1,5 / <2,75 / до 4 определяет low/mid/high. Результат показывает число ответов и вопросы, на которых основан вывод. Он не диагноз, не обещание поведения и не согласие. Автоматических изменений карты нет.

## Приватность, повтор и удаление

`tests.list/start/read/save/complete/delete` не принимают owner/роль/возраст от клиента. Core account/device-token проверяется на сервере; fake Actor отклоняется. Чтение/сохранение дополнительно требуют совершеннолетия и точных текущих согласий. Удаление требует действительной собственной сессии, доступно после истечения возрастного допуска. Все private tables закрыты RLS и не имеют anon/authenticated grants; admin actions не читают answers/results. Ответ transport проецируется whitelist, включая вложенные definition/result.

Save/complete/delete используют operationId и expectedRevision. Owner transaction lock, CAS и payload hash исключают повторное выполнение/чужое изменение. Receipt хранит только hash и attempt_id. Удаление очищает answers/result, оставляя пустую tombstone; старый save/start/complete retry не восстанавливает ответы. Удаление `feture_profiles` каскадно очищает attempts/receipts; полный Core account-erasure flow — отдельная O02.

Форма только в памяти и keyed по account/device/token/attempt. После switch старый ответ не записывается в новую сессию. На сетевой ошибке ответы остаются; retry отправляет ту же операцию. Изменение формы запрещено, пока исход операции неизвестен: можно повторить или явно загрузить сохранённое. Переход предлагает сохранить, остаться или уйти без сохранения; reload предупреждает beforeunload. Нет offline queue/общего localStorage с ответами.

## Проверка и границы

Полный check: unit 17, security 20, PostgreSQL 8, TypeScript и build. Один focused UI сценарий проверяет потерянный ответ, блокировку перехода и точный retry; один PostgreSQL contract — версии, scoring/skip/extremes, CAS/replay, owner isolation/role denial, erasure. Live service-role assertions выполнены в rollback: тестовая публикация/ответы не сохранены. Live после W04.1 — шесть опубликованных versions, ноль attempts/receipts. Это не production adult access и не пользовательская browser/native приёмка; A01/A04/A05 остаются внешними зависимостями. W04.1 редактура и публикация выполнены; W04 целиком требует пользовательской приёмки с production доступом; W05.1: явный перенос выбранных приватных тем теперь реализован, см. [result-map contract](result-map.md).
