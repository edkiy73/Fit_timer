# FetUre — визуальный эталон из Claude MVP (12.10.2026)

**Источник:** [оригинальный интерактивный HTML](design-reference/claude-mvp-concept-2026-10-12.html) (1079 строк / ~230 КБ). **Не открывать весь HTML на каждом задании:** эта выжимка — основной источник для дизайн-задач. Оригинал читать **только точечно** для воспроизведения конкретного движения/экрана.

## Что одобрено владельцем и надо сохранить
- Общая эстетика, типографика, палитра, композиция карточек, мягкие тени, отступы и анимации прототипа лучше текущего технического UI.
- Плавающее нижнее меню, пружинящие/инерционные реакции на касание, раскрывающиеся нижние панели, анимации появления и перемещения карточек.
- Цвета должны работать **в обеих темах** и поддерживать контраст/доступность. Референс — направление, не 1:1 шаблон всех экранов.

## Подтверждённые исходным HTML дизайн-токены
- **Шрифт:** Geologica Variable, fallback system-ui / -apple-system / Segoe UI / Roboto / sans-serif. Заголовки насыщенные (700–900), часто `SHRP:100`; базовый текст 15px / 1.5. В исходнике заголовки ~26px, большие промо-названия ~64–96px. Не копировать фиксированные размеры без clamp/адаптации.
- **Светлая тема:** фон `#F3EEF2`, дополнительный `#EBE3EA`, поверхность `#FFFFFF`, приподнятый `#F8F3F7`, текст `#1E1219`, secondary `#75606D`, граница `#E3D7E0`.
- **Тёмная тема:** фон `#1A0F16`, secondary `#140B11`, поверхность `#241520`, elevated `#2F1C2A`, текст `#FBF0F4`, secondary `#B89FAD`, граница `#43293B`.
- **Акценты:** latex/coral `#E01A3E` (dark `#FF3355`), lilac `#5C47D6` (dark `#B9A6FF`), mint `#1E8A62` (dark `#7FE0B9`), amber `#B7741A`. Цвет применяй по смыслу, не заливай все элементы акцентами. Тени исходника: `0 18px 40px -22px rgba(60,20,45,.35)` для light.
- **Радиусы:** карточки ~22px, крупные панели ~24–30px, кнопки ~18px, чипы pill, поля ~16px. Отступы типично 8/10/12/14/16/18/22/24, мобильные поля экрана ~16px.
- **Кнопки:** высота основной ~54px, основные input ~54px, иконка-кнопки ~42px, touch targets в production — минимум 44–48px.
- **Нижняя навигация:** floating rounded dock около 66px с background blur(20px) saturate(1.4), safe-area bottom, подсветка выбранного элемента с лёгким scale/opacity. Не делать blur на больших списках.
- **Bottom sheet:** скругление верха ~28px, максимум высоты ~88%, внутренний скролл, анимация `translateY(105%) → 0` за ~340ms `cubic-bezier(.2,.8,.2,1)`; фон затемняется за ~250ms. Production: React Aria dialog, focus trap/return, Back/Escape, dirty state, z-index выше dock.
- **Появления:** `translateX(±26px)` + opacity за ~340ms; нажатия кнопок ~120ms `scale(.98)`; chips ~`scale(.95)`; reveal карточек `cubic-bezier(.2,.8,.2,1)`.
- **Свайп-карточки:** стек с `scale(.94–.95)`, `translateY(10–14px)`, drag без transition, fly ~280ms, прогресс на карточке; контент внутри скроллится, поэтому корректная арбитрация swipe и vertical scroll обязательна. Полноценная поддержка touch/pointer/mouse/reduced-motion.
- **Контроль анимации:** `prefers-reduced-motion: reduce` выключает необязательные переходы. Не анимировать `filter`/`backdrop-filter` для длинного списка, не поддерживать бесконечные expensive effects в фоне.

## Что в прототипе нельзя слепо переносить
- **Desktop НЕ разработан как самостоятельная продуктовая версия.** При ширине >760px он показывает панель индекса и **390px phone mockup**, а не полноценный адаптивный сайт. Это только презентационная оболочка. Production должен иметь самостоятельные композиции и навигацию на 768/1024/1440; планшеты, fold и desktop равноценны телефону.
- В самом HTML есть наложенные «fixes v3», ручные стили, inline JS, mock-профили, демонстрационный характер и потенциальные конфликты слоёв. Это **не production-код и не готовая библиотека**. Не копировать огромное содержимое в React.
- Не переносить fake interactions, некорректные точки попадания/скролл, placeholder avatars, paywall, identity, age/consent и private fields без серверного контракта и реальной UX-логики.
- Оригинальная ширина 390px не гарантирует 320px, экранную клавиатуру, fold, landscape и 200% zoom: проверить на настоящем приложении.
- Не требовать новой UI-библиотеки ради косметики. Стек: React + TS + React Aria Components + Motion (уже установлены) + AppBase UI. Новую библиотеку брать только если существует измеримая проблема, которую штатный стек не решает.

## Обязательная последовательность UI-задачи
1. **Сначала 1-страничный UX blueprint**: цель экрана, информационная иерархия, реальные CTA, состояния, responsive композиции 390/768/1440 и зависимость от API. Это часть PR или короткого Issue-комментария, не новый многомегабайтный документ.
2. **Затем реализация** с реальными компонентами и данными. Повторно использовать токены/примитивы; продумать empty/loading/error, keyboard/back, safe-area.
3. **Затем визуальное QA:** реальные браузерные скриншоты минимум 390 и 1440, плюс 320/768/1024 при значимых изменениях. Сравнивать общие пропорции/динамику с эталоном. Проверить не только билд, но и функционал.
4. Описать в PR **что взяли из прототипа, что специально адаптировали, что проверено и что нет**. Нельзя принять UI по одному typecheck.

## Приоритетные экраны первой дизайнерской волны
1. Онбординг и новый полноценный **Аккаунт/Профиль** (A06, A01), где нынешний экран — технический набор ссылок; учитывать зависимости server auth и privacy. Не превращать личный кабинет в обязательную анкету.
2. «Мой мир» и редактор интересов, состояния карт и progress.
3. Общая AppBase админка — только при сохранении общей оболочки, компактные workflow/dialogs вместо бесконечных форм.
4. Сообщество и затем dating — после готовности серверных прав и модерации.

*Референс отражает визуальные предпочтения владельца, а не подтверждает правильность исторического функционала из прототипа. Продуктовое поведение определяется текущими MVP cards и реальными серверными контрактами.*
