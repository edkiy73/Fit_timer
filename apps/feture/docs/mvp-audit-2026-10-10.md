# FetUre — аудит исходников и решений перед MVP

Дата: 2026-10-10. Проверенный код: `e4aead4c5dd2218cff80b79bce7465d33012e5dc`.
Аудит кода и документов, не проверка работающего production и не юридическое заключение.
Исполняемый документ: [план MVP](launch-mvp-plan-2026-10-10.md).

## Источники и приоритет

1. Последние прямые требования владельца: сайт открыт; все платформы полноценны; временные данные без legacy; реалистичное наполнение без технических плашек; анимации; планшеты/foldables; исходная механика свайпов.
2. `apps/feture/AGENTS.md`, фактические контракты AppBase и текущий код.
3. Прикреплённая MVP-концепция 3.1: самостоятельная польза «Мой мир», исследование, сообщество, знакомства opt-in; подсказки, дневник, приватность, четыре раздела. Проверен JS, поскольку тело HTML почти пустое.
4. Прикреплённый «MVP-концепт интерфейса (1)»: богатая карточка людей, полный профиль внутри, стопка, фото, like/pass/undo, запрос доступа, пары. Это источник механики, не готовый код React.
5. Прикреплённая «концепция, стратегия и план запуска (3)»: дневник, шаринг/сравнение, парный профиль, согласия, свободная безопасность, локальная плотность маркетинга, метрики.
6. Официальные страницы конкурентов и платформ ниже. Отдельного приложенного файла/URL «страница конкурентов» не обнаружено; проверены упомянутые в концепции продукты напрямую. Ранее обсуждавшееся позиционирование не считается доказательством отсутствия функций у конкурентов.

Старые HTML не переписаны. Их утверждения о процентах совместимости, конверсии Hinge, бюджетах и этапах compliance не становятся обязательствами или проверенными фактами. Изменение позиции «дейтинг первым» → «самопознание первым» сохраняется. Старое предложение урезать мобильную версию сразу заменено последним решением владельца.

## Что подтверждено кодом

| Область | Факт | Следствие |
|---|---|---|
| UI | `src/feture/experience.tsx`: React, четыре вкладки, hardcoded DEMO_POSTS/PROFILES, локальные взаимодействия | Внешний вид не доказывает действующее сообщество/дейтинг |
| Карта | `model.ts`: один status + intensity + visibility + клиентское at; `categoryProgress` = доля изученных тем | Опыт не может полноценно сосуществовать с желанием/границей; часы клиента недостаточны для конфликтов |
| Sync | `src/sync.ts`, `use-interest-map.ts`, `lib/app-sync-schema.js`: interest-map зарегистрирован в документном Core sync | В PostgreSQL одновременно есть feture_interest_states; требуется выбрать каноническое хранилище |
| Auth | `api/auth.js` использует createAuthHandler; `api/sync.js` — createSyncHandler | Переиспользовать Core, не добавлять Supabase Auth и вторые аккаунты |
| PostgreSQL | Миграции 001/002 описывают 9 таблиц, публичный каталог и закрытые личные таблицы | Наличие миграции не доказывает текущую схему/секреты в production; README сообщает о применении, повторно не применять вслепую |
| Каталог | 12 категорий / 144 темы / 18 описаний тестов | Это редакционный материал, не 18 работающих опросников |
| Mobile | Capacitor config + prepare scripts, без опубликованных приложений | Готовность APK/iOS ещё не подтверждена |
| Инфраструктура | FetUre vercel.json содержит build/output, собственного ignoreCommand нет | Не считать, что дисциплина деплоев FitTimer автоматически настроена у FetUre |
| Проверки | package.json: typecheck, test:smoke, test:unit, build, общий check | Использовать фактические команды FetUre, не тяжёлую лестницу legacy FitTimer |

Секреты, живая БД, биллинг, отправка OTP, native build, скорость и реальные пользовательские сессии в этом аудите не проверялись. README о неактивном backend — указатель для проверки, не доказательство текущего состояния dashboard.

## Изменения относительно прежнего плана

| Недостаток | Решение |
|---|---|
| Два параллельных порядка работ, M0 требует сразу все домены | Один граф задач; наполнения добавляются рядом с соответствующей схемой |
| Личное состояние в документном sync и таблицах без правила владения | PostgreSQL — источник истины домена; Core — auth/общие сервисы; IndexedDB — изолированный кеш/очередь |
| Адаптивность и motion отложены в конец | Общие компоненты в первой вехе, проверка при каждом существенном UI изменении |
| Нет формального ACL/состояний согласия | Матрица прав, ограничения полей, конечные состояния, серверная отмена |
| Signed URL назван немедленно отзываемым доступом | Для отзыва — авторизованная выдача; уже скачанное отозвать невозможно |
| Проверка документа «для всех» смешана с юридическими требованиями | Отдельные account, age, identity; провайдерный контракт сейчас, рынок и процедура перед внешним включением |
| Прототипная модель интереса смешивает опыт и желание | Независимые поля; граница сильнее ранжирования; отсутствие ответа не равно отказу |
| Потеряна самостоятельная польза и вирусный цикл | Дневник, история, выбранная share-карточка, приглашение и сравнение — обязательные задачи |
| Пары отложены неопределённо вопреки сильной концепции | Ограниченный MVP пары: два аккаунта, общий слой, взаимное подтверждение; без общего пароля и произвольного графа |
| Автоматическая модерация/админка после публикаций | Контракты жалоб/карантина/ролей до UGC |
| Непроверяемые «готово» | У каждой задачи зависимости, файлы, результат, проверка и запись handoff |
| Требование demo labels в AGENTS противоречит последнему решению | Служебная маркировка только в БД/админке; перед запуском seed-профили исключаются из реальной выдачи |

## Технические и внешние источники

- [Supabase Storage access control](https://supabase.com/docs/guides/storage/security/access-control): service key обходит RLS; серверная авторизация обязательна. [Changelog](https://supabase.com/changelog.md) не удалось прочитать через web-парсер (тип text/markdown); перед реализацией сверить релевантные изменения повторно.
- [Motion gestures](https://motion.dev/docs/react-gestures): базовые жесты доступны; разрешение конфликта swipe/scroll/gallery остаётся обязанностью приложения, не обещанием библиотеки.
- [Apple App Review](https://developer.apple.com/app-store/review/guidelines/), 1.1.4/1.2: ограничения явного сексуального контента и требования к UGC. [Google Play](https://support.google.com/googleplay/android-developer/answer/9878810): ограничения sexual content. Полный исходный продукт сохраняем, публикацию конкретной сборки не обещаем. Внешний gate не повод остановить разработку.
- Перед выбором платежей, хранения adult-media, age-provider и стран запуска отдельно проверить действующие договоры/политику именно выбранных сервисов. Этот аудит не подтверждает их пригодность и не выводит возраст 21+ просто из страны проживания владельца.

## Что SOL не должна делать на основании прототипов

Не переносить случайные проценты/online/расстояния/успешные toast в реальные домены. Не выдавать интерес или тест за согласие на действие. Не импортировать все ответы в карту автоматически. Не расширять видимость при merge, после мэтча или связи пары. Не отправлять приватные ответы в аналитику/LLM. Не закрывать весь сайт. Не поддерживать старые временные форматы. Не менять FitTimer/UnMute/общую БД при сбросе FetUre.
