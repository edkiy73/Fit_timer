# W07.2 — отзывные ссылки на выбранные темы
Статус: **SQL установлен в prelaunch Supabase, код PR #797 проверен CI; требуется независимый security/privacy review, слияние PR и реальные 18+/native испытания.**

## Контракт
- Владелец вручную выбирает 1–6 тем и подтверждает конкретную ревизию, отношение и срок 1/3/7 дней.
- Сервер собирает immutable snapshot только из доверенных `feture_interest_states` и `feture_interests`, без заметок, ответов, опыта, границ, intensity, email, ID пользователя и raw DTO.
- UUIDv4 ссылки — bearer capability внутри hash-router URL fragment. Создание/read разрешены только через Core session с доверенным 18+ и актуальными юридическими согласиями; SQL дополнительно требует `feture_peer_eligible` у владельца при создании и у обеих сторон при чтении.
- Чтение повторно проверяет действительность ссылки, owner/viewer eligibility, блокировки и **все исходные ревизии**. При изменении или удалении хотя бы одной темы ссылка закрывается целиком.
- Отзыв/list разрешён владельцу с действующей Core session даже после истечения age/consent proof, чтобы не оставлять неудаляемую ссылку.
- TTL ограничен семью днями; максимум десять одновременно действующих ссылок на владельца; операция создания с тем же UUID идемпотентна и CAS revisions обязательны.
- База `feture_share_links` с RLS без доступа `anon` и `authenticated`, сервисная RPC на правах `service_role`. Получателю возвращаются только `title`, `stance` и expiry; route с noindex. Никакого публичного REST доступа к приватным таблицам.
- Локальный PNG из W07.1 независим от этой функции и по-прежнему невозвратен. Для ссылок реальный отзыв немедленен после успешной транзакции, уже сделанные получателем копии не удалить.

## Внутренний аудит защиты (2026-10-11)

В PR #797 серверный SQL gate создания дополнен проверкой `feture_peer_eligible(p_actor)` независимо от HTTP guard. PostgreSQL contract расширен: неподтверждённый владелец даже с записью карты не может создать ссылку, блокировка пары немедленно запрещает чтение, повтор отозванной операции не возобновляет доступ. UI корректно разбирает идемпотентный ответ `revoked=true` без застрявшего повтора. **Миграция позже применена штатно**: результат инструмент подтвердил `success:true`, схема и ACL проверены live. Независимый privacy review и двухаккаунтная acceptance остаются открыты.
