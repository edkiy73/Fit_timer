# W07.2 — отзывные ссылки на выбранные темы
Статус: **реализовано в PR #797, проверено CI/PGlite, НЕ РАЗВЁРНУТО**, ожидает независимого privacy/security review и SQL migration.

## Контракт
- Владелец вручную выбирает 1–6 тем и подтверждает конкретную ревизию, отношение и срок 1/3/7 дней.
- Сервер собирает immutable snapshot только из доверенных `feture_interest_states` и `feture_interests`, без заметок, ответов, опыта, границ, intensity, email, ID пользователя и raw DTO.
- UUIDv4 ссылки — bearer capability внутри hash-router URL fragment. Создание/read разрешены только через Core session с доверенным 18+ и актуальными юридическими согласиями; SQL дополнительно требует `feture_peer_eligible` у владельца при создании и у обеих сторон при чтении.
- Чтение повторно проверяет действительность ссылки, owner/viewer eligibility, блокировки и **все исходные ревизии**. При изменении или удалении хотя бы одной темы ссылка закрывается целиком.
- Отзыв/list разрешён владельцу с действующей Core session даже после истечения age/consent proof, чтобы не оставлять неудаляемую ссылку.
- TTL ограничен семью днями; максимум десять одновременно действующих ссылок на владельца; операция создания с тем же UUID идемпотентна и CAS revisions обязательны.
- База `feture_share_links` с RLS без доступа `anon` и `authenticated`, сервисная RPC на правах `service_role`. Получателю возвращаются только `title`, `stance` и expiry; route с noindex. Никакого публичного REST доступа к приватным таблицам.
- Локальный PNG из W07.1 независим от этой функции и по-прежнему невозвратен. Для ссылок реальный отзыв немедленен после успешной транзакции, уже сделанные получателем копии не удалить.

## Текущее состояние и приёмка
- CI `38121371033` — **success**, PostgreSQL contract проверяет два допущенных взрослых аккаунта, чужой owner, CAS/replay, missing age, note non-disclosure, hard boundary, revoke, blocked direct DB grants.
- **SQL не применён.** Попытка применить `20261011081500_feture_share_links.sql` через Supabase была отклонена системой безопасности инструмента. Проверка `to_regclass('public.feture_share_links')` вернула `null`. Нельзя заявлять работоспособность ссылки в online app и нельзя обходить блокировку другим путём. PR #797 оставлен открытым.
- A04/A05 всё ещё не подключены в production: Core identity не выдаёт доверенный adult flag. Обычный пользователь пока не может открыть новый share endpoint; нельзя отключать этот guard ради проверки UI.
- Необходима отдельная независимая проверка схемы (SOL 6.1 предпочтительно), разрешения безопасного SQL deployment, тест двух настоящих проверенных взрослых аккаунтов, ревокация при block/restriction/age/consent expiry, native Android/iOS share/deep-link и 320/390/768/1024/1440 layouts.
- W07.3 — только отдельное добровольное раскрытие каждой стороны при совместном сравнении; общих баллов привлекательности нет. Не входит в W07.2.

## Внутренний аудит защиты (2026-10-11)

В PR #797 серверный SQL gate создания дополнен проверкой `feture_peer_eligible(p_actor)` независимо от HTTP guard. PostgreSQL contract расширен: неподтверждённый владелец даже с записью карты не может создать ссылку, блокировка пары немедленно запрещает чтение, повтор отозванной операции не возобновляет доступ. UI корректно разбирает идемпотентный ответ `revoked=true` без застрявшего повтора. **Миграция остаётся неприменённой**: решение инструмента не обходится. Независимый privacy review и двухаккаунтная acceptance остаются открыты.
