# C02.4 — публичный автор / подписка / скрытие (контракт prelaunch)

1. Профиль `feture_profile_details.profile_id` **приватный**: нельзя использовать его в постах, ссылках, follow, mute или адресе API. `account_hash`, email, device/session/generation тоже никогда не возвращаются.
2. Для публичной связи нужен **отдельный случайный UUID v4** `publicAuthorId`, связанный с внутренним владельцем только в RLS-таблице FetUre (`service_role` only).
3. По умолчанию `publicAuthorId=null`; появление кликабельного автора требует отдельного, отзывного согласия «Мой публичный профиль и подписки». Публикация поста не означает такого согласия.
4. Сервер выдаёт идентификатор только с актуально опубликованным публичным постом, пока оба аккаунта eligible 18+, согласны с текущими правилами, не заблокировали друг друга, публикация доступна читателю и автор явно включил публичную связь.
5. Идентификатора нет в `mine`, черновиках/ожидающих постах, selected/private audience и в реакциях/комментариях/сервисных журналах. Анонимный запрос всегда закрыт.
6. Владелец может отключить доступ или сменить идентификатор. Отзыв сразу скрывает публичную ссылку и закрывает операции follow; ротация разрывает все входящие связи, чтобы прежний идентификатор не восстанавливал идентичность.
7. Сервер никогда не принимает `accountHash` получателя из клиента: только `publicAuthorId`, который сейчас резолвится в разрешённого автора. Существование недоступного ID не отличимо от несуществующего.
8. `Follow` — приватная связь зрителя, не выдаёт право читать закрытые посты, профиль, результаты тестов, фото, местоположение или участников. Нет публичных списков подписчиков, уведомления владельцу или публичного счётчика в первом срезе.
9. `Mute` — личная настройка зрителя, скрывающая публикации автора из его собственной ленты. Автору не видно и не сообщается, кто его скрыл.
10. Предпочтение mute над follow: скрытый автор не появляется в feed даже при сохранённой подписке. Существующая подписка сама по себе не раскрывает контент.
11. Все действия от Core-аккаунта через `/api/domain`, strict JSON DTO, случайный operationId v4, неизменяемый receipt и точный повтор; состояние меняет только серверная атомарная операция.
12. Права 18+/consent/block/отзыв/настройка автора проверяются **в каждом чтении и записи**; операции delete/unfollow/unmute самого зрителя доступны даже после истечения его допуска, чтобы он мог удалить свою связь.
13. Пагинация — не более 20 записей с непрозрачным cursor; никаких списков иных зрителей или скрытых авторов. Чужой профайл не открывается без отдельного явного доступа.
14. Роли anon/authenticated не читают RLS-таблицы и не вызывают приватные RPC; только сервер `service_role` с идентичностью Core. Действует global account quota и rate limit на новые связи.
15. В интерфейсе: кнопки «Подписаться / Отписаться» и «Скрыть / Вернуть» только на разрешённых публикациях; без цветового редизайна. Потеря ответа — повтор той же операции без ложного успеха.
16. Зависимости: внедрить opt-in owner API и rotation → отдельный проекционный `publicAuthorId` на публичных постах → follow/mute RPC → фильтр ленты и UI. Каждый шаг маленьким PR с CI.
17. До реального включения: независимый security/privacy review, SQL grants/RLS, 3 настоящих аккаунта (автор/читатель/блок), отзыв согласия, блокировка/ротация, устройство/fold и скрытый/deleted родитель; не считать CI достаточной приёмкой.
18. Исторический `authorLabel` — **только подпись у конкретной публикации**, не глобальный идентификатор и не источник follow. Не переносить поле `profile_id` или приватную карту в общий пост DTO.
