# A06 — приватный профиль

`profile.read/save` — отдельный owner-only домен за age/consent gate. Прежний `profile.get` содержит лишь имя и описание; ориентация/идентичность не попадают в него. Новые сведения находятся в `feture_profile_details`, без client grants/RLS policies. Сервер возвращает только opaque profile ID, семь разрешённых полей, revision и updatedAt. Email/owner/дата рождения/координаты/признаки доступа не входят в DTO.

Пошаговая React-форма позволяет пропустить любое поле, быстро перейти к карте и сохранить текущие изменения. Dating не включается заполнением формы. Ошибка оставляет ввод в памяти формы; повтор использует исходный operation ID. Изменение формы создаёт новый ID. После смены аккаунта редактор пересоздаётся; ответ дополнительно проверяется на текущую сессию. Навигация/закрытие страницы не сохраняет несохранённый профиль автоматически.

PostgreSQL profile row lock сериализует CAS. Receipt связан с owner+UUID+hash payload+expected revision. Повтор возвращает текущую запись и исходную appliedRevision, не создаёт новую редакцию и не откатывает свежие сведения. Конфликт требует явного обновления формы с подтверждением потери локального ввода.

`tests/profile-postgres.mjs` проверяет два устройства, запрещённые поля, retry collision, отдельные аккаунты, отказ client roles, actor spoof и каскадное удаление. Schema применена в prelaunch FitT. Production OTP/adult provider/legal publications остаются условиями живой приёмки; нельзя считать её пройденной по SQL fixtures.
