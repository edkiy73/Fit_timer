# A04/A05 — возрастная проверка и QA-доступ FetUre
**Статус:** QA prelaunch доступ реализован PR #799; новая доработка разрешает выдачу любому существующему Core аккаунту без лимита 12, с audit/lookup. Настоящая production верификация 18+ ещё не подключена.

## Решение о внешнем провайдере после MVP (11.10.2026)
**Основной кандидат: Yoti Age Verification.** Провайдер поддерживает server-created sessions, age estimation по селфи, скан удостоверения/Digital ID и получение серверного результата через API или подписанный webhook. Начальный способ: age estimation с консервативным порогом 21 для допуска 18+, в спорных случаях — документ или Digital ID с порогом 18. Ошибка оценки НЕ означает, что человек несовершеннолетний; пользователь получает альтернативную проверку. Селфи и документы обрабатывает провайдер, не FetUre.
**Резерв:** Persona Relay Age Assurance, если Yoti не подходит по цене/странам/правовым требованиям/UX. Veriff и Sumsub — другие сравниваемые варианты, не интегрировать параллельно без причины.
**Ссылки:** https://developers.yoti.com/age-verification/create-a-session ; https://developers.yoti.com/age-verification/results ; https://developers.yoti.com/age-verification/notifications ; https://developers.yoti.com/age-verification/age-estimation ; https://www.yoti.com/privacy/age-verification/ ; https://withpersona.com/product/relay
**До заключения договора проверить:** актуальные цены, поддержку целевых стран/Индонезии, обязанности по хранению/удалению и биометрии, применение законов целевых рынков и требований Apple/Google, false-accept около порога, доступность и SLA. Yoti — целевое техническое решение, НЕ заключённый договор и НЕ подтверждённая законная пригодность.

## Контракт будущей production-интеграции
1. Существующая Core session создаёт одноразовый серверный verification attempt, затем сервер — provider session. Пользователь получает только hosted URL, не API key или возможность указать success/age. Клиентский redirect не подтверждает возраст.
2. Подлинность результата проверить по серверному GET с API key или точной подписи webhook по документации Yoti. Применить результат к сохранённому account-bound attempt через verification-engine и verification-store; повтор, отзыв и истечение срока — атомарно.
3. В FetUre хранить только 18+ claim, issuer, policy version, issued/expiry/revoked, без биометрии, DOB, номера паспорта и файлов. Adult proof отдельно от identity verification; сильное identity подтверждение для знакомств и пар может потребовать дополнительной политики.
4. Пример базового срока proof — 90 дней, окончательно после проверки законодательства и договорных условий. Все неполные/неизвестные статусы fail-closed. Разобрать fraud, retries, апелляции, accessibility, Apple/Google browser redirects и нативный callback.
5. До официальной интеграции и проверки двух реальных аккаунтов production actor не подтверждает возраст, а A04/A05 остаются открытыми.

## QA prelaunch — строго ограниченный способ тестирования
Администратор вручную добавляет ТОЛЬКО лично проверенных взрослых тестировщиков по email существующего Core аккаунта. Backend хранит лишь его 32-символьный account hash, созданное/истекшее/отозванное разрешение. TTL 24–72 часа, без глобального лимита числа тестировщиков; каждое решение индивидуально с журналом действий администратора. Разрешение не является настоящей верификацией; UI сообщает это явно.
Защита: действительная Core device session, строго совпадающий account hash, каждый запрос заново проверяет DB разрешение, статус feture_seed.environment = prelaunch на конкретном проекте, действующие отдельные юридические согласия RU. Смена stage на live отключает ВСЕ разрешения немедленно без необходимости вручную удалять строки. Админская выдача и отзыв только через общий Core-admin endpoint с секретом, без самостоятельного user endpoint. Anon/authenticated не имеют доступа к таблице и RPC; Service role хранится только на сервере.
O02.1 добавляет личную Core сессию и роли manager/qa_operator/auditor для QA, а новые решения привязаны к account hash оператора. Общий ключ нужен только для первого назначения управляющего на сервере; текущая оболочка Core Admin ещё требует ключ для открытия. Остальные admin-домены пока используют общий ключ. Нельзя считать эти допуски полноценной проверкой личности; они непригодны для запуска реальных пользователей.

## Проверка готовности
PostgreSQL: grant/revoke/expiry, stage live выключает доступ, consent обязателен, client roles запрещены. CI, схема prelaunch и ACL должны пройти перед слиянием. UI на ПК/планшете/Android/iOS проверить отдельно; отсутствие настоящего provider proof не маскировать зелёной плашкой.
## Ручное подтверждение любому аккаунту — решение 2026-10-11

**Да, возможность ручного подтверждения в админке нужна для любого зарегистрированного человека**, а не только для 12 предварительно отобранных тестировщиков. Лимит числа разрешений удалён из QA, сохранились индивидуальный Core account, 1–3 дня TTL, отзыв, персональная server-side роль, prelaunch-only marker и обязательные документы. В админке появилась точная проверка email и счётчик действующих допусков; закрытый append-only журнал фиксирует grant/revoke с account hash текущего оператора; старые строки без привязки сохраняют метку `core-admin`.

**После MVP ручная верификация — не свободный toggle.** Нужен отдельный продакшн-процесс O02/A04 с индивидуальными ролями оператора, подтверждённым методом проверки (например, provider-hosted повтор/видеопроверка по утверждённой процедуре), минимальным основанием без документов в БД, сроком proof, отзывом и непрерывным аудитом. Никакая самодекларация или простое личное мнение администратора не должны превращаться в `verifiedAdult=true`. Ручной production override не реализован и не должен наследовать QA-строки. Прежде чем включать ручную процедуру — проверить правовую допустимость в целевых странах.

Обоснование: [Ofcom Age Assurance Guidance](https://www.ofcom.org.uk/online-safety/protecting-children/age-assurance) (обновлено 2026-09-02) перечисляет способы, способные быть высокоэффективными, и прямо исключает self-declaration. Это ориентир для оценки качества, а не универсальный правовой совет для всех стран.
