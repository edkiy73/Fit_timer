## Как экономить токены и не терять историю
1. При старте читать STATUS (~2–4 КБ) и одну целевую карточку (1–10 КБ); если нужен статус конкретного PR — GitHub diff/CI, не архив.
2. `STATUS.md` — **единственное текущее сводное состояние**. Обновлять конкретные строки, дату и handoff, а не приписывать дневник каждый раз.
3. Карточки — **целевой scope, зависимости, критерии**. Не складывать туда сотни ежедневных отчётов. Смена решения владельца: обнови нужную карточку и STATUS.
4. Подробный разбор или milestone писать в новом маленьком `history/YYYY-MM-DD-topic.md` либо туда, где уже ведётся журнал этой вехи; архив 10–11 октября и оригинал не править.
5. Никогда не отмечать всю карточку выполненной на основании одного CI. Статусы: `не начато`, `реализовано — ожидает проверки`, `проверено`, `внешний блокер`. Указывать PR/SHA и конкретные непроверенные gates.
6. Если присоединяется другой агент, передавать максимум: `ID, статус, последние PR/SHA, 2–5 файлов, проверки, blocker`. Не передавать 97 КБ истории.
