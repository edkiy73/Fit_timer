## 6. Проверка и критерий завершения

Обычный законченный кодовый срез:

```bash
npm --prefix apps/feture run typecheck
npm --prefix apps/feture run test:smoke
npm --prefix apps/feture run test:unit
npm --prefix apps/feture run build
# либо эквивалентная одна команда: npm --prefix apps/feture run check
```

`npm ci --prefix apps/feture` один раз для зафиксированного lockfile при необходимости. Общий Core менять только по реальной потребности, тогда дополнительно его check и существующие проверки потребителей. Не запускать весь legacy FitTimer suite для правки документа или локального FetUre UI. Документационный PR: diff/links/consistency, без APK и production build.

Минимальные автоматические проверки опасных контрактов: actor spoof/IDOR, whitelist projection, media revoke/expiry, account switching и conflict/delete replay, verification webhook, immutable test scoring, pair approvals, match idempotency, deletion isolation. Объединять смежные сценарии, не дублировать E2E и unit без причины.

Ручной конечный сценарий: гость → OTP → возраст → карта → тест → выбор обновления → дневник → устройство 2 → share/сравнение → grant частично → expiry/revoke → пост/комментарий/группа → report/block → пара/согласие → opt-in/свайп/матч/чат → отключение dating → экспорт/удаление. Повторить основные приватные границы третьим аккаунтом. Responsive при существенных layout изменениях, полный cross-platform проход перед выпуском.

MVP не завершён, если: есть mock успех вместо backend; auth/age доступны только sandbox; private payload отфильтрован лишь CSS; нет действующей модерации; пары не имеют двойного согласия; privacy платная; iOS считается проверенной по одному web build; искусственные люди попадают в выдачу реального запуска; часть обязательных карточек молча пропущена.

## 7. Внешние решения, не блокирующие независимую разработку

| Решение | Когда действительно необходимо | Поведение до него |
|---|---|---|
| Страны, юрлицо, age/identity провайдер, процедура ID/liveness | Перед включением чувствительных функций для внешних участников | Готовые контракты/ошибки/проверки, без production fake verification; не закрывать landing |
| Adult-media hosting/moderation vendor и договоры | Перед реальным хранением/выдачей такого UGC | Generic adapters, quarantine, редакционная работа; не утверждать пригодность по наличию API |
| Юридические тексты, согласия/retention/обращения | Перед внешним запуском | Админ-редактор и версионированные черновики готовы |
| Платежи | Только перед реальными продажами | Бесплатный MVP, скрытый неработающий paywall; Core billing не переписывать |
| App Store/Play канал | Перед submission | Полный общий продукт, отдельный документ policy review; нельзя обещать, что одного 18+ gate достаточно |
| Видео лимиты или явная отсрочка | Перед V01/финальным scope signoff | Фото pipeline готов, видео-контракт не выдаётся за готовую функцию |
| Переход к реальным пользователям | Перед O06 production launch | Открытая разработка, временные данные, без legacy |

Пары, базовый шаринг, история и дневник больше не «возможно когда-нибудь»: включены в этот план на основании исходной концепции. Сложные расширения ограничены §1. Новое решение владельца фиксировать здесь с причиной и изменением зависимостей, не оставлять два противоречащих плана.
