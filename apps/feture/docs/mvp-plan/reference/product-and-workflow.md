## 1. Результат и неприкосновенные требования

Строим полноценное 18+ пространство: **понять себя → вести личную карту и дневник → управлять раскрытием → общаться → при желании знакомиться**. Самостоятельная польза должна существовать без местной аудитории и партнёра. Знакомства выключены по умолчанию. Название в коде `feture`, продукт FetUre, репозиторий `edkiy73/Fit_timer`.

- Один React/TypeScript/Vite/AppBase продукт: полноценный сайт для ПК/планшета/телефона и Capacitor Android/iOS/iPadOS. Следовать Task Mini и UnMute, не создавать второе ядро.
- Все возможности разрабатываются для всех клиентов, включая разрешённый взрослый контент. Не вырезать домен ради сторов. Канальная политика — отдельная конфигурация сервера/сборки, без скрытого обхода review и обещаний одобрения.
- Сайт `https://feture-mvp.vercel.app` остаётся открытым по ссылке. Никакого общего пароля, SSO, allowlist или ожидания «открытия города». Доступность сайта не отменяет авторизацию приватных действий и возрастные проверки контента.
- До отдельного решения владельца о реальном запуске существующие FetUre данные временные. Разрешено пересоздавать только FetUre сущности; не сохранять старые форматы, не добавлять legacy/dual-write. Это не разрешение сбрасывать общие аккаунты AppBase, FitTimer или UnMute.
- В пользовательском UI нет технических плашек «демо», «тестовые данные», «в разработке». Наполнение реалистично, хранится в БД, происхождение видно в админке. Нельзя имитировать успешный запрос, оплату, отправку или сохранение.
- Плавные анимации, понятные подсказки терминов, полноценная адаптивность и доступность — часть каждой функции.
- Несколько небольших связанных пунктов можно выполнять за заход. **Перед задачей, для которой качественный результат требует усилия модели выше среднего, остановиться**, назвать следующую карточку, причину сложности и рекомендуемый уровень; продолжить после переключения/указания владельца.
- Короткие/средние задачи, без многочасовой автономной переделки. Ориентир одного рабочего захода ~5–10 минут; большая карточка ниже делится на контракт/API, UI и проверку. Это размер захода, **не обещание закончить целый домен за десять минут**.
- Не собирать APK/IPA и не запускать отдельный Vercel deploy на каждый мелкий шаг. Итоговая сборка — в конце вехи; магазины/публичный запуск по отдельному решению владельца.

### Объём, который нельзя молча сократить

| Входит в MVP | Граница первой реализации |
|---|---|
| Аккаунт и приватность | Email OTP Core, серверные права, восстановление, экспорт/удаление, возрастной провайдер |
| Мой мир | Профиль, фото/альбомы, карта, история, приватный дневник, вид «как видит другой» |
| Исследовать | Редактура 12/144, определения/синонимы, поиск, 4–6 настоящих тестов, сохранение/продолжение/повтор |
| Распространение пользы | Выбранная share-карточка, приглашение, сравнение только раскрытых ответов |
| Сообщество | Разные посты, комментарии, реакции, подписки, группы, поиск, сохранённое, уведомления |
| Доверие | Запрос/частичное разрешение/срок/отзыв, модерация, блокировки, жалобы, апелляции |
| Пара | Два личных аккаунта + общий профиль и согласия. Приватное не становится общим |
| Знакомства | Opt-in, взаимные фильтры, объяснимый подбор, исходная карточка со скроллом, like/pass/undo, матчи |
| Общение | Разрешённый 1:1 диалог; разговор пары с приглашённым в минимальном составе, если используется парный dating |
| Админка | Каталог/тесты/группы/жалобы/документы/seed/конфигурация и аудит |
| Платформы | Телефоны, ПК, планшеты, fold/flip, общая функциональность, native проверка в финале |

После MVP: ML-ранжирование, произвольные поли-графы и групповые чаты, live/video-трансляции, события с билетами/картой, подарки, AI-терапевт, PDF-отчёты, сложные платные уровни. Короткое загружаемое видео выделено отдельной карточкой V01: исходники предусматривают его; не объявлять полную медиачасть готовой без него либо явного решения владельца об отсрочке. Подписка не блокирует бесплатный MVP: безопасность, отзыв, блокировка, экспорт и удаление всегда бесплатны.

Прочесть корневой AGENTS, `apps/feture/AGENTS.md`, README и аудит. Затем текущий HEAD и только файлы текущей карточки. Состояние production backend необходимо проверить, не делать вывод по одному README.

### Правила работы SOL

1. Обновить main, прочитать статус задач. Выбрать первую незавершённую карточку с выполненными зависимостями.
2. Указать ID, точный результат захода, 2–5 основных файлов. Существующие пути ниже проверены; новые пути помечены «создать» и являются предложенной организацией.
3. Реализовать вертикальный сценарий. Не создавать все таблицы, очереди и UI заранее. Общая абстракция — только если уже нужна двум реальным потребителям.
4. Если внешние ключи/решение владельца недоступны: закончить адаптер, серверный отказ и локальные проверки; записать конкретный blocker; перейти к независимой задаче. Не включать success-заглушку в публичный backend.
5. Существующие быстрые проверки обязательны. Новые тесты только для auth/ACL, утечек, конфликтов, удаления, согласий, платежей и существенной стабильной логики; не добавлять snapshot на каждый чип.
6. Обновить карточку `[x]` лишь с доказательством результата; частичный результат `[ ]` + запись. Обновить README при изменении фактической готовности.
7. Перед push/merge снова сравнить main, примирить чужие изменения, не force-push. Одно логичное изменение/PR, документационные коммиты `[skip vercel]`. Проверить собственную ignored-build политику FetUre в F01.
8. Handoff внизу этого файла: ID, commit/PR, сделано, команды и итог, ручная проверка, ограничения, следующая карточка. Не писать «готово» по одному build.
