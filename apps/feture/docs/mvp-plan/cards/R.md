### R — пары и совместимость

- [ ] **R01. Подтверждённая связь двух аккаунтов.** После P01/P03/A06. Invitation одноразовое/с expiry, accept/decline/cancel/unlink, joint profile draft, два независимых владельца. Готово: никто не может привязать чужой account по email или читать его дневник; повтор invite/accept безопасен; unlink прекращает совместную выдачу.
- [ ] **R02. Общий слой и двойное согласие.** После R01/P02. Отдельные общие цели/границы/фото/аудитории. Для чувствительных материалов оба подтверждают точную версию; изменение сбрасывает approvals; любой отзывает. Обычное раскрытие одним допустимо только при заранее принятой обоими политике, default оба. Готово: race approve/revoke не публикует без действующего согласия; личные желания не усредняются и не импортируются тайно.
- [ ] **R03. Объяснимая совместимость.** После W02/P01/R02. Детерминированные правила без ML/LLM: eligibility → обязательные предпочтения → доступные совпадения/комплементарность ролей/темы для обсуждения. Отдельный private opt-in на использование данных для подбора; причины только из доступной обоим проекции. При малом пересечении «недостаточно данных», не случайные 87%. Hard boundary исключает конкретный конфликтующий сценарий, не объявляет человека плохим. При «обязательном» конфликте не рекомендовать пару, не называть скрытую причину. Готово: один/оба unknown, hard vs want, fantasy vs real, разные роли и pair cases покрыты короткими табличными тестами. Поиск/score/повторные запросы не дают oracle для скрытых признаков.
