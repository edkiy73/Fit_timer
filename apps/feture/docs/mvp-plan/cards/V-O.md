### V/O — медиа, эксплуатация, выпуск

- [ ] **V01. Короткие видео.** После P02/P03. Предлагаемый MVP лимит 60 сек/50 MB, подтвердить бюджет; upload → quarantine → async transcode → poster+stream, MIME/duration/limits/ACL сегментов/удаление. Без autoplay со звуком и без прямых эфиров. Готово: provider failure/retry не публикует оригинал, revoke закрывает новые запросы; те же consent/модерация, что у фото. До готовности не выводить нерабочую загрузку видео. Отсрочка требует записи решения владельца, а не молчаливого исключения.
- [ ] **O01. Экспорт и удаление FetUre.** После A03/P02/W06/C03/R02/D04. Сначала немедленно отозвать sessions/grants/visibility внутри FetUre, затем идемпотентная job удаления/анонимизации по политике: map/tests/journal/media/posts/comments/chat memberships/notifications/search/seed refs/provider references. Экспорт только своих данных, не чужих приватных сообщений/полей по grant. Общий аккаунт AppBase/другие продукты не удалять кнопкой «удалить FetUre». Готово: два аккаунта, два продукта, повтор job и попытка старой очереди проверены; shared content/retention и backup expiry честно описаны.
- [ ] **O02. Admin operation и редакционная готовность.** После всех включённых доменов. Роли, поиск кейсов, история действий, каталог/тесты/группы/документы/seed/config, audit без личных текстов. Наблюдение за moderation queue age, retries, storage/egress; ответственный человек и контакт обращения. Готово: администратор может реально снять публикацию, ограничить участника и рассмотреть апелляцию; нет безграничной кнопки читать private всё.
  - **GPT-6 High, отдельная проверка:** Ожидает: GPT-6 High; после продуктовых доменов, аудит admin permissions.
- [ ] **O03. Метрики и расходы.** После W07/C04/D05. В AppBase analytics только allowlist событий: test started/completed, map updated(count), share created/redeemed, return, discussion, match/conversation started. Не отправлять значения интересов, диагнозы, body, ID приватных тем, геопозицию, URL токены или session replay. Разделять seed/internal и реальные cohorts сервером. Измерить activation, D1/D7 без dating, share→completion, долю релевантной непустой выдачи, time-to-first-reply, complaint resolution; targets после baseline. Готово: проверен payload, лимиты storage/egress/provider budget и оповещения; нет выдуманных KPI.
  - **GPT-6 High, отдельная проверка:** Ожидает: GPT-6 High; аудит отсутствия чувствительных значений в событиях.
- [ ] **O04. Стабильность и восстановление.** После O01/O02. Бэкап и проверка восстановления в изолированном окружении, scoped rollback, deletion ledger против восстановления удалённого, quotas/timeouts/retries, private-cache audit, orphan cleanup. Готово: восстановление доказано, не только включён checkbox; сбой внешнего провайдера не теряет draft/сообщения, не затрагивает общую FitT БД.
- [ ] **O05. Платформенная приёмка.** После функций MVP/F03. `capacitor.config.json`, `scripts/mobile.mjs`, native adapters. Поддержку hinge определить feature detection, без зависимости от одного API. Готово: матрица реально проверенных устройств/эмуляторов/браузеров; отсутствие macOS или девайса отмечено, не выдаётся за успешный тест.
  - **GPT-6 High, отдельная проверка:** Ожидает: GPT-6 High; ручная device/browser проверка, не заменять симуляцией.
