# A01 — подключение существующих сервисов

## Выбранный контракт

FetUre использует существующий AppBase Auth (`api/auth.js`), а не Supabase Auth.
Core account/KV хранится через готовый Supabase adapter в общем FitT.
Доменная карта переключается на PostgreSQL отдельно в A02/A03.
Не копировать Redis другого продукта: это не подтверждает общую идентичность и может связать OTP/сессии двух разных окружений.

В Vercel **feture-mvp**, для production, нужны:

| Переменная | Значение / источник |
|---|---|
| `APPBASE_STORE` | `supabase` |
| `SUPABASE_URL` | URL существующего FitT `anrhayozrhrmiwexmbhw`; уже настроен |
| `SUPABASE_SECRET_KEY` | Серверный secret существующего FitT; Secret, без `VITE_` |
| `RESEND_API_KEY` | Ключ отправки Resend; Secret, без `VITE_` |
| `MAIL_FROM` | Для разработки: `FetUre <onboarding@resend.dev>`. Для запуска: адрес на своём подтверждённом домене |

`SUPABASE_PUBLISHABLE_KEY` остаётся только для каталога. Не включать
`ALLOW_MEMORY_STORE`, не публиковать секреты в git/клиенте. Preview не получает
production credentials автоматически. Не менять конфигурацию FitTimer/UnMute.

## Проверка до deployment

`npm run check:auth-env` читает только окружение текущего процесса и выводит
булевы проверки без значений. Exit 1 означает неполную/неверную конфигурацию.
Команда не загружает `.env` автоматически; в локальном Node с приватным
файлом используйте `node --env-file=.env.local tools/check-auth-env.mjs`.
Успех означает только полноту конфигурации, не доставку письма или рабочий вход.

До выбора домена разрешён `npm run check:auth-env -- --development-mail`.
Он допускает отправителя `FetUre <onboarding@resend.dev>` и явно показывает
`mailMode=resend-owner-only`, `launchMailReady=false`. Письма доступны только
владельцу аккаунта Resend; получатель — его адрес, отправитель — адрес Resend.
Без флага проверка сохраняет запрет тестового домена для запуска.
Проверка своего домена всё равно требует Resend и реальной доставки.

После настройки выполнить один deployment актуального main. Проверить
`/api/health`: store connected, Supabase configured, mail ready; каталог
остаётся доступен гостю, `/api/domain` остаётся закрыт гостю.

## Обязательная приёмка A01

1. Отправить код только на явно указанные владельцем контролируемые ящики.
   Проверить реальную доставку, неверный код, повторную отправку, срок 15 минут
   и невозможность повторно использовать успешный код.
2. Два аккаунта и два устройства: сервер различает владельцев, подстановка
   чужого actor не открывает чужой профиль.
3. Подтвердить восстановление, истечение и серверный отзыв токена при выходе;
   Core logout теперь отзывает токен на сервере; абсолютный срок — 90 дней
   с момента выдачи. Локальные проверки пройдены; живая проверка ещё не выполнена.
4. A01 отмечать `[x]` только после всех проверок. Общая конфигурация сама по
   себе не подтверждает облачное сохранение карты (A02/A03).

## Серверные сессии — срез A01 (2026-10-10)

Core выдаёт `expiresAt` после OTP. Проверка срока и отдельного token-hash
отзыва действует в auth/sync/AI/billing, доменном API FetUre и существующих
account-token API FitTimer/UnMute. Это та же Core identity; новая система
аккаунтов не вводилась. Срок абсолютный — 90 дней, запросы его не продлевают;
после истечения нужен новый OTP. Существующие общие записи используют
серверный `at`; запись без корректного времени выдачи отклоняется.

`logout` отзывает только текущий токен, другие устройства продолжают работать.
Отдельная запись отзыва переживает параллельную запись старого account snapshot.
Push отправляется только устройствам с действующей сессией. Core client
сохраняет локальный вход при сетевой/серверной ошибке выхода и не позволяет
позднему ответу восстановить отозванную сессию или стереть новый вход.

FetUre показывает ошибку выхода с возможностью повторить. Общие React-клиенты
используют новый Core logout; прежний продуктовый `signOut` FitTimer пока
остаётся локальным (отдельная продуктовая интеграция, не предмет A01 FetUre).
Сервер FitTimer уже отклоняет отозванные/истёкшие Core токены.

Проверки — локальные обработчики с памятью вместо production store; реальные
письма, аккаунты, окружение и БД не изменялись. Серверные обработчики остались
CommonJS: deployment загружает их без TypeScript server build. Проверяемый
контракт session helpers добавлен в `packages/core/server/util.d.ts`;
полная конверсия серверной сборки не входит в этот срез.
