# Безопасность: от чего защищаемся

Проверено по коду 29.10.2026. Ключи, 2FA и план при утечке — [security-keys.md](security-keys.md); здесь — сценарии.
Усилие: **S** — до дня работы агента, **M** — 2–5 дней, **L** — больше недели. Срок: **①** до первых реальных
пользователей, **②** до публичного запуска, **③** потом.

## 1. Рекомендация (главное)

1. **Закрыть «вход за любого» из админки.** Админка умеет выдать код входа для любого аккаунта («Пользователи» →
   «Код для входа»). Кто знает админ-ключ, тот войдёт как любой пользователь и прочитает его чаты. Ключ сейчас слабый и
   общий (значение здесь не пишем). Мера: сменить ключ и выключить выдачу кодов, когда среда станет `live`.
2. ~~Второй фактор для сотрудников~~ — **сделано 29.10.2026**: обязательный TOTP для любой роли (ниже, «Сотрудники»).
   Passkey — позже.
3. ~~Уведомление о входе с нового устройства~~ — **сделано 29.10.2026** (ниже, «Вход с нового устройства»); экран «Мои
   устройства» для всех — тоже. **Необязательный код из приложения для всех** — **сделан 29.10.2026**.
4. **Медиа только по коротким подписанным ссылкам.** Это уже так; держать и не ослаблять.

## 2. Что уже есть в коде

| Защита | Где | Значение |
|---|---|---|
| Код входа | `packages/core/server/auth-core.js` | Живёт 15 мин, 5 попыток на код |
| Лимит отправки кодов | там же | 10 в час на почту, 30 в час с одного IP |
| Лимит проверки кода | там же | 20 за 15 мин на почту, 120 с IP |
| Сессия | `packages/core/server/util.js` | Абсолютный срок 90 дней, выход отзывает на сервере |
| «Мои устройства» | Core `sessions`, `session_revoke`, `sessions_revoke_others` + `account.devices` (`server/devices.mjs`) | «Я → Настройки → Вход и безопасность»: устройство, город и страна по данным Vercel (без IP), когда было активно, «Выйти» и «Выйти на всех остальных» |
| Второй фактор персонала | `server/second-factor.mjs`, `server/commands/staff.mjs` (`requireStaff`), миграция `20261029140000_fe_second_factor.sql` | TOTP (RFC 6238, SHA1, 6 цифр, 30 с, ±1 шаг) обязателен для любой роли; секрет зашифрован AES-256-GCM ключом из `FETURE_ID_PEPPER`; 10 одноразовых кодов восстановления — только хэши; код работает один раз; 5 неверных за 15 мин — блок на 15 мин; вход персонала живёт 12 ч в этой сессии; свежий код (10 мин) для выдачи и снятия ролей, бана, документов и селфи, сброса чужого 2FA; сброс — `owner`/`lead`, в журнале; снятие роли сразу закрывает вход персонала |
| Код из приложения для всех | `server/signin.mjs`, `server/core-guard.mjs`, `account.factor*` (`server/commands/account.mjs`), миграция `20261029180000_fe_user_second_factor.sql` | Включается в «Вход и безопасность» (QR, ключ, первый код, 10 кодов восстановления один раз); те же таблицы и правила, что у персонала. Пока включён, новый вход по коду из письма ничего не может, кроме ввода кода и выхода: проверка на сервере перед каждой командой `/api/fe` и перед действиями Core с сессией (список устройств, выход на других, смена почты, удаление, ник), синхронизацией, старым `/api/domain` и кабинетом операторов (403 `second_factor` `signin`). Включение спрашивает код на всех остальных устройствах; выключение и новые коды — только по текущему коду; потерян телефон — код восстановления или сброс `owner`/`lead`; персоналу выключить нельзя |
| Вход с нового устройства | `server/signin.mjs` | Каждый вход записывается один раз (`account_signin`). Новый — если аккаунт уже входил раньше, Core открыл вход меньше суток назад и за 90 дней не было входа с того же устройства или того же семейства («Chrome · Mac») из той же страны. Тогда: пункт во входящих (не отключается), пуш (в «Безопасных» только «FetUre · Вход с нового устройства») и простое письмо без трекинга (адрес не хранится, `.test` не получают). Не больше 5 в час. Срабатывает и для входа, который ещё не ввёл код |
| Лимиты API | `api/fe.mjs`, `server/README.md` | 600 запросов в мин на аккаунт, 1200 с IP, отдельные дневные лимиты на жалобы, лайки, заявки |
| Журнал действий персонала | `feture.staff_action` (`server/commands/staff.mjs`) | Пишутся выдача ролей, решения, **каждый просмотр медиа** |
| Ссылки на медиа | `server/media/assets.mjs` | 10 мин обычные, 60 с для одноразовых фото, максимум 1 час |
| Согласие партнёра | `server/approvals.mjs` | Приватную часть пары открывают только вдвоём |
| Документы и селфи | `server/commands/premium.mjs` | Документ удаляется сразу после решения, селфи — через 30 дней |
