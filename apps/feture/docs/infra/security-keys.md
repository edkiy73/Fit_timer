# Ключи, пароли и что делать при утечке

Проверено 29.10.2026. Секреты не выводились и не читались; ниже только имена переменных.

## 1. Рекомендация

1. **Сменить админ-ключ сейчас.** `ADMIN_KEY` в Vercel слабый и уже был в чате. Новый — длинная случайная строка,
   которую агент **никогда не видит**.
2. **Личные роли вместо общего ключа** (`owner`, `lead`, `moderator`, `verifier`, `support`, `auditor`, с журналом).
   Ключ нужен только для первого назначения управляющего и старых разделов админки.
3. **2FA (вход с кодом из приложения) на всех аккаунтах.** Лучше приложение-аутентификатор или ключ-флешка, а не SMS.
4. **Ключ подписи Android — две копии в разных местах.**
5. **Все секреты только в Vercel** (Environment Variables, тип Sensitive) и в GitHub Secrets. Никогда в чате, в
   коде, в письмах. **Репозиторий публичный** — любой файл в нём видят все.

**Стоимость:** 0. Менеджер паролей — Bitwarden (бесплатно) или «Связка ключей». Сценарии атак — [security.md](security.md).

## 3. Что делает владелец

### Сменить админ-ключ (10 минут)
1. Терминал не нужен. Открыть bitwarden.com/password-generator (или генератор в менеджере паролей):
   длина 48, буквы и цифры. Скопировать.
2. Сохранить в менеджер паролей с названием «FetUre admin key».
3. Vercel → проект `feture-mvp` → Settings → Environment Variables → `ADMIN_KEY` → Edit → вставить → Save.
4. Vercel → Deployments → последний → Redeploy.
5. Написать агенту «ключ сменил». Агент проверит, что старый ключ больше не работает. Новый ключ в чат **не
   отправлять**.

### 2FA — пройти по списку
GitHub, Vercel, Supabase, Google (аккаунт Firebase и Play), Apple ID, Porkbun, Resend, Bunny, почта владельца,
Robokassa/NOWPayments. Резервные коды сохранить в менеджер паролей.

### Ключ подписи Android
- Файл `FetUre-release.jks` и пароль: одна копия в iCloud Drive или в менеджере паролей (как вложение), вторая — на
  флешке дома. Проверить, что обе открываются.
- В GitHub он уже хранится как секреты `FETURE_KEYSTORE_BASE64`, `FETURE_KEYSTORE_PASSWORD`, `FETURE_KEY_ALIAS`,
  `FETURE_KEY_PASSWORD`, но оттуда его **не скачать**. Потеря обеих копий = установленный FetUre больше никогда не
  обновится, а пакет, зарегистрированный в Google (см. [app-stores.md](app-stores.md)), останется за старым ключом.

Модераторам — только роль, никогда не админ-ключ и не доступ к Vercel/Supabase. Ушёл человек — снять роль в тот же день.

## 4. Что делает агент

- После смены ключа проверяет, что `/api/admin` не принимает старый.
- Переводит оставшиеся разделы админки на личные роли, чтобы общий ключ стал нужен только в аварийной ситуации.
- Генерирует новые секреты скриптом, который владелец запускает сам. Значения в чат не попадают.
- Раз в квартал проверяет: кто имеет роли, у кого доступ к Vercel, Supabase и GitHub, нет ли секретов в коде.

## 5. Какие секреты есть (имена)

| Переменная | Что открывает | Как часто менять |
|---|---|---|
| `ADMIN_KEY` | Общая админка | Сейчас, потом при уходе любого, кто его знал |
| `SUPABASE_SECRET_KEY` | Полный доступ к базе Supabase | При подозрении на утечку |
| `FETURE_DATABASE_URL` | Вход ограниченной роли `feture_api` | При подозрении |
| `FETURE_ID_PEPPER` | Скрытые идентификаторы | **Не менять** без миграции: сломает ссылки и хэши |
| `FETURE_JOBS_SECRET` | Запуск фоновых задач (также в Vault Supabase) | При подозрении, вместе с Vault |
| `FETURE_MEDIA_TOKEN_SECRET`, `R2_*`, `RESEND_API_KEY`, `FIREBASE_SERVICE_ACCOUNT_*`, `FE_VAPID_*` | Медиа, письма и push от нашего имени | При подозрении |
| `FETURE_KEYSTORE_*` (GitHub) | Подпись приложения | Никогда (смена = новое приложение) |

## 6. Если что-то утекло

1. **Сразу (первый час):** сменить утёкший ключ в его сервисе, вставить новый в Vercel, сделать Redeploy.
   Утёк `SUPABASE_SECRET_KEY` → Supabase → Settings → API Keys → отозвать и создать новый.
2. Написать агенту: что утекло и когда. Агент проверит журналы Vercel и Supabase на чужие запросы.
3. **Если утекли данные пользователей:** сообщить надзорному органу ЕС **в течение 72 часов** (GDPR ст. 33) через
   представителя в ЕС. Если есть юрлицо или ИП в РФ — уведомить РКН в течение 24 часов (проверить у юриста). Затем
   предупредить пользователей.

## 7. Риски

Самый вероятный путь утечки — захват почты или GitHub владельца, поэтому 2FA важнее всего. Секрет, вставленный в
чат с ИИ, считается утёкшим.
