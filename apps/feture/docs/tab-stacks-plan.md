# План: у каждой вкладки свой стек (как в Instagram и Telegram)

Статус: план, код не менялся. Решение владельца 30.10.2026: делаем «как Instagram / Telegram».

## Что должно быть (поведение)

1. Каждая из пяти вкладок дока (Лента, Люди, Комьюнити, Чаты, Я) помнит свой путь: корень → экраны, открытые внутри неё.
2. Тап по вкладке показывает то, где ты в ней остановился. Пример: лента → профиль Весты → «Чаты» → тап «Лента» → снова профиль Весты, с тем же скроллом.
3. Тап по уже открытой вкладке: сначала прокрутка наверх (уже сделано), второй тап сразу после — возврат на корень вкладки.
4. «Назад» (кнопка в шапке, жест, кнопка Android) идёт по стеку текущей вкладки. Когда в стеке остался корень: «назад» с корня любой вкладки ведёт на Ленту, с корня Ленты спрашивает «Закрыть FetUre?».
5. Листы и просмотрщики (`useBackClose`) остаются поверх стека и закрываются «назад» первыми, как сейчас.
6. Выход из аккаунта и смена профиля (я/пара) сбрасывают все стеки.

## Как сейчас (проверено по коду 30.10)

- Роутер: `createHashRouter` (`src/main.tsx`), один общий стек истории на всё приложение.
- Док (`src/fe/shell.tsx`, `go()`): тап по вкладке делает `navigate('/n/<вкладка>')`, то есть открывает корень вкладки новой записью. Повторный тап по открытой вкладке только прокручивает вверх.
- Подсветка вкладки считается по адресу (`current` в shell.tsx): профиль человека относится к «Люди», пока не открыт из «Я».
- Кнопка «Назад» в шапке профиля: `navigate(-1)`, если в истории есть что-то раньше, иначе на «Люди» (`ProfilePage`).
- Листы и просмотрщики добавляют в историю свою запись (`useBackClose`, `src/fe/kit/index.tsx`).
- Кнопка Android «назад»: `src/feture/native-navigation.tsx` (проверить, что именно он подключён для `/n`).

## Подход

Не делать пять роутеров. Оставить один `createHashRouter` и вести рядом **карту «вкладка → стек адресов»** (`tab-stacks.ts`, модуль с `Map`, живёт, пока открыто приложение):

- На каждый `location` (кроме оверлейных записей `feOverlay`) определяем вкладку (та же функция, что `current` в shell.tsx) и обновляем её стек: новый адрес поверх; «назад» внутри вкладки снимает верхний.
- `go(id)` в доке: если вкладка уже открыта, прокрутка/корень по правилу 3; иначе `navigate(<верх стека вкладки>)`, а не корень.
- Скролл каждого экрана запоминаем по ключу адреса (`scrollTop` его `.view`) и возвращаем при возврате.
- «Назад» внутри вкладки: если в её стеке есть предыдущий адрес, идём на него (`navigate(prev, {replace})`), иначе правило 4. Историю браузера не надеемся использовать: она общая.

Альтернатива (отброшена): настоящие `MemoryRouter` на вкладку с живыми экранами. Это даёт сохранение состояния «бесплатно», но ломает ссылки, уведомления и `useBackClose`, а переписывать пришлось бы весь роутинг.

## Шаги

1. `src/fe/tab-stacks.ts`: `tabOf(pathname)`, стеки, `push`, `pop`, `top`, `reset`, `remember(scroll)`. Чистый модуль, юнит-тесты без браузера.
2. Подключить к `shell.tsx`: слушаем `useLocation`, `go()` по новым правилам. Сброс при выходе и смене профиля (`useFe`).
3. Заменить «назад» в шапках (`ProfilePage`, `PersonBar`, `SubBar`, `CoverBar`, экраны публикации и галереи) на общий `useTabBack()`.
4. Кнопка Android «назад»: тот же `tabBack()` (проверить, какой компонент реально стоит под `/n`, и убрать дублирование).
5. Возврат скролла: ключ адреса → `scrollTop`, восстанавливать после отрисовки данных.
6. Глубокие ссылки, пуши и «Открыть» из уведомления: адрес открывается внутри нужной вкладки; стек этой вкладки становится «корень → адрес» (без чужой истории).
7. Тесты и ручная проверка (см. ниже).

## Крайние случаи

- Адрес вне `/n/<вкладка>` (приветствие, регистрация, модераторский кабинет `/n/staff`): в стеки не попадают.
- Один и тот же экран открыт из двух вкладок (профиль из «Ленты» и из «Чатов»): стеки независимы, дублирование нормально.
- Удалённый или заблокированный объект в стеке: при возврате показываем экран «недоступно» и «назад» снимает его.
- Экраны с неотправленным черновиком (публикация, чат): при смене вкладки черновик остаётся; уход с созданной публикации по-прежнему спрашивает «Сохранить черновик?».
- Предыдущая запись в истории при холодном старте: `window.history.state.idx` может быть 0 при глубокой ссылке; «назад» ведёт на корень вкладки, а не закрывает приложение.
- Док скрыт (клавиатура, режим выбора): правила не меняются.

## Проверка

- Юнит-тесты `tab-stacks`: переходы, возврат, сброс, повторный тап.
- Сценарии на телефоне: лента → профиль → чаты → лента (профиль на месте); профиль → назад (лента); два тапа по вкладке (прокрутка, потом корень); «назад» с корня каждой вкладки; смена профиля сбрасывает стеки; глубокая ссылка из пуша.
- Не проверять в одном браузере: жест «назад» Android и холодный старт; это только на реальном телефоне.
