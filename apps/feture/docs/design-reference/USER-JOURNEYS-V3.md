# FetUre — карта пользовательских путей и план пересборки V3

Решение владельца 13.10.2026. **Сначала проектировать полный путь, затем реализовывать связанные экраны одним функциональным блоком.** Этот документ определяет UX-очередь и дополняет PRODUCT-UX-V3.md; заменяет прежнюю очередь косметической полировки. Серверные требования остаются в доменных MVP-карточках. План не является заявлением о готовности функций.

## 1. Результат для пользователя

FetUre помогает разобраться в себе, собрать личную карту, выбрать, чем поделиться, и найти общение. Знакомства включаются отдельно. Пользователь без партнёра и без знакомств получает полноценный продукт. Каждый экран отвечает на три вопроса: где я, что здесь полезного, что могу сделать дальше. Отдельная постоянная «Главная» не нужна.

Основа: одобренный Claude HTML — типографика, тёплые поверхности, розовый/лиловый акцент, мягкий свет, стекло, плавные реакции. Его навигация, проценты совместимости, платежи и иллюстративные участники не являются готовыми продуктовыми контрактами. Наши сценарии и права определяют структуру.

## 2. Состояния пользователя и точки входа

| Состояние | Что видит / куда попадает | Следующее действие |
|---|---|---|
| Первый гость на `/` | Короткое приветствие: польза, три направления, «Начать», вторичный «Войти» | Начать → короткий первый путь; Войти → email/код |
| Гость с прямой ссылкой на тему | Нейтральная публичная часть темы, если разрешена | Читать; личное действие вызывает соответствующий gate |
| Гость с приглашением | Разрешённый минимум приглашения без чужих закрытых данных | Войти → вернуться к тому же приглашению → проверить актуальные права |
| Первый вход | Аккаунт создан/восстановлен; минимальный профиль и необязательный первый путь | Выбрать цель / пропустить → Мой мир; вход не включает знакомства |
| Повторный вход | Мой мир; для разрешённого приглашения — исходное приглашение | Продолжить последнее содержательное действие |
| Вход с локальными отметками | Короткий вопрос о переносе после нужных допусков | Подтвердить перенос / оставить отдельно; без молчаливого слияния |
| Вход без допуска 18+ | Обычная оболочка и разрешённый контент, без огромного предупреждения на каждом экране | Ограниченное действие → контекстное окно проверки |
| Сессия истекла в процессе | Сохранённый черновик и окно повторного входа | Войти → перепроверить права → продолжить; не заявлять сохранение до ответа |
| Возврат с другого устройства | Серверные подтверждённые данные; локальные данные другого устройства не обещать | Продолжить работу; при конфликте сравнить версии |

Первый путь: приветствие → «Для чего ты здесь?» (познание себя / темы / общение) → необязательный выбор нескольких направлений → выбранная тема или вопросы → первая отметка/результат → Мой мир. Не заставлять сначала заполнять большую анкету, выбирать партнёра или покупать Premium. «Пропустить» всегда ведёт в полезный раздел. Повторный вход не повторяет обучение. Редактирование профиля доступно позже.

Предпочтения и завершение первого пути привязать к аккаунту; гостевое состояние хранить отдельно. Нужны честные состояния создания профиля: создаём / создан / ошибка с повтором. Успешный OTP сам по себе не означает успешной записи профиля.

## 3. Информационная архитектура

| Раздел | Главная потребность | Содержимое первого экрана | Что не размещать здесь |
|---|---|---|---|
| Мой мир `/world` | «Что я уже понял о себе и куда двигаться?» | Личная карта; продолжение начатого; контекстная рекомендация следующего шага | Полный каталог, длинные системные инструкции, дубли настроек |
| Темы `/explore` | «Что это значит и хочу ли я узнать больше?» | Поиск; содержательные направления; редакторская подборка | Копию личной карты, матрицу одинаковых баночек |
| Общение `/community` | «Что обсуждают, где участвовать?» | Лента / Группы / События; один выбранный подраздел | Отдельную вкладку событий в общем доке, все формы создания одновременно |
| Я `/account` | «Как выгляжу, что раскрываю, как управляю аккаунтом?» | Краткий профиль; редактирование; доступ/безопасность; настройки | Длинную анкету и открытые формы удаления/покупки на стартовом экране |
| Знакомства `/dating` | «С кем хочется познакомиться?» | Полноэкранная подборка, фильтры, симпатии | Повторный большой hero, внешнюю прокрутку вокруг маленькой карточки |

Четыре базовые вкладки; пятая — после добровольного включения знакомств. Первые четыре сохраняют порядок. Внутренние страницы подсвечивают родительский раздел: тесты/дневник → Мой мир, каталог → Темы, пост/группа/событие/диалог → Общение, профиль/доступ/проверка → Я. На desktop — та же логика в боковой навигации. Редактор полного экрана может временно скрывать док, но обязан иметь понятный возврат и защиту черновика.

Включение знакомств доступно в Я и как вторичное действие в Мой мир. Общение остаётся полезным без знакомств. Симпатии находятся внутри знакомств; сообщения — в Общении, с переходом из взаимной симпатии. Существующие маршруты не переименовывать ради подписей; новые глубокие ссылки вводить отдельной согласованной реализацией.

## 4. Единый механизм доступа: действие → объяснение → продолжение

**Не раскладывать постоянные тексты «подтвердите 18+», «войдите», «купите» между карточками.** Требование появляется после осмысленного действия. Однако ограниченный контент не загружается и не показывается до серверного разрешения. Разрешённый нейтральный preview и закрытое содержимое — разные вещи.

| Причина ограничения | Окно в момент действия | Успех / отказ |
|---|---|---|
| Нет аккаунта | «Войди, чтобы [конкретная польза]» → email → код | Вернуться к безопасно сохранённому намерению; отмена возвращает к исходному месту |
| Нужен допуск 18+ | «Этот раздел доступен совершеннолетним» + почему и следующий реальный шаг | Сервер перепроверяет статус; самодекларация не выдаёт допуск |
| Нет актуального согласия | Краткое объяснение + точная версия нужного документа, просмотр полного текста | Явное согласие; отказ сохраняет доступ к остальным разрешённым функциям |
| Нужен Premium | Польза именно этой функции, проверенные условия и доступная покупка | Entitlement подтверждается сервером; без фиктивного «Premium включён» |
| Закрытая информация человека | «Запросить доступ» с точным перечнем полей | Запрос → ожидание → разрешено/отказано/отозвано; оплата не заменяет согласие |
| Нет прав на группу/событие | Условия участия и реальное состояние заявки | Заявка/решение без обещания адреса, билета или допуска |
| Сессия/допуск отозваны | Контекстный отказ с возможным повторным входом/проверкой | Немедленно убрать запрещённые данные, сохранив только допустимый собственный черновик |

Последовательность проверок: аккаунт → требуемый возраст/согласия → права на ресурс → entitlement, только если функция платная. Не показывать четыре окна одновременно. После каждого шага перепроверить ресурс; разрешение могло измениться. Не выполнять публикацию, оплату, like или отправку сообщения автоматически после логина: вернуть подготовленную форму и дождаться явного действия. Чтение можно продолжить после проверки.

Контекстный gate — adaptive sheet на телефоне, диалог на desktop. Закрывается Back/Escape/явной кнопкой, фокус возвращается к вызвавшему действию. При недоступном age-провайдере показать это здесь и в Я → Доступ, без бесконечной кнопки «Подтвердить». Служебная QA-выдача остаётся в защищённом операторском интерфейсе и не выдаётся за production proof.

Исключение из скрытия статусов: **реальная потеря/неопределённость сохранения**. Не прятать её ради красоты. Краткая строка «Не сохранено» возле действия/черновика → окно восстановления с точным повтором, деталями и конфликтом. Уже существующие immutable retry, CAS и блокировки опасного выхода сохраняются. Успешное сохранение — краткая обратная связь, не постоянная техническая панель.

## 5. Цельные сценарии

### J01. Начать и получить первую пользу

Приветствие → выбор цели/пропуск → тема или вопросы → первый результат → Мой мир. Вход по запросу сохранения в аккаунт или прямой кнопке. Связанный блок: welcome, first-steps, email/OTP, создание минимального профиля, перенос гостевых отметок, первый полезный результат. Обязательно сохранить приглашение и допустимое намерение. Текущий `sign-in-return.ts` разрешает только известные share/compare UUID: расширение возврата делать через allowlist и тест безопасности, без произвольных URL.

### J02. Изучить тему и добавить её в личную карту

Темы → поиск/направление → описание и смысл → «Отметить для себя» → компактный редактор → сохранение → возврат к теме → «В моей карте». Редактор различает отношение, опыт, силу и границу; запрет не считается сильным желанием. Подсказки терминов открываются по нажатию. Каталог показывает знания, карта — личные отметки. Изменение/удаление/конфликт относятся к этому же блоку, а не к будущей отдельной полировке.

### J03. Ответить на вопросы и понять результат

Мой мир/Темы → выбор опросника → короткое описание → вопросы → результат → объяснение вывода → просмотр предлагаемых отметок → явное добавление в карту. Не публиковать ответы, не менять существующие границы автоматически. Незавершённый тест можно продолжить; выход предупреждает только при реальном риске потери. Итог не диагноз и не выдуманная научная оценка. Возврат с результата ведёт к карте/тестам согласно точке входа.

### J04. Вести личные заметки

Мой мир → Дневник → список по времени → новая запись в редакторе → сохранить → запись. Редактирование и удаление с коротким подтверждением; очистка истории в отдельном опасном действии. При неизвестном результате — точный повтор существующей операции. Дневник приватен; публикация, если появится, отдельный явный путь с предпросмотром, не переключатель по умолчанию.

### J05. Оформить профиль и управлять раскрытием

Я → редактировать профиль в связанных коротких шагах → сохранить → «Посмотреть, что видят другие». Ник из аккаунта не дублируется противоречащим полем. Необязательные поля можно пропустить. Фото — существующий защищённый pipeline, с отдельными условиями публикации. Место — город/район, без точных координат.

Я → «Кто видит что» → приватно / по разрешению / публично для конкретного поля → предпросмотр → подтверждение. Запросы доступа → выбор точных полей → согласие → отзыв. Отзыв немедленно влияет на новые чтения. Я → ссылки и сравнения → предпросмотр выбранного содержимого → создать/отозвать ссылку; сравнение двух людей требует согласий обеих сторон. Пара — связанное добровольное приглашение, не второй логин и не автоматическое раскрытие партнёра.

### J06. Читать и участвовать в общении

Общение → Лента → пост → комментарии/реакция/автор. Фильтр и позиция ленты сохраняются при Back. Создание открывает редактор в sheet/workbench: текст → медиа при желании → аудитория/условия → предпросмотр → отправить → фактический статус рассмотрения/публикации. Не разворачивать форму на много экранов ниже ленты. Draft/pending/rejected и исправление отказа — часть того же пути. Жалоба, скрыть, блокировать доступны в меню поста/автора; причины и апелляция — в связанном окне. Не рисовать фальшивые просмотры/реакции.

### J07. Найти группу и участвовать

Общение → Группы → поиск/направление → группа → правила/контент по разрешению → вступить или подать заявку → реальное состояние. Автор: Мои группы → создать → правила/описание → предпросмотр → отправить на рассмотрение → редактировать после решения. Закрытые участники/материалы не показываются в preview. Membership/admin функции подключать только по реальному ACL.

### J08. Найти событие и принять решение

Общение → События → онлайн/рядом/дата → детали → интересуюсь / иду / не иду. Детали: название, организатор, время и часовой пояс, формат, условия, доступное описание, разрешённая ссылка. RSVP и публичность участия — разные решения; анонимность по умолчанию согласно backend. Список участников появляется только при необходимом взаимном согласии, без раскрытия закрытых имён.

Заявка → ожидание → одобрено/отклонено/отозвано. RSVP, одобрение, билет и доступ к адресу — разные статусы. Закрытый адрес/онлайн-ссылка не попадают в общий preview. Внешняя оплата подписана как внешний переход; внутренняя продажа билетов — отдельный финансовый проект, не фиктивная кнопка «Оплачено».

Автор: Мои события → создать → основные данные/время/условия → предпросмотр → отправить на рассмотрение → детали своего события → редактирование/отмена/заявки/безопасная статистика. Внесённые поля не теряются после отклонения или сетевой ошибки. Приёмка обязательно охватывает гостя, участника и организатора.

### J09. Включить знакомства и пройти подборку

Я/Мой мир → «Включить знакомства» → зачем и что будет видно → нужные допуски → кого ищу/город/предпочтения → предпросмотр публичного профиля → явное включение → пятая вкладка. Не включать видимость по факту входа или покупки.

Подборка → фото/галерея → внутреннее описание → пропустить/симпатия → следующая карточка; есть кнопочные альтернативы свайпу. Undo возвращает фактически последний выбор. Фильтры → применить → новая выдача; пустая выдача → изменить фильтры/пауза, без тупика. Симпатии → профиль → ответ; взаимность → предложить диалог в Общении. Закрытый слой → запрос доступа, без чтения запрещённых данных. Выключить → объяснить эффект → отключить discovery → четыре вкладки и возврат к Мой мир. Текущее in-memory переключение в V3 — только presentation; реальный server opt-in и сохранение preference требуют D01/D03.

### J10. Диалог, безопасность и платные функции

Общение → сообщения → диалог; переход из mutual match открывает тот же разговор. Требования допуска/взаимности/блокировки соответствуют server контракту. Отправка имеет pending/error/retry; нельзя рисовать полученное сообщение до ответа. Блокировка/жалоба → подтверждение → безопасный выход, без обхода блокировки из другого маршрута. UI может быть спроектирован до backend, но live отправка запрещена без контрактов.

Платная функция → конкретный paywall → тариф/условия → реальная покупка → проверенный entitlement → возврат к функции. Я → подписка/восстановить/управление. Не переносить цены и free trial из HTML как утверждённые условия. Пока платежи не подключены, фиксировать blocker в ledger; не изображать успех покупки и не запускать неподключённый checkout. Монетизация, privacy и age gate не смешиваются.

### J11. Настройки, восстановление и сотрудники

Я → настройки языка/темы/уведомлений; Я → доступ (18+, согласия, приватность); Я → выход/удаление. Удаление — отдельный ясный путь с перечнем последствий, серверным подтверждением и восстановлением неизвестного результата. Смена аккаунта очищает чужие состояния, gate-намерения, подборку и кеши согласно текущей owner isolation.

Сотрудники идут в существующий защищённый operator/AdminWorkspace: очереди → материал → решение/причина → следующий материал. Роли и приватные фото не объединять с consumer UI. Moderation/editorial экран можно улучшать отдельно, но публикация и доступ определяются backend. Служебные тексты/QA-допуски не должны попадать на пользовательские экраны.

## 6. Контракт экранов и окон

| Поверхность | Состав и главное действие | Возврат / состояние |
|---|---|---|
| Мой мир, пустой | Короткая польза + один выбор «Найти первую тему», вторично вопросы | Без нулевой статистики и длинных инструкций |
| Мой мир, наполненный | Карта/баночки, продолжить начатое, компактный доступ к результатам и дневнику | Фильтр/позиция/выбранная тема сохраняются |
| Каталог | Поиск, разнородные редакторские направления, короткие описания | Empty search + сброс; возврат к запросу |
| Тема | Определение, полезные связи, личная отметка при наличии | Подсказка и редактор — поверх контекста |
| Тест/результат | Один вопрос/группа по смыслу; результат с раскрываемым объяснением | Прогресс/черновик/явное добавление в карту |
| Общение | Переключатель Лента/Группы/События; контент выбранного подраздела | Создание — отдельное окно; списки не сбрасываются |
| Я | Краткий профиль + предпросмотр, сгруппированные назначения | Редакторы/доступ/подписка по нажатию |
| Знакомства | Фото занимает доступную высоту; внутреннее чтение; действия над доком | Горизонталь выбирает, вертикаль читает |
| Gate | Заголовок о текущем действии, одна причина, один следующий шаг | Отмена безопасна, ресурс перепроверяется |
| Опасное действие | Конкретный объект и последствия, подтвердить/отменить | Нет фонового auto-submit после входа |

Для каждой поверхности: loading без скачков; настоящий empty с полезным действием; error с повтором; offline/неподтверждённое сохранение; denied/revoked; длинные тексты; RU/EN. Toast подходит для краткого результата, не для ошибки, требующей решения. На phone длинная задача — полноэкранный editor, короткая — sheet; desktop editor в удобной рабочей области, не растянутый телефон. Сохранять существующие URL/Back/focus guards. Не наслаивать окна над окнами: gate временно заменяет нужный шаг с сохранением контекста.

## 7. Визуальная дисциплина

- Один выразительный акцент на смысловую область; мягкий glow в фоновой композиции/главном действии. Маленькие карточки — типографика и содержимое, без случайных SVG-орбит, огромных иконок и конкурирующих свечений.
- Баночки используются там, где объясняют личную карту. Подборка людей — фото; события — дата/формат; обсуждения — автор/текст; каталог — редакторская структура. Не превращать всё в одинаковые card-grid.
- Смысловые заголовки вместо «технических» intro-card. Длинные объяснения — помощь по нажатию, кроме действительно необходимых ошибок/последствий.
- Тёплые light/dark токены Claude и Geologica; не повышать декоративную плотность ради «премиальности». Нужны проверенный контраст, ясная иерархия, воздух и размер текста на 320px.
- Motion отвечает на действие: sheet, reveal, выбор, сохранение, свайп. Transform/opacity, reduced motion; без постоянных анимаций мелкого декора.
- Desktop — полноценная композиция с боковой навигацией и полезными колонками; tablet/fold — собственная плотность. Не масштабировать 390px simulator.

## 9. Проверка и передача между сессиями

Перед работой: fresh main/open PR → этот документ → один блок → его Issue/доменные контракты → 2–5 нужных файлов. Никакого чтения всего архива по умолчанию. Перед реализацией записать в Issue: пользователь, точка входа, цель, happy path, отказ/ошибка, выход, surfaces, frontend/backend boundary.

На каждый блок: typecheck/build/существующий smoke + required CI; реальные React-снимки минимум 390/1440 light/dark; 320/768/1024 и короткая высота для материальной адаптивной правки; Back/Escape/focus/клавиатура, reduced motion, no overflow. Сравнить содержимое и композицию с Claude, а не только токены. Проверить весь путь и один существенный отказ. Новые тесты — для рискованных guards, сохранения, доступа/платежей, не для каждого пикселя.

В Issue/PR фиксировать: реализовано; подключено к серверу; проверено в браузере; что осталось макетом; блокеры. Отдельно хранить demonstration ledger. Не закрывать live acceptance по fixture или CI. Документные изменения не требуют сборки приложения и не должны провоцировать Vercel deploy.

**Первый следующий шаг: B0 + UX-контракт B1.** Сначала инвентаризация точек требования входа/18+/согласий и короткая схема сохранения намерения; затем цельный путь первого результата. Не начинать очередную «полировку Мой мир» отдельно от переходов в тему/вход/сохранение. После каждого coherent среза сохранить GitHub handoff ≤12 строк и продолжать следующий готовый шаг без запроса подтверждения каждого PR.
