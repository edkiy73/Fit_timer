# FetUre V10 — аудит переполнения текстов без пробелов (2026-10-16)

Исправления интерфейса в этом этапе **не вносились**. Изменён только QA-инструмент прототипа (`prototype/v10/qa.js`, одна строка в `main.js`) и пересобран `public/prototype-v10.html`.

## 1. Что сделано в QA-инструменте

Новый независимый режим **«Тексты без пробелов»** (панель V10 → «Тексты без пробелов → Без пробелов», `?nospace=1`, `FT_QA.nospace(true|false)`).

| Требование | Реализация |
|---|---|
| Максимальная длина поля | Лимиты взяты из форм: ник 20 (пара 60), о себе 500, расширенный профиль 1000, сообщество 50 / описание 500 / правила 1000 (делится на число правил) / вопрос 120, событие 80 / описание 1500 / условия 500 / вопрос к заявке 120 / ответ 300 / объявление 500 / причина отмены 300, пост 1000, вопрос опроса 200, вариант 80, комментарий и ответ 1000, обсуждение 120 + 3000, сообщение чата 2000, ответ в заявке 300, пара 60/500/1000. Поля без лимита (место, площадка, цена, ссылка, внешний билет) — 600 символов; город — 60; почта — 120; недавний поиск — 200 |
| Алфавиты | По кругу: кириллица, латиница, смесь, цифры, широкие заглавные (WМШЩ), длинный URL, e-mail. Ники — только допустимые символы `[A-Za-z0-9_.]` |
| Охват | Люди, города, сообщества (название, описание, правила, вопросы), события (включая созданные), посты, опросы и варианты, комментарии, обсуждения и ответы, сообщения чата, обновления, заявки в сообщества, ответы на заявки, дневник, пара (название, описание, правила, предложения, общий профиль), мой профиль и почта, недавний поиск |
| Не трогает служебное | id, маршруты, enum, ссылки на изображения, время, ключи. Уже набранная тестировщиком непрерывная строка сравнимой длины тоже остаётся как есть |
| Динамический контент | Применяется перед **каждым** рендером любого экрана (`SC[*].render`, в т.ч. частичный `chatRefresh`) и перед отрисовкой Bottom Sheet (`drawSheet`) — покрывает созданные посты/события/сообщества, автоответы чата, ленивые данные |
| Полное восстановление | Каждое исходное значение хранится в журнале; выключение возвращает его. Копии, которые прототип сам сделал из подставленных значений (общий профиль пары, черновики), возвращаются по уникальному маркеру. Проверено: `JSON` всех текстовых данных после «выкл» **идентичен** исходному для `persona=full|pair|new` |
| Ничего не сохраняется | Только память страницы; ни сети, ни `localStorage` |
| Другие режимы | «Длинные тексты» и остальные QA-опции не изменены логически; включение одного из двух режимов выключает другой (иначе их снимки перепутались бы). Контрактные тесты `tests/prototype-v10-*-contract.mjs` проходят |

Каждая подставленная строка начинается с метки поля (`bioru…:`, `evru…:`, `commru…:` и т. д.) — на скриншоте сразу видно, какое поле переполнено.

## 2. Как проводился аудит

Локальная сборка (`public/prototype-v10.html` из тех же исходников; production-URL из среды недоступен — прокси даёт 403; лишних деплоев нет), шрифт Onest подключён. Chromium + Playwright, скрипты — `tools/prototype-v10-nospace-audit/` (README внутри).

| Слой | Объём |
|---|---|
| Статика | все пункты меню V10 (79 экранов + 11 специальных состояний) × 6 размеров (320×700, 390×844, 430×932, 768×1024, 1024×768, 1440×900) × RU/EN, светлая тема |
| Обход кликами | 69 дополнительных экранов по ссылкам + клик по каждому уникальному `data-act` (до 26 на экран) и ещё один уровень внутри Bottom Sheet: ≈2 200 взаимодействий на 320 RU и ≈2 000 на 320 EN |
| Сценарии форм | 19 сценариев × 8 конфигураций (320 RU/EN, 390, 768, 1440, 320 тёмная, 320 «в паре»): публикация поста и опроса, голосование и список голосовавших, комментарий и ответ, чат (2000 символов + автоответ), создание события (4 шага), заявка на участие, создание сообщества, обсуждение, редактирование профиля и ошибка ника, заявка в закрытое сообщество, жалоба, объявление/отмена события, меню и диалоги подтверждения |
| Детектор | для каждого текстового узла: выход за viewport, обрезка предком с `overflow`, выход за свой блок, пересечение с кнопками рядом; плюс растяжение родителя и «содержимое шире экрана» |
| Проверка | 52 компонента отдельно воспроизведены и **сфотографированы** на 320 (RU, EN, тёмная), 390, 768, 1440 (`verify.mjs`); каждый вердикт ниже подтверждён скриншотом |

Автоматика дала 158 «первичных» групп; после визуальной проверки они сведены к ≈30 реальным компонентам и 6 первопричинам. Ложные срабатывания отброшены: однострочное многоточие (`.nmt`, `.chat-row`, `.frow`, `.bar .sub`, недавний поиск, мини-карточки в правой колонке) — **намеренное поведение**, не ошибка. Строки, у которых «вылезает» только соседний элемент из-за растянутого родителя, не считались отдельными ошибками.

## 4. Группировка по первопричинам

| Причина | Что исправлять системно | Закрывает строки |
|---|---|---|
| **A. Нет базового переноса для пользовательского текста.** `overflow-wrap` не задан на `.md`, `.bio`, `.cmc b/small`, `.disc b`, `.rules li`, `.fact`, `.upd`, `.nt`, `.li small`, `.me-id b`, `.evc .bd b`, `h2` обсуждений/сообществ/событий. Уже правильные компоненты (`.cm .reply-text`, `.poll .pot`, `.md a`, `.kv dd`) используют `overflow-wrap:anywhere` — правило есть, но не централизовано | Одна базовая утилита/правило для «контента пользователя» (`overflow-wrap:anywhere`, перенос по месту, а не `hyphens`) вместо точечных патчей; перечислить в нём все текстовые узлы или добавить класс в билдеры (`bar()`, `linkRow()`, `field()`, `empty()`, `grp()`, карточки в `ui.js`) | 1, 4, 8–11, 13–16 |
| **B. Flex/grid-потомки без `min-width:0` и `minmax(0,1fr)`.** Один длинный элемент растягивает родителя до своей `min-content` ширины | `.poll` (grid), `.pc-who`/`.pc-name`/`.pill` (flex-wrap), `.fact`, `.li`, `.cmc`, `.toast .tx`; везде где `flex:1` без `min-width:0` или `grid-template-columns:1fr` | 2, 3, 5, 6, 7, 13, 19 |
| **C. Сжатое по ширине переполнение не видно и не обрабатывается.** `.view{overflow-x:hidden}`, `.evc`, `.hero`, `.ev-hero`, `.card` режут край без многоточия и без индикации; страница «молча» шире экрана | Страховка на контейнерах (`min-width:0; max-width:100%`), для намеренно однострочных мест — единый паттерн «nowrap + ellipsis», для многострочных — перенос; не полагаться на `overflow:hidden` как на решение | усиливает 1–16; проявляется как «содержимое сдвинуто / обрезано» |
