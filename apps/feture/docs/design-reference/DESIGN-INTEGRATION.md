# Полный дизайн и подключение функций

Решение владельца 13.10.2026: **проектировать законченный продукт до готовности backend**. Ожидание API не блокирует визуальные сценарии, наполненные экраны, взаимодействия и состояния. Демонстрационное поведение явно описывать здесь, в PR и Issues, без технических плашек в потребительском интерфейсе. Это уточнение заменяет ограничения «дизайн только после готовности backend» в прежней очереди #908 и PRODUCT-UX-V2.

Серверные права, возраст, публикация, настоящие совпадения и раскрытие личных данных остаются отдельными задачами. Демонстрация не даёт разрешения включать реальные функции или подменять успешным ответом ошибку существующего API. При подключении реальных пользователей иллюстративные профили исключить из выдачи.

## UX-contract D02

1. Основной путь: необязательный вход → подборка → галерея/полный профиль → выбор/отмена → симпатии/конец подборки.
2. Ручные фильтры города и возраста; без геолокации. Применение фильтров сохраняет симпатии.
3. Только горизонтальный жест после direction lock; вертикаль прокручивает профиль. Кнопки не запускают свайп.
4. На время смены карточки повторный выбор заблокирован: нельзя оценить невидимый профиль.
5. Галерея имеет доступные кнопки и индикаторы; все действия доступны без жестов.
6. Phone: внутренняя прокрутка; короткие экраны оставляют место для действий и дока. Tablet/fold: карточка + контекст. Desktop: фото и отдельная прокручиваемая часть профиля рядом.
7. Фильтры и симпатии — AppDialog/React Aria с URL overlay, focus return, Escape/Back. Детали desktop доступны клавиатурой.
8. Reduced motion убирает пространственное движение. Никаких выдуманных процентов совместимости, online badges, verified badges, взаимных симпатий и сообщений.
9. Пустая подборка и пустые симпатии имеют осмысленные действия. Network/loading/error состояния реальной выдачи будут подключены вместе с D01; не симулируем network success.
