# FetUre — пересборка UX V3

Решение владельца 13.10.2026, 01:37. **Заменяет выбранную IA V2 (постоянная Главная + пять фиксированных вкладок).** Визуальный ориентир — Claude HTML; функциональная структура — наши актуальные доменные сценарии. Полный дизайн не ограничивается готовностью backend; demonstration ledger — [DESIGN-INTEGRATION.md](DESIGN-INTEGRATION.md).

## Новая основа

| Раздел | Назначение |
|---|---|
| Мой мир `/world` | Личная карта, отмеченные темы, результаты, дневник. Домашний раздел после входа; `/` перенаправляет сюда с `replace`. Отдельную Главную удалить. |
| Исследовать `/explore` | Редакторский каталог нового: темы, определения, тесты и материалы. Не копия личной карты. |
| Сообщество `/community` | Общение, лента, группы и события внутри одного раздела. |
| Я `/account` | Профиль, оформление, настройки, доступ и безопасность. |
| Знакомства `/dating` | **Пятая вкладка только после добровольного включения**. Выключение возвращает четыре. Первые четыре остаются в том же порядке. |

Публичное приветствие остаётся отдельным вводным состоянием `/` без аккаунта; это не постоянная вкладка. Онбординг — отдельный короткий путь, а не домашний экран. Полные названия в заголовках/desktop и доступных именах; короткие подписи дока («Мой мир / Темы / Общение / Я / Встречи») исключают обрезанные слова на 320px.

## UX-contract первого законченного среза

1. Один ProductLayout и одна навигация для потребительских разделов; удалить отдельные rails Account/Experience и tablet nav.
2. Desktop — одна боковая навигация, прокручиваемая при малой высоте; phone/tablet/fold — единый стеклянный dock с фактическим числом 4/5 колонок.
3. «Мой мир» сохраняет реальные карту/конфликты/редактор/очередь; добавляет добровольный вход в знакомства. Навигация остаётся и на внутренних потребительских инструментах.
4. Включение/выключение знакомств сейчас — **in-memory presentation choice**, общий для всех маршрутов, с reset при смене аккаунта. Это не server discovery/consent; reload сбрасывает выбор. Отдельные D01/D03 подключат реальное включение/выдачу/решения.
5. Phone Dating — **viewport-композиция**: компактный заголовок → photo-led карта на оставшуюся высоту → действия → dock. Без внешней прокрутки и повторных больших hero/header/context panels.
6. Полный профиль прокручивается внутри карточки; горизонталь выбирает, вертикаль читает. Смена размера отменяет активный жест. Кнопки не участвуют в drag.
7. Галерея, like/pass/undo, локальные симпатии и конец подборки работают по уже существующему fixture-ledger. Повторный выбор во время смены карты заблокирован.
8. Filter/options/likes — responsive AppDialog с URL/Back/Escape/focus; вход в симпатии остаётся в options даже на коротком телефоне.
9. Tablet/fold — карта с комфортной шириной, тот же dock; desktop — photo/details split. Это один React product, не iframe/phone simulator.
10. Типографика Geologica SHRP/CRSV, warm light/dark, rose/lilac, стекло и мягкая глубина — из Claude; движение transform/opacity, reduced motion, крупные зоны действий.
11. Нет новых UI libraries/платных API, server/auth/privacy/SQL изменений или преждевременного APK/IPA.

## Проверка первого среза

Реальная production React-сборка, изолированный Chromium headless shell (без реальных аккаунтов). Матрица: 320×640, 390×844 и короткий 390×650, 768×1024, 1024×768, 1440×900; light/dark на 390/1440. Никакого горизонтального overflow или внешнего page-scroll на Dating. На 390×844: photo-card577px, действия завершаются754px, dock начинается766px; на320×640:373px/550px/562px. Док имеет ровно4/5 ссылок, все touch targets≥44×54px.

Путь `4 → включить → 5 → Исследовать → Я → Знакомства → выключить → 4`, галерея, внутреннее раскрытие, like/undo, filters/Escape прошёл без page runtime errors. Дополнительные touch/reduced-motion/source comparison результаты — в PR и #1015. Снимки настоящего React: `.artifacts/v3/`; предыдущий main44e343e — отдельный baseline, Claude HTML — отдельный reference. Физические Android/iOS/fold, реальные server-backed D01/D03 и live permission acceptance остаются открытыми.

Основа взаимодействий: [WCAG 2.2 dragging alternatives](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements), [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action), dynamic viewport/safe areas. Это ориентиры для реализации, не заявление полной WCAG-сертификации.

## Дальнейшая пересборка — целыми сценариями

1. **Оболочка + Dating mobile viewport** — текущий срез, подтверждение скриншотами; не «дизайн всего продукта готов».
2. **Мой мир / Исследовать** (#910/#1015): пересобрать композицию карты, jars, тему и результаты; вторым экраном сделать настоящий editorial catalogue, не ещё одну матрицу одинаковых cards. До/после phone+desktop light/dark.
3. **Сообщество / События / Группы** (#1017/#1020–1023): разные содержательные форматы, афиша, детали, создание в sheet/workbench, RSVP и организатор. Будущие состояния проектировать сейчас, demo только в ledger, без подмены live API success.
4. **Я / профиль / первый путь / тесты / дневник**: единая выразительная композиция и компактные editors, последовательные переходы и сохранение; существующие guards/retry не менять ради макета. Shared AdminWorkspace отдельно.
5. **#869/#870:** физические устройства, keyboard/200%/screen reader/native и выпуск. Не закрывать по одному CI или красивому одному screenshot.
