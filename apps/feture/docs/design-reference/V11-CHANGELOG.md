# FetUre V11 — что изменено

V11 — копия V10 (main @ 3085b6d0, после #1196 и #1197) с исправлениями по UX-аудиту [`V10-UX-AUDIT.md`](V10-UX-AUDIT.md).
V10 остаётся замороженной: `public/prototype-v10.html`. Новая версия: `public/prototype-v11.html`.

Решения владельца (20.10.2026):
- тесты на паузе — упоминания тестов убраны из интерфейса;
- пара — у каждого свой аккаунт, профили связываются приглашением, второму партнёру короткий вход;
- вкладка «Я» → «Профиль» (у пары — «Профили»);
- отказ в доступе показывается мягко, но однозначно («решили не открывать»); повторный запрос — не раньше чем через 30 дней.

Номера задач (UX-NN) — из аудита.

## 20.10.2026 — исправления по UX-аудиту

### Онбординг
- **UX-01 · тесты.** Шаг «Первый тест» убран (он показывал интересы). В шторке «Создать», композере, ленте и знакомствах «результат теста» заменён на «интересы»: вложение «Интересы», тип «С интересами», «Добавить интересы» вместо «Пройти тест». Плитка «Тесты» в профиле осталась со «Скоро».
- **UX-02 · счётчик.** Одна шкала 1 / 3 → 2 / 3 → 3 / 3 (имя и дата → о тебе → интересы), полоска шагов на каждом экране.
- **UX-03 · пара.** «мы пара — ищем вместе» убрано из личных статусов (внутри профиля пары статус остаётся). На шаге «О тебе» новый вопрос «Ты здесь с партнёром?» — «Да, вместе» после регистрации сразу открывает приглашение партнёра. На экране приглашения — «У партнёра ещё нет аккаунта? Отправь ссылку».
- **UX-29.** «Я ошибся в дате» → «Дата указана неверно».

### Сообщества
- **UX-04 · пилюля = состояние, кнопка = действие.** На карточках: «На рассмотрении» вместо «Заявка отправлена»; в «Моих сообществах» пилюля не повторяет заголовок секции; в онбординге кнопки «Вступить / Подать заявку / Отменить / Отозвать».
- **UX-05 · экран сообщества.** «Ты участник» — пилюля, а не кнопка выхода; выход — «⋯ → Выйти из сообщества». Ждущая заявка: пилюля «Заявка на рассмотрении» + «Отозвать»; под замком «Заявка у ведущих. Обсуждения откроются, когда её одобрят».
- **UX-05b.** «Расширить аудиторию нельзя» → «Обсуждение увидят только участники — так устроены закрытые сообщества».

### События
- **UX-06 · отменённое.** Нет строки цены и условий, нет «откроется после одобрения», нет замка — только плашка об отмене.
- **UX-07 · прошедшее.** «Ты на событии» → «Посещено».
- **UX-08 · онлайн.** «Ссылка на подключение откроется, когда ответишь «Иду»» / «…после одобрения заявки».
- **UX-09 · время.** Очное событие показывается по местному времени площадки («19:00–22:00 местное время»), онлайн — по времени человека, а при другой зоне второй строкой «У организатора: 19:30–21:00 по Москве». Карточки и списки — так же (раньше берлинские вечеринки стояли на 01:00).
- **UX-10.** В алерте организатора «Рассмотри заявки ниже — люди ждут ответа», число осталось только в статистике.

### Профили и доступы
- **UX-11 · совместимость.** Тема попадает ровно в одну группу; «Стоит обсудить» и «Дополняете друг друга» важнее «Совпадает».
- **UX-12.** «Формат отношений разный: у тебя — …, в профиле Maya — …»; везде «Дополняете друг друга».
- **UX-13 · доступы.** Вкладки «Открыто мной · Открыто мне · Мои запросы». Отказ виден как «решили не открывать» с подписью «Запросить снова можно через N дн.»; повторный запрос — через **30 дней** (было 7).
- **UX-14.** Кнопка на входящем запросе «Открыть доступ» вместо «Открыть» (ведёт в выбор разделов и срока, одним тапом доступ не выдаётся).
- **UX-32.** «Симпатии выкл.» → «Не принимает симпатии», по нажатию — объяснение, что можно подписаться.
- **Вкладка «Я» → «Профиль»,** при активной паре — «Профили». Все отсылки «в «Я»» обновлены.

### Чаты, уведомления, лента
- **UX-15.** QA «Приглашение» больше не падает (алиасы в QA разрешаются); добавлен пункт «Приглашение в пару» → уведомления.
- **UX-16.** В чате одна пилюля доступа с направлением: «Приватное открыто друг другу» / «Тебе открыта приватная часть» / «Твоя приватная часть открыта».
- **UX-17.** Переключатель чатов «Все · Личные · От пары» и подпись «Здесь вы пишете от имени пары…»; QA «Совместные чаты» открывает пару.
- **UX-18.** Лента: явный переключатель «Для тебя · Подписки» вместо одиночного чипа.
- **UX-19.** Страница темы: пилюля «В твоих интересах» + «Изменить ответ»; иначе «Добавить в интересы».
- **UX-20.** Аудитория «Кому открыт доступ · N» вместо «Приватный круг»; в «Создать» подпись «Или сразу начать с».
- **UX-21.** «С кем-то вместе? Свяжи профили в пару»; плитка «+N ещё» вместо второго «Все».
- **UX-22.** В настройках строка «Режим» в секции «Знакомства».
- **UX-30.** «Приглашает тебя связать профили в пару».
- **UX-31.** Пустая приватная часть пары обращается на «вы».

### Знакомства, Premium, мелочи
- **UX-24.** Premium: подзаголовок не дублирует пункт, пометка «для этого», футер «Premium не обходит чужие настройки приватности».
- **UX-25.** Лимит запросов: сколько можно за сутки и когда станет доступен следующий.
- **UX-27.** Штампы «Нравится / Пропустить» (как кнопки), одноразовая подсказка про свайп на первой карточке.
- **UX-28.** «Написать первым» → «Написать сообщение».
- **UX-33.** RU/EN, сортировка ответов и ✕ сброса фильтра получили зону нажатия 44 px.

### Проверено и оставлено без изменений
- **UX-23** (шторка интереса): «Кто видит … Все» — это выпадающий список, а не дубль; «Всё» в «Как тебе ближе» — быстрый выбор всех трёх, работает как ожидается.
- **UX-26** (выдача доступа): «Срок 7 дней» — тоже выпадающий список, дубля нет.

Проверка: `npm run test:prototype` (70 PASS, в т. ч. новый `prototype-v11-ux-audit-contract.mjs`), все 88 QA-экранов V11 открываются без ошибок, ключевые экраны просмотрены в браузере на 390 px.
