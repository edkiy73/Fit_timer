# FetUre V6 — аудит, изменения и причины

13.10.2026. Основа — Claude V5 из main `37521a70`, а не старый concept.html и не React V4.

[Открыть V6](prototype-v6.html) · [V5 для сравнения](prototype-v5.html) · [React-интерфейс](./#/design/F01)

## Что это за версия

V6 — связанный кликабельный прототип для обсуждения и переноса в существующий React/TypeScript/AppBase. Это **не** замена production backend: вход, проверки, доступы, события, симпатии и оплаты в прототипе иллюстрируются на вымышленных данных. Серверные ACL и реальные аккаунты этой работой не изменены. В React перенесение и backend-подключение остаются отдельной работой. Вся текущая сессия сбрасывается при перезагрузке; язык/тема не равны сохранению доменных данных.

Проверено исходное live-представление V5: Лента, Люди, Чаты, Я, собственный профиль, редактор. Отдельно проверены исходники всех разделов, состояния и переходы. Ошибки privacy/chat/block/undo подтверждены независимым воспроизведением кода, а не только визуальным впечатлением.

## Продуктовые исправления

| Недостаток V5 | Что изменено в V6 | Почему / где |
|---|---|---|
| Роль отмечена «по доступу», но показана в публичном профиле | Сохранение visibility и единая публичная проекция для гендера, ориентации, формата и роли | Выбранная приватность должна реально влиять на профиль. core.js, s-profile.js |
| Скрытый опыт и приватная роль используются в объяснении общего | Объяснение читает только публичные данные; расширенный доступ не расширяет публичное объяснение | Нельзя раскрывать закрытое через сравнение. ui.js |
| Наличие thread открывает чат без взаимности | Проверка взаимности до создания thread, повторная проверка перед отправкой/вложением/повтором | Только взаимная личная симпатия открывает сообщения. s-people.js, s-chats.js |
| Старый приватный экран доступен после блокировки | Удалены связанные запросы/grants/уведомления, валидаторы проверяют block и срок | Блокировка прекращает весь доступ в текущей модели. s-profile.js |
| Истёкшие доступы показаны открытыми | Нормализация статуса и проверка срока при каждом просмотре | Просмотр нельзя обещать после истечения. s-profile.js |
| Сужение доступа расходится между списком и заявкой | Синхронизированы выбранные scopes | Одна выдача должна одинаково выглядеть везде. s-profile.js |
| «Взаимно» снова в Людях, включая боковую колонку | Люди: Подборка / Симпатии / Запросы; взаимные контакты — только в Чатах | Последнее требование владельца; меньше дублирующих мест. s-people.js, ui.js |
| Счётчик новых контактов отличается от показанных кружков | Один критерий: у взаимного контакта ещё нет сообщений | Счётчик относится к видимой группе. core.js |
| Undo после взаимности будто возвращает анкету, но match остаётся | Понятное объяснение и переход к управлению контактом в Чатах | Undo просмотра не должен тайно отменять взаимное решение. s-people.js |
| Автоответы приходят после block/end/logout | Callback проверяет текущий аккаунт, thread, mutual, block и ended | Старые операции не должны воскресить контакт. s-chats.js |
| Новое сообщение не возвращает архив, хотя UI обещает | Соответствующее поведение добавлено | Архив и блокировка имеют разные последствия. s-chats.js |
| Социальный чат навязывает первое свидание | Нейтральные подсказки про общие темы и удобный способ общения | Приложение полезно вне знакомств. s-chats.js |
| Симпатии выключены, но профиль позволяет отправить | Единый guard и явный переход в настройки | Не включать пользовательское участие скрытым действием. s-profile.js |
| Редактор «Как видят» показывает сохранённое | Предпросмотр использует текущий черновик без публикации | Можно оценить изменения до сохранения. s-profile.js |
| Из формы можно уйти через другой раздел без предупреждения | Общая защита go/tab/back, сохраняем ввод при отказе | Предупреждение должно работать на всех выходах. core.js |
| Переключение видимости RSVP ставит «Иду» | Сохраняется прежний ответ; есть «Без ответа» | Приватность не означает намерение участвовать. s-events.js |
| Проверка возраста пропускается в финальной форме RSVP | Финальный guard проверяется перед сохранением | Другой вход в форму не должен менять требование. s-events.js |
| Редактирование события сбрасывает часы/условия | Полный перенос времени, зоны и условий в черновик | Редактирование одного поля не должно портить другое. s-events.js |
| «У тебя» всегда означает Берлин; зимой неверное UTC | Зона устройства и преобразование через IANA timezone; несуществующее время отклоняется | Время события зависит от зоны и DST, не языка интерфейса. core.js, s-events.js |
| Конец раньше начала незаметно переносится на завтра | Ошибка у поля времени | Нельзя молча менять дату завершения события. s-events.js |
| «Рядом» означает все офлайн-события | «В моём городе», фильтр по выбранному городу; без города — «Офлайн» | Не обещать расстояние без соответствующих данных. s-events.js |
| Скопировано / календарь / архив данных — только тост | Реальный clipboard с ручным fallback, ICS-файл, JSON-файл текущей сессии | Эти действия можно проверить даже без backend. s-completion.js |
| Заглушки пары и отсутствующий pairLink | Приглашение, ожидание второго согласия, предложение изменений, отдельные доступы, разъединение | Приглашение не равно согласию; личные аккаунты остаются раздельными. s-completion.js |
| В материалах только «следующая версия» | Выбор файла, описание, аудитория, личное/ожидающее review состояния | Видим весь путь; файл не загружается в сервис. s-completion.js |
| Видео можно запросить, но нет представления | Самостоятельное пустое состояние выданного видео-раздела | Право просмотра не означает наличие материала. s-completion.js |
| Предоставлено 3 фото, показано 6 | Количество соответствует выданному scope | Фото и альбом различаются. s-profile.js |
| Сообщество → заявки/модерация/правила/ведущие — заглушки | Экраны очередей, редактор правил и список ведущих | Завершён путь управления без расширения приватных прав. s-completion.js |
| Помощь — ряд неработающих кнопок | Конкретные объяснения возраста, доступа, чатов, событий, Premium | Пользователь должен понять последствия действия. s-completion.js |
| «100% профиль» требует обозначить границу | Границы исключены из обязательной полноты | Не принуждать к раскрытию чувствительной информации. s-me.js |
| «Пять вопросов» содержит один | Описание и длительность соответствуют фактическому тесту | Обещание должно совпадать с содержимым. s-me.js |
| «Как в системе» всегда русский | Читается системный язык устройства | Системная настройка должна соответствовать устройству. s-settings.js |
| Настройки уведомлений теряются после повторного открытия | Настройки принадлежат аккаунту в модели сессии | Состояние экрана не равно настройкам пользователя. s-settings.js |

## Визуальные и accessibility-исправления

| Наблюдение | Решение | Причина |
|---|---|---|
| Фото профиля занимает почти весь первый экран; содержательные табы ниже | Более короткий адаптивный hero и спокойный отступ вокруг действий | Данные и вкладки доступны раньше |
| Названия баночек обрезаются («Ролевые и…») | Сетка по минимальной ширине, перенос по словам, полный текст | Можно различать тему без открытия |
| Маленькие действия и иконки | Минимальные 44 px для вторичных действий и фокус-контур | Удобнее нажимать и пользоваться клавиатурой |
| Диалог не удерживает фокус, фон доступен Tab | Focus trap, inert фон, Escape и возврат к инициатору | Работа мышью и клавиатурой должна быть равноправна |
| Свайп начинает движение при нажатии внутренних кнопок | Кнопки исключены; pointercancel не принимает решение | Просмотр и выбор не должны конфликтовать |
| Три «фотографии» — повтор одного кадра с искусственными crop | Индикатор соответствует наличию реального изображения в fixture | Не обещаем галерею без фото |
| Уже применены 6 невидимых фильтров | Нейтральные исходные фильтры 18–99, без скрытого отбора | Новая сессия не должна создавать ложное «никого нет» |
| Компьютер выглядит слишком растянутым | Ограничение рабочей области и отдельные sidebar/context размеры | Полноценный desktop без растягивания телефона |

## Сценарии проверки

1. Вход/регистрация → минимальный профиль → обычное личное пространство. Проверить ошибки, отказ, отсутствие ненужной публикации.
2. Лента → автор → профиль → баночки → объяснение общего. Публичные и скрытые поля не смешиваются.
3. Люди → симпатия → взаимность в Чатах → диалог → архив/прекращение/блок. Права не возникают от наличия записи.
4. Я → карта → интерес/граница/видимость → профиль. Граница не равна нулю интереса.
5. Опрос → назад → пропуск → результат → выбранное применение. Черновик сохраняется, карта не меняется автоматически.
6. События → RSVP/видимость → заявка/адрес/билет → редактор. Все статусы принадлежат конкретному событию.
7. Сообщества → правила → вступление → обсуждение → управление. Чужие личные данные недоступны ведущему.
8. Пара → приглашение → ожидание → общие решения. Одного клика одного участника недостаточно для второго согласия.
9. Материал → файл → аудитория → статус проверки. Не представлять локальный выбор за загрузку.
10. Настройки → язык/тема/уведомления/данные/приватность. Отказы и ошибки не теряют ввод.

## Где код и что переносить

Исходники: `apps/feture/prototype/v6/`; сборщик `tools/build-prototype-v6.mjs`; результат `public/prototype-v6.html`. Все изменения сделаны в V6, V5 оставлен для сравнения.

При переносе в React использовать эти состояния и действия через текущий AppBase и существующие domain API, не копировать симуляцию проверок и сетевых успехов. Одни и те же серверные permission проверки обязательны на чтении и записи. Разделённые privacy поля должны приходить уже отфильтрованными с сервера, а не скрываться CSS. Никакого нового auth, SQL или общей инфраструктуры этот прототип не вводит.

## Проверки и пределы

Результаты текущих проверок записываются в PR. Не проверены физические Android/iOS/fold, системная клавиатура, VoiceOver/TalkBack, настоящий OAuth/email/проверка возраста, платежи, доставка сообщений или сохранение в production DB. Проверка макета не закрывает #908/#1015/#869 и не означает готовность к выпуску.
