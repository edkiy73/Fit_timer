## Где смотреть

- **Прототип V5:** `https://feture-mvp.vercel.app/prototype-v5.html` (один файл, работает и скачанным на телефон). Слева вкладка «Экраны» — все экраны, язык RU/EN, тема, ширина телефон/планшет/окно, режим «нет сети», новый или заполненный аккаунт, Premium.
- **Это описание:** `https://feture-mvp.vercel.app/prototype-v5-notes.html`, исходник `apps/feture/docs/design-reference/CLAUDE-V5-REVIEW.md`.
- **Исходники прототипа:** `apps/feture/prototype/v5/` (стили, данные, ядро, экраны по разделам). Сборка: `node tools/build-prototype-v5.mjs`. Проверка: `node tools/qa-prototype-v5.mjs` — открывает все 80 точек в RU и EN и ищет ошибки JS, русский текст в английском интерфейсе и горизонтальный скролл.
- Быстрый вход: «У меня уже есть аккаунт» → «Продолжить с Google» → первый аккаунт. Новый пользователь: «Создать аккаунт». Коды: `000000` — неверный, `999999` — истёк, любой другой — верный.

V5 — кликабельный эталон дизайна и поведения, а не продакшн. Серверные права, оплата, проверка возраста и доставка сообщений в нём имитируются. Следующий шаг — перенос в React-компоненты `src/feture/design/` (раздел «Как переносить в React»).

## Что ChatGPT сделал хорошо — сохранено

- Структура V4: пять постоянных разделов **Лента / Люди / Сообщества / Чаты / Я**, события внутри Ленты, карта/изучить/дневник внутри «Я».
- Спецификация `MASTER-PRODUCT-SPEC-V4.md`: правила R01–R04 (подписка ≠ симпатия, доступ ≠ чат, взаимность — единственный путь в личный чат), три статуса события (ответ / заявка / билет), квота запросов, приватность RSVP. V5 следует этим правилам.
- Отказ от «87% совместимости» и от «симпатии с комментарием» — верные решения (это обход запрета на сообщения до взаимности).
- Настоящий вход через Core, серверные проверки не тронуты, пустой тестовый аккаунт без записи в базу.
- Реальные фотографии в карточках вместо абстрактных пятен.

### Список недоработок владельца: причина и как исправлено в V5

| Недоработка | Причина в коде ChatGPT | Как сделано в V5 |
|---|---|---|
| «Публикации» в профиле открывают общую ленту | `onPosts={()=>go('F04')}` — переход в ленту темы без автора | Вкладка «Публикации» внутри профиля, фильтр по `author` выбранного человека, счётчик на вкладке |
| Отредактированные сведения видны не везде | Профиль собирается из фикстур `people`/`viewerPerson`, редактор пишет в отдельный черновик | Один источник `S.me`: редактор, шапка «Я», боковая панель, композер, посты, карточка «как видят другие» читают одно и то же |
| Нет полного списка исходящих запросов со статусами | В P07 только «получено/отправлено» без жизненного цикла | «Я → Доступы»: Ко мне / Мои запросы / Открыто мне / Кому открыто. Статусы: ждёт ответа, открыт частично, открыт, без ответа, истёк, отменён; отмена запроса, квота «осталось 2 из 3», повтор не раньше 7 дней |
| «Мои события» показывают все события | `E10` фильтрует только по формату и городу | Вкладки Иду / Интересуюсь / Заявки / Организую / Прошедшие, в каждой — только события с твоим статусом |
| Статус участия не привязан к событию | Одно `useState('interested')` на все события | `S.rsvp[eventId] = {status, app, ticket, show}` — отдельно для каждого события |
| «Организатор» открывает чужой профиль | `button('Организатор','Organiser','P01')` без id; `P01` берёт `?person=` от прошлого экрана или первого человека | Кнопка передаёт `event.organizer`; если организатор — ты, открывается твой профиль |
| Одинаковые обсуждения в разных сообществах | Общий список и зашитое `'2'` в табе | У каждого обсуждения есть `community`; страница сообщества показывает только свои; счётчик считается |
| Счётчик участников не меняется | `members={group.members}` из фикстуры | `C.members(id)` = база + ты, если вступил; меняется при вступлении и выходе |
| Непереведённые элементы | Часть строк собирается из английских ключей фикстур | Каждая строка интерфейса — пара `L('рус','eng')`; данные-заглушки тоже двуязычные; автоматическая проверка: в английском режиме 0 строк кириллицы на 80 экранах |
| Счётчики зашиты | Бейджи и табы с константами | Все счётчики — функции состояния (`C.likesIn`, `C.reqIn`, `C.unreadChats`, `C.notif`…): ответил на симпатию — бейдж уменьшился, прочитал уведомление — колокол обновился |
| Параметры прошлого экрана переносятся | `go()` копирует весь `location.search` в следующий маршрут | Каждая запись истории хранит свои параметры; у экрана есть проверка `valid(p)`: без нужного id показывается нейтральное «Это недоступно», а не чужие данные |

### Дополнительные замечания владельца

- **Поиск с фильтрами:** вкладки Всё / Люди / Публикации / Сообщества / События / Темы; у публикаций — темы и тип, у событий — формат, даты, язык, цена, без заявки, у сообществ — тип вступления; недавние запросы, подсветка совпадений, «ничего не найдено → сбросить фильтры». Люди ищутся по нику и имени даже с выключенными знакомствами — фильтры возраста и желаний есть только в «Люди» (правило R03).
- **Док больше не перекрывает контент:** правило «есть стрелка назад — нет дока». На внутренних экранах кнопка действия в закреплённой нижней панели, у списков отступ под док. Тосты поднимаются над доком или панелью.
- **Тосты и ошибки:** успех, предупреждение, ошибка с «Повторить», отмена действия («Отменить» после отказа, отзыва, архива). Режим «нет сети» в панели экранов: все серверные действия честно падают, сообщения и ответы показывают «не отправлено · повторить», текст не теряется.
- **Валидации:** почта, код (неверный/истёк/попытки/повтор через 30 с), ник (формат, длина, занят, «свободен»), дата рождения, согласие с условиями, поля публикаций, опросов, событий (дата в прошлом, конец раньше начала, адрес/ссылка, цена), заявки, сообщества, удаление аккаунта вводом ника. Ошибка у поля + встряхивание + фокус на первом ошибочном поле.
- **Google и Apple:** на экране входа и регистрации. Выбор аккаунта Google; Apple со «Скрыть почту». Существующий аккаунт сразу входит, новый идёт в профиль. В «Настройки → Вход и безопасность» можно привязать и отвязать способы входа (последний отвязать нельзя) и завершить чужую сессию.
- **Дата рождения при регистрации:** день / месяц / год, проверка существования даты, «Тебе 32» после выбора, моложе 18 — отдельный экран без создания аккаунта. Дата никому не видна; в профиле только возраст и только при включённых знакомствах. Это самодекларация — для 18+-функций остаётся отдельная проверка возраста (селфи или документ), как требует спецификация.

| Адаптивность: телефон — док; планшет — рейка; компьютер — боковое меню, рабочая колонка и правая колонка контекста; окна — центрированные диалоги | AGENTS.md §2: все форм-факторы первого класса |

## Как переносить в React (для ChatGPT/Codex и следующих сессий)

1. Сначала модель состояния: `rsvp[eventId]`, `discussion.community`, `reqOut[].status`, производные счётчики. Это закрывает 8 из 11 багов независимо от вёрстки.
2. Навигация: параметры принадлежат маршруту (`/design/P01?person=mia`), `go(next, params)` не копирует чужие параметры; у экрана — проверка обязательных параметров.
3. Разбить `product-design.tsx` на файлы по разделам, как `prototype/v5/s-*.js`; один экран — одна функция.
4. Перенести токены и компоненты из `prototype/v5/styles.css`: баночки, круги совпадения, вуаль, карточка подборки, события, нижние окна, тосты, валидация полей.
5. Тосты и ошибки — общий провайдер; любое серверное действие: кнопка в состоянии загрузки → успех по ответу сервера → ошибка с «Повторить» без потери ввода.
6. Сверять с V5 на 390 / 820 / 1440 px и в обеих темах; `qa-prototype-v5.mjs` — образец автоматической проверки локализации.
