# FetUre — Product UX V2: целостный дизайн до MVP

> Статус: **целевой UX/visual contract, не реализованный код** (12.10.2026). Источник: пользовательские замечания, загруженный/репозиторный Claude HTML, реальный React source review и текущий MVP-plan. Gate: #1015, coordinator #908, real-device #869. Это не разрешение открывать неготовые приватные функции.
>
> Главный критерий: **единое приятное приложение с понятными действиями**, а не набор аккуратных карточек, успешных CSS-PR и зелёный CI. Старый HTML не копировать как DOM или данные. Текущий React/AppBase/Core/серверные контракты сохранить.

## 1. Выявленные проблемы: подтверждение по исходникам (не browser acceptance)
1. `experience.tsx`: `/` сейчас является `world` и визуальной домашней страницей одновременно; `/explore` показывает похожие категории. Нет самостоятельного пользовательского «что дальше». Текущий `navigation.ts` знает только `world/explore/community/dating`.
2. `app.tsx`: страница Account и общий Shell имеют иную навигацию/структуру, чем `FetureExperience`; цельное ощущение приложения и переходы между разделами отсутствуют.
3. Приветствие/onboarding в Claude прототипе присутствуют, но отсутствуют как законченная consumer-first последовательность с настоящими маршрутами и проверяемым завершением; текущие 7 полей профиля не заменяют продуктовый onboarding.
4. `experience.tsx` dating использует локальное `datingEnabled`, `PROFILES` и изображения `profile-*.webp` как показ, а не серверные профили/consent/права. **Запрещено считать реальными знакомствами** или выдавать выбор из демонстрационного массива за текущих пользователей.
5. `tokens.css` объявляет Geologica/цвета/радиусы, однако выразительная геометрия шрифта (`SHRP`, `CRSV`), пластика слоёв, glow/glass/media, переходы карточек и последовательные микровзаимодействия из Claude не стали экранной системой.
6. `app.tsx` / сохранение и выход: техническое предупреждение «только на этом устройстве» может быть реальным для ещё не отправленных изменений; нельзя обещать стопроцентный cloud sync/стирать безусловно. Нужно отличать **«Всё сохранено» / «Сохраняем…» / «Без интернета. Изменения сохранятся и отправятся позже» / «Перед выходом есть несохранённые изменения»**. Последние показывать только при настоящем риске. Server truth и retry менять только с отдельным функциональным review.
7. Список Issues дробит дизайн на CSS, навигацию, формы и tests; milestone screen quality должен описывать экран, связанный путь, 5 главных отличий от Claude, states, animation and evidence. Последние #1013/#1018 — полезные промежуточные PR, **не финальная visual acceptance**.

## 2. Пользовательская архитектура и нижняя навигация — выбранный кандидат для проверки

**Основной кандидат: пять фиксированных пунктов, в одинаковом порядке для phone/tablet/desktop.**
1. **Главная** (`/` для вошедшего): короткая персональная сводка и **одно следующее действие**, недавние темы/тест/дневник, релевантные общественные материалы или события только при разрешённом API. Без повторной карты категорий.
2. **Мой мир** (`/world`): *то, что я уже исследовал и отметил о себе*: личная карта/баночки, прогресс изученных тем, сила/опыт/границы как отдельные измерения; дневник, результаты и приватное редактирование. Ни рейтинга личности, ни совместимости в процентах.
3. **Исследовать** (`/explore`): *то, чего я ещё не знаю*: редакторский каталог с поиском/фильтрами, иллюстрированными категориями, описаниями, объясняющими подсказками, тестами/историями. Вхождение в тему понятно: «Изучить» → «Добавить в мой мир». Не повторять личные jar-progress карточки.
4. **Сообщество** (`/community`): лента, сохранённое, группы, события и обсуждения внутри одного hub. Внутренние tabs/фильтры для «Лента / События / Группы», без 6–7 нижних иконок; разделы показывать по наличию server-backed контракта.
5. **Я** (`/account`): профиль, приватность/доступ, документы, настройки, выход. Не смешивать каталог тем и аккаунт, не прятать безопасность в длинные страницы.

**Знакомства** остаются самостоятельным `/dating`, вход через заметную contextual CTA на Главной/Сообществе и персональную настройку; не рекламировать их как обязательную функцию. На desktop — отдельный пункт sidebar после добровольного включения. При opt-out — понятный экран объяснения/включения, без демонстрации живых чужих профилей. **НЕ менять динамически пять основных иконок и не переназначать их местоположение**. Вариант с постоянным пятым «Знакомства» рассмотрен и отклонён как MVP-default: навязывает optional dating и убирает вход в настройки. Проверить 5 пунктов на ширинах 320/390 и крупном тексте; при несоответствии адаптировать labels, а не tap targets. На desktop отдельная боковая навигация и плотная многостолбцовая композиция; на tablet/fold deliberate 2-column shell.

**Договорённость о маршрутах:** новые `/world` и guest welcome, авторизованная `/` → «Главная»; прямые `/explore/:id`, `/community`, `/dating`, `/account` и существующие deep links сохраняются. Миграцию роутинга выполнять лишь отдельным PR после проверки URL/Back, не ломать `useQueryOverlay`, scroll restore, protected paths и Core session.

## 4. Визуальная ДНК — не ограничиваться CSS tokens
- **Шрифт**: Geologica variable один раз с offline fallback; display/headings `font-variation-settings: "SHRP" 70–100` и плотной межбуквенной пластикой, выделенные подписи возможны `CRSV`, но не в длинных инструкциях; проверить на кириллице и 200% zoom. Body 14–16px, тексты без 9–10px основной информации.
- **Графика и фоны**: атмосферные цветовые `radial-gradient` + локальные слои/иллюстрации. На Welcome, смысловых hero, editorial каталогах и событиях — осмысленные background/cover media; при отсутствии лицензированного/безопасного изображения градиентная композиция, **не** случайное фото/не «фиктивные люди». Настоящие photo-карточки только с разрешённой сервером медиадоступностью. Respect data saver, slow connection and dark/light.
- **Материалы**: слегка прозрачные панели, `backdrop-filter` dock/header/sheet с solid fallback, тени/edge highlights и аккуратная глубина; контраст поверх фото/стекла >=4.5:1 для small text, не blur ради blur.
- **Свет и цвет**: accent latex rose, secondary lilac, смягчённый neon glow для первичных CTA/выделений, не везде одновременно; warm backgrounds, тёмные многоуровневые surfaces, контраст focus/active/error, subtle grain only if cheap/static.
- **Motion как поведение**: press 110–150ms; chip feedback 140–190ms; card reveal/navigate 240–340ms; modal/sheet 280–360ms с backdrop+focus return; jars fill or milestone celebration только по истинному изменению модели; dating horizontal swipe/return spring, vertical scroll not stolen; no fake loading/irritating infinite shimmer; prefers-reduced-motion removes spatial movement. Motion/react existing; no new heavy libraries.
- **Эффекты**: видимый hover на desktop, touch feedback, magnetic feel без тяжёлой физики, choice chips animate only after confirmed action, skeleton loading without content jumps, sticky blur dock above safe-area, sheets above dock with scroll containment. Задача — tactile feeling и ясное взаимодействие, а не «все анимировать».
- **Пустые состояния**: иллюстрированные, эмоциональные, **честные**: «Пока нечего показывать — начни с ...», offline+retry, без статических псевдопубликаций.
- **Единый desktop/tablet**: редактор/детали рядом со списком, хорошие reading widths, не phone simulator; split view там, где он сокращает действия. Onboarding/welcome маркетинговая сетка desktop independent.

## 5. Язык интерфейса: запрет на отладочную речь
- Писать про результат человека, а не про архитектуру: «Данные на устройстве», «локальная очередь», «CAS», «ревизия», «проверить хранилище», «demo» — не обычный consumer copy. Сохранённые сервером данные: **«Сохранено»**. Сохранение без ответа: **«Не удалось подтвердить сохранение. Повторить»**. Офлайн: **«Нет соединения. Твои изменения не пропадут; отправим их при подключении»** только когда actual queue гарантирует это. Перед выходом при несинхронном draft: **«Есть изменения, которые ещё не отправлены. Выйти и потерять их?»** только если реально true. Нельзя молча удалить предупреждение о риске потери данных.
- Развести «Мой мир» = *про меня*, «Исследовать» = *про новое*: уникальные illustration/hierarchy/copy, не две копии одинаковой category grid. Подсказки к интересам/границам не превращать в совместимость/консенсус.
- Никаких `QA`, `mock`, `test account`, `UnMute` и прочей технической речи в consumer UI, даже если контент prelaunch. Provenance остаётся admin/backend.

## 6. Очередь задач и управление PR
0. **#1015 (P0)** — сравнить реальные собранные экраны + перезапустить visual criteria. Статус source audit отдельно от реального screenshot review.
1. **DUX IA + shell/nav/home** — план маршрутов/экранных схем, новая 5-tab навигация в единой оболочке для Home/World/Explore/Community/Account; право на frontend-only visual PR после UX contract.
2. **Welcome + onboarding** — полноценный публичный и first-use сценарий, отдельно не блокируя Core auth/18+. Реальный возрастной допуск не симулировать.
3. **Visual language** — SHRP/CRSV/gradient/glass/media/motion как проверенная система, первый assembled эталонный экран. Не перекрашивать целиком старое приложение одной простынёй CSS.
4. **World / Explore** — разнести назначение и layout, сохранить данные/исходные маршруты/overlay/queue; затем questionnaires/journal/profile — пройти полную сценарную цепочку.
5. **Dating D02** — production-level UX prototype/contract с backend-gated empty/opt-in; функциональные D01/3/4/5 не выдавать за готовые. **Никаких fake live profiles**.
6. **Community + Events + Groups** — визуальная доводка реального C02; #1020–#1023 только после server gates, не изменять конкурентные backend SQL/media.
7. **Admin** — пройти цельный mobile/editor/queue путь внутри AppBase.
8. **#869 assembled visual/device QA + #870 release** — фактическая приёмка, отдельно от merge.

**Для каждого экранного milestone:** 10–20 строк UX-contract (цель/главное действие/secondary paths/пусто/loading/error/offline/Back/keyboard/сохранение, 320/390/768/1024/1440 + zoom200). Перед/после **настоящие React** captures 390 и 1440 light/dark + короткое видео важных motion; сравнение с Claude по 5 отличиям. Код в небольших независимых PR, автоматическая CI + read-only review, агент может safe merge без ожидания владельца. При недоступном browser — `VISUAL QA BLOCKED`, не `DESIGN DONE`; физический Android/iOS/fold — #869. Скоуп backend/auth/privacy/API/CAS/photo/SQL по-прежнему за отдельными сессиями.

## 7. Что НЕ принято и требует честной маркировки
- Пять нижних иконок — предложенная IA, **не протестирована** на настоящем 320px, 200% zoom/rotated/fold/screen reader.
- Welcome, новый home и весь onboarding **не реализованы этим документом**. Routes нужны отдельным PR с обратной совместимостью ссылок.
- Dating cards с реальными людьми, match, чат, private media, event RSVP, public views **зависят от server ACL/age/consent**, не оживляются фиктивными данными.
- Фотографии/background art должны пройти авторское право, разрешения, контраст и performance; использовать generic artwork где источник недоступен.
- Не считать CSS-срез или documentation-PR визуальной/production приёмкой.
