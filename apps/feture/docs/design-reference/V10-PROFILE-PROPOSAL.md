# V10 — следующий согласуемый срез: анкета «О тебе»

14.10.2026. Статус: предложение для обсуждения, НЕ реализовано.

## Зачем и граница

V10 — кликабельная спецификация для переноса в основное React/AppBase-приложение. Не переносим имитации авторизации, платежей или seed-хранилище как рабочую архитектуру. Фиксируем поля, видимость, пользовательские переходы и состояния; существующий основной сервер остаётся владельцем прав.

Предложение первого UX-среза ограничено четырьмя полями личности: гендер, ориентация, формат отношений и роль. Фото, дата рождения, проверка возраста, доступы и навигационная структура сейчас не меняются. Нельзя исправить всю модель профиля одним маленьким PR.

## Радиус изменений — до UX-решения

| Поле / действие | Где используется |
|---|---|
| gender / orient | A05, P02, P01/P03, meAsPerson/publicField, whoLine, карточка D03; gender в dating filters |
| format | A05, P02, P01/P03, shared и passDating; уже массив, допускает несколько значений |
| role | A05, P02, P01/P03, shared и passDating; сейчас одно значение или null |
| vis четырёх полей | applyIdentityDraft, редактор P02, публичная проекция, сравнение и карточки |
| Сохранение / пропуск | Черновик A05, переход к интересам/сообществам; заполнение позже через P02 |

Потребители: `s-auth.js`, `s-profile.js`, `core.js`, `ui.js`, `s-people.js`, `s-me.js`; проверки существующих `s-settings.js` search и `s-location.js` не должны получить новое побочное поведение. `data.js` и OPT остаются едиными справочниками. Сохранение одной анкеты не включает знакомства, не открывает приватное и не создаёт Match/Chat. Новые поля/права на сервер не добавляем.

## Сейчас

A05 делит четыре необязательных поля на последовательные части: кто ты → ориентация → формат → роль. Редактор P02 показывает те же значения другим способом. Пользователь должен помнить, где их поменять; каждый переход добавляет действие. Обработчик skip при наличии identity draft сейчас применяет его — значение «пропустить» может быть неоднозначно после выбора.

## Предлагаемое поведение

1. Вместо четырёх последовательных частей A05 — один необязательный экран «О тебе» с четырьмя компактными секциями. Частые варианты сразу доступны; длинный список раскрывается по «Все варианты» с поиском.
2. Две явные кнопки: «Сохранить и продолжить» и «Заполнить позже». Первая применяет текущий выбор; вторая не сохраняет черновик этого экрана. Прежние сохранённые данные не очищаются.
3. По умолчанию новые значения видны только самому пользователю. Короткое объяснение: «Видно только тебе. Открыть другим можно в профиле». Не спрашиваем про доступ для каждого поля в onboarding.
4. В P02 — тот же набор вариантов и тот же выбор. Только там доступны настройки видимости полей и preview, потому что оформление публичного профиля — отдельная задача.
5. Значения появляются в карточке, публичном профиле, фильтрах и сравнении по уже существующим правилам. Не меняем алгоритм подбора в рамках этого среза.

**Ожидаемое сокращение:** вместо четырёх экранов и переходов «Дальше» — один экран и одно сохранение; отложить всё заполнение можно одним действием. Для поиска редкого варианта остаётся раскрытие каталога. Это предложение сокращает переходы, а не обещает меньше касаний при любом количестве выбранных вариантов.

## Критерии приёмки и перенос

- gender/orient/format остаются массивами ID; role — ID либо null. Переводы не превращаются в ключи данных.
- Открытие и смена языка не меняют сохранённые поля. Черновик до сохранения не попадает в publicField/shared/passDating.
- «Заполнить позже» действительно пропускает черновик; при повторном редактировании уже сохранённое сохраняется.
- После сохранения четыре поля обновляются синхронно во всех представлениях; visibility не расширяется сама.
- 320/390/768/desktop, RU/EN, клавиатура/Back и каталог не дают переполнения. Проверка новой персоны и заполненного аккаунта.
- При переносе в React нужен один компонент выбора этих четырёх полей, один DTO-адаптер к существующим domain API и существующие серверные проверки видимости. Перезагрузка тестового HTML не переносится в механизм выхода основного приложения.

Реализация этого UX-среза требует отдельного согласования владельца. Текущее «Го» разрешает минимальный повторный старт тестирования и подготовку предложения, не утверждает это новое устройство анкеты.
