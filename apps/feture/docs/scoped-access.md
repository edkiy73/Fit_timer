# P01/P04 — раскрытие по явному разрешению

Профиль и карта закрыты по умолчанию. Поля профиля имеют «Только мне / По разрешению / Участникам»; темы используют те же независимые состояния в редакторе карты. «Участникам» означает допустимый авторизованный adult account, не anonymous страницу. Публичный каталог/правила остаются доступны гостю.

Запрос содержит только opaque profile UUID, выбранные поля/темы и отдельный флаг общения. Owner и viewer выводятся сервером из Core identity и таблицы профилей; email/role/age/SQL не принимаются. Частичное одобрение не может расширить исходный запрос, включает явный срок 1–90 дней. Поле/тема с visibility private не раскрывается grant; сначала владелец отдельно разрешает режим granted. Альбомы подключаются через P02, сейчас scope альбома отклоняется.

Receipt UUID запроса связан с hash нормализованного payload. Повторы решения не продлевают grant и не восстанавливают его после отзыва. Новый одобренный запрос явно заменяет старый grant этой пары, без скрытого объединения scope. Отмена pending и отзыв разрешения идемпотентны. Block сериализуется теми же упорядоченными profile locks, отзывает grants в обе стороны и отменяет pending; unblock не восстанавливает доступ.

`feture_profile_project/preview/visible` возвращают whitelist fields/topics до передачи в браузер. Нет private counts, source/test revision, owner hash, email, discovery flags или клиентской фильтрации приватного payload. Предпросмотр конкретного получателя использует действующий grant и те же block/eligibility правила; вариант без получателя показывает public projection. Сам владелец по ссылке на профиль видит эту публичную проекцию. Чужой профиль проверяет live Core account existence, production proof/единственную enabled policy/expiry и канонические согласия. Пока production policy отсутствует, public Actor не получает adult authorization.

Permission lists — только собственные метаданные с UUID cursor и максимум 30 строк; correlation ID не подменяет persistent access ID. Отозвать/заблокировать и читать свои permission metadata можно после expiry возраста/согласия; личные значения профиля/карты в списки не попадают. CanMessage отличается от доступа к данным и не включает пока не реализованный чат. Match позднее не будет автоматически выдавать grant.

Проверки: focused PostgreSQL контракт для трёх аккаунтов, CAS visibility, private field reclosure, частичный scope, отдельный contact, global ID collision, replay after revoke, expiry/block/unblock, public own projection, exact audience preview, cursor pages, actor spoof и запрет anon/authenticated. Live FitT повторяет частичное одобрение/постороннего/revoke replay/block с assertions внутри rollback. Requests/grants/blocks/policies/publications после rollback пусты, Core documents 90. Advisors: только INFO RLS-no-policy для намеренно закрытых таблиц, [описание](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

Live Core OTP/adult/legal acceptance и реальные альбомы остаются открыты. Нельзя считать полный P01 принятой production-функцией только по SQL fixture. Блокировки применяются к profile/request/grant; новые community/dating/chat queries обязаны применять тот же predicate перед выдачей.
