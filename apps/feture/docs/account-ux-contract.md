# A06.ux — аккаунт и личный профиль FetUre
**Контракт для Issues [#873](https://github.com/edkiy73/Fit_timer/issues/873) → [#874](https://github.com/edkiy73/Fit_timer/issues/874) → [#875](https://github.com/edkiy73/Fit_timer/issues/875).** Дизайн: [эталон](design-reference/README.md), [адаптивная приёмка](ui-quality.md), [A06](mvp-plan/cards/A.md). Не подменяет backend, готовность 18+ или проверку на реальных устройствах.

## Сценарий и иерархия
- **Гость:** одна ясная карточка «Твой мир начинается с тебя», пояснение «Можно исследовать темы без длинной анкеты», главный путь «Войти или зарегистрироваться» через существующий Core `SignInForm`; вторичный путь «Исследовать». Без чужих профилей, фальшивой статистики или обещаний облачного сохранения гостю.
- **Вход выполнен:** сначала персональное приветствие (`session.handle`, иначе нейтральное «Твой аккаунт»), затем основной маршрут **«Мой профиль»** с кратким объяснением приватности и добровольного заполнения. Далее 2 самостоятельные группы: **«Твой мир»** (дневник, ссылки на темы, сравнения по согласию) и **«Контроль и безопасность»** (видимость/доступ, документы/согласия, возраст, обращения). Настройки языка и темы — в компактной группе; «Выйти» отдельно внизу. E-mail — служебная подпись аккаунта, не публичное имя.
- **Редактирование:** `/profile` открывает обзор заполненности без процента «готовности». Одно поле/небольшая смысловая группа редактируется в компактном экране или доступном dialog/sheet, не семь развернутых инпутов на длинной странице. Пользователь может пропустить любое поле, вернуться и сохранить в любой момент. После изменения показать несохранённость; `Отмена` / Back / Escape не должны терять правки без предупреждения.
- **Onboarding:** необязательное вводное пояснение ценности карты интересов, затем «Исследовать» или «Рассказать о себе». Не блокирует продукт, не запрашивает 18+ в качестве фальшивого подтверждения и **не включает знакомства**. Отдельный будущий dating opt-in на своём маршруте.

## Только реальные возможности API
- В Core auth уже доступны текущие `session.email`, `session.handle`, восстановление сессии, `logout`, `SignInForm`. Сохранение ника/внешних полей Core отдельно не обещать; поле профиля `nickname` не должно молча переписывать `session.handle`.
- `profile.read` и `profile.save`: ровно 7 необязательных строк — `nickname` (80), `about` (2000), `pronouns` (160), `identity` (160), `orientation` (160), `relationships` (160), `city` (120); серверная ревизия + `operationId` и защита от чужой сессии. Никакой даты рождения, адреса, точной геопозиции, публичности по умолчанию.
- Существующие ссылки ведут на реальные `/journal`, `/share-links`, `/comparisons`, `/access`, `/safety`, `/documents`, `/verification`, `/explore`. В разделе возраста показывать только честный результат сервера: `unavailable` пока нет рабочего provider/права; QA-допуск не называть реальной верификацией.
- **Не заявлять до A01/A04/A05 и живой проверки:** доставку OTP всем адресатам, успешно подтверждённые 18+, опубликованные юридически согласованные документы, видимость чужим людям, подписки, лайки и мэтчи. Скрыть QA/operator из обычной иерархии; рабочий маршрут не удалять и не обходить его серверные роли.

## Состояния и защита данных
- `auth.loading`: короткий skeleton/status без мелькания гостевых данных. Гость и истёкшая сессия: никаких прошлых данных, аккуратный вход.
- `profile.read` loading/empty/error: ясно отличать пустой профиль от сетевой ошибки; «Повторить» не затирает несохранённые поля. `save` pending: блокировать двойной submit; при потере ответа повтор с **тем же operationId**. При version conflict показывать выбор обновить/оставить введённое; не терять ввод и не заявлять об успехе до server ACK.
- Logout: сохранить действующий `prepareLogout → auth.logout → finishLogout / appDocs.clear`; предупреждать о локальных правках, не очищать приватное при отказе/logout error. При переключении владельца не показывать старые значения даже на мгновение; stop/ignore старых ответов.
- Ошибки — рядом с действием и с `role=alert`; успех — `role=status`, без ложных «проверено» и технического stacktrace. У пользователя всегда есть безопасный путь назад.

## Адаптация и движение
- **390/320:** короткая hero-карточка, один основной CTA, 2–3 компактных входа в разделы, нижний dock учитывается; редактор отдельным экраном/scrollable sheet c внутренним скроллом, 44px интерактивные зоны, safe areas и клавиатура.
- **768/1024:** 2 колонки (профиль/«Мой мир» + контроль/настройки); редактор не растягивать на всю ширину; удобные focus и длинные тексты без overflow.
- **1440+:** полноценная страница с самостоятельной боковой навигацией AppBase и рабочей областью, ограниченной комфортной шириной; не «телефон в рамке». Контент не должен тянуться на 1440px строкой.
- Geologica (одна загрузка с fallback), тёплые light/dark, красный основной/лиловый вторичный, иерархия радиусов/отступов из референса. Motion только opacity/transform ~120–340 мс, reduced-motion без переходов, без скачков высоты. Tab/Escape/Back, фокус и 200% zoom — часть приёмки, а не дополнительная функция.
