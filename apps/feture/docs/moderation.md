# P03.1 — профильные жалобы, ручной разбор и апелляции

`moderation.report/status/appeal` проверяют настоящую Core device session и разрешают обращения после expiry возраста/согласия. Owner/role/snapshot/client verdict не принимаются. На профиль можно пожаловаться по его opaque UUID; неизвестный или заблокированный target не раскрывает существование/закрытые сведения в ответе. Receipts UUID+hash не дублируют обращения. 10 жалоб и 5 апелляций в день на аккаунт, плюс общая quota. Автоматического бана по числу жалоб нет.

Модератор получает только текст, который заявитель явно направляет ему, и одно выбранное доступное поле профиля. Snapshot создаёт сервер: свежий Core target, production age/consent eligibility, block и field visibility/grant. Недоступное поле даёт пустой snapshot. Дневник, вся карта, verification documents, email, tokens и чужие owner hashes не входят в case DTO.

AppBase product Admin предлагает приоритетную очередь cases/appeals, bounded cursor, явное подтверждение просмотренного решения, expected revision и UUID retry. Dismiss/hide/suspend/restore записываются вместе с санкцией атомарно. Санкция закрывает peer eligibility, отзывает grants и pending requests. Снятие/expiry не восстанавливает grants. Старый случай не снимает ограничение более нового. Решения неизменяемы и содержат только operator label/action/reason/duration/case ID, без личного текста. Текущий защищённый общий Admin key честно обозначен `core-admin`; индивидуальные роли/атрибуция — незавершённый O02.

Апелляция доступна только subject account соответствующей санкции, отдельно от заявителя. Один open appeal на case+owner; повтор не дублирует. Решение закрывает текущую апелляцию. Клиент связывает несохранённый текст с case, смена случая не переносит текст автоматически.

`moderation-engine.js` — изолированный typed automatic label adapter: два bounded вызова, timeout/abort, строгий `{label}` whitelist, failure остаётся `manual_required`. Он не публикует UGC, не закрывает case и не вводит sanctions. Реальный vendor/worker пока не подключён. Типы post/comment/media/message добавляются вместе с C/P02/D04 domain adapters; сейчас API поддерживает профиль, не выдаёт другие типы за рабочие.

Проверены полный FetUre check, focused PostgreSQL roles/ownership/snapshot/CAS/replay/appeal/newer-case protection/daily quota и timeout fixture. Schema применена в prelaunch FitT. Live service-role assertions report→no-auto-ban→manual hide/retry→own appeal→restore выполнены внутри rollback; reports/decisions/restrictions/appeals/policies/publications пусты, Core documents 90. Advisors только INFO для намеренно закрытых RLS таблиц: [описание](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

Открыто: production auth/adult/legal setup, реальные люди/ответственный оператор и контакты, индивидуальные staff roles, автоматический moderation/media vendor, integration всех будущих UGC queries, согласованные retention/purge. Это работающий проверенный контракт ручной профильной модерации, не заявление о полной готовности сообщества или production launch.
