# S4. Модерация и админка

27.10.2026. Часть серверной спецификации ([README](README.md)). Обязательна до того, как медиа и публикации станут видны другим людям: правила магазинов (Apple 1.2 — фильтр, жалобы, блок, быстрая реакция), закон о цифровых услугах ЕС (DSA) и обязанности по CSAM.

Что переиспользуем из старого кода: экран операторов `/#/operator` и роли, журнал решений только на добавление, повтор решения после обрыва сети по UUID, движок авто-меток (`moderation-engine.js`). Владелец данных в новой модели — профиль, сотрудник — аккаунт с ролью.

## 1. Сотрудники и роли

| Роль | Что может |
|---|---|
| `owner` | Назначает и снимает роли, видит всё, решает всё, кроме того, что касается его собственных профилей |
| `lead` | Как модератор + апелляции, санкции «блокировка аккаунта», настройки правил (скрытые темы, зарезервированные ники) |
| `moderator` | Очереди медиа, публикаций, сообществ, событий, жалоб, споров «это я на фото»; санкции до «ограничения» |
| `verifier` | Проверка фото («это я»), спорные случаи проверки возраста, названия городов |
| `auditor` | Только чтение журнала решений и статистики, без содержимого |
| `support` | Видит статус обращений пользователя по его запросу, без содержимого жалоб |

Правила:
- Сотрудник — обычный аккаунт FetUre (вход Core) с записью в `staff_role(account_id, role, granted_by, granted_at, revoked_at)`. Отзыв роли действует на следующем запросе.
- Вход в рабочий экран — отдельный поддомен админки, сессия не дольше 12 часов. Обязательная вторая проверка (одноразовый код на почту при каждом входе; позже — ключ доступа/passkey).
- Сотрудник не решает ничего о своих профилях и о профилях, где он участник пары.
- Все команды сотрудников — `staff.*` в `/api/fe`, проверка роли на сервере. Клиент роль не передаёт.

## 2. Очереди

| Очередь | Что попадает | Цель по времени | Кто |
|---|---|---|---|
| CSAM | Совпадение сканера (`safety.csamMatch`) | Сразу, автоматически (§5) | система, затем `lead` |
| Жалобы «несовершеннолетний» | `report.reason = minor` | ≤ 1 ч | moderator |
| Медиа на проверке | `media_asset.state = needs_review` (нет сканера, неуверенный классификатор, проверка фото) | ≤ 30 мин (V21: «обычно до 30 минут») | moderator / verifier |
| Споры «это я на фото» | `tag.object` от неотмеченного человека | ≤ 4 ч, пост скрыт сразу | moderator |
| Жалобы «угрозы, шантаж» | `report.reason = threat` | ≤ 4 ч | moderator |
| Жалобы «чужие приватные материалы» | `report.reason = private` | ≤ 4 ч, медиа скрыто до решения | moderator |
| Сообщества и события | до публикации и крупные правки (Q15) | ≤ 1 ч (V21: «обычно до часа») | moderator |
| Остальные жалобы | `spam`, `other` | ≤ 24 ч | moderator |
| Апелляции | на санкции и удаления | ≤ 72 ч, решает другой сотрудник | lead |
| Города | `place.state = pending` | ≤ 7 дней | verifier |

Порядок в очереди: категория → число независимых жалоб → возраст карточки. Жалобы на один объект объединяются в один случай.

## 3. Случай и решение

- `moderation_case(id, target_type, target_id, target_version, queue, priority, state open|decided|appealed|closed, opened_at, decided_at)`. Цель: `profile | post | reply | discussion | community | event | message | media`.
- Снимок цели делает сервер при открытии случая (текст, ссылки на медиа) и хранит отдельно от живого объекта, чтобы удаление автором не уничтожило материалы. Медиа в снимке — только ссылки на `media_asset`, удаление файлов приостанавливается, пока случай открыт.
- `moderation_decision(case_id, staff_account_id, action, reason_code, note, created_at)` — только добавление. Действия: `dismiss`, `remove_content`, `restore`, `label_explicit`, `restrict_profile`, `suspend_account`, `ban`, `escalate`.
- Решение принимается по конкретной версии цели (ревизия); если цель изменилась — карточка обновляется, решение по старой версии запрещено.
- Повтор решения после обрыва сети — тем же UUID (как сейчас в P03.2).
- Сотрудник видит содержимое только в карточке случая; каждый просмотр медиа сотрудником пишется в `staff_media_view` (кто, что, когда). Медиа в админке размыто по умолчанию, открывается нажатием.

## 4. Санкции

| Санкция | Действие |
|---|---|
| Удаление контента | Объект `removed`, автор видит пометку и причину; медиа хранится 30 дней для апелляции |
| Метка «откровенное» | Медиа остаётся, но уходит из публичных мест (S3) |
| Ограничение профиля | Убрать из подборки и поиска, запретить новые симпатии, запросы доступа и сообщения; отозвать выданные доступы |
| Блокировка аккаунта | Все профили аккаунта `suspended`, сессии отозваны; пара — остановлена (S1 §5) |
| Бан | Блокировка + метка на ключ входа Core (как метка «младше 18»): повторная регистрация с той же почтой невозможна |

Автоматического бана по числу жалоб нет. Пользователь получает **обоснование решения** (DSA ст. 17): что, на основании какого правила, как обжаловать.

## 5. CSAM

1. Сканер нашёл совпадение → медиа `blocked`, ни одной копии не публикуется (S3), профиль-владелец и аккаунт сразу `suspended`, сессии отозваны.
2. Оригинал и метаданные (хэш, время, аккаунт, IP-журнал, если есть) копируются в отдельное хранилище улик с доступом только у `owner`/`lead`; срок хранения — по требованию закона (не меньше 90 дней, по запросу органов — дольше).
3. Сотрудник с ролью `lead` подтверждает совпадение (без повторного просмотра, если совпадение по базе хэшей), и сервис отправляет уведомление: NCMEC CyberTipline (если провайдер или юрлицо в США) или национальная горячая линия и полиция страны юрлица в ЕС. Шаблон и контакты — в юридическом документе (готовит юрист).
4. Пользователю не сообщается причина «CSAM» (чтобы не мешать расследованию); статус «аккаунт заблокирован за нарушение правил».
5. Ложное совпадение (редко, но возможно) — снимается только `owner` после проверки, с записью в журнал.

## 6. Жалобы от людей (интерфейс уже в V21)

- `report.create`: цель, причина, текст ≤ 500, «также заблокировать», для чатов — выбранные сообщения (Q27).
- Одна открытая жалоба на (жалобщик, цель); не больше 10 жалоб в сутки на аккаунт; жалобщик не раскрывается автору.
- Жалобщик получает итог в уведомлениях (`reportDone` / `reportKept`).
- Механизм уведомления о незаконном контенте для всех, включая людей без аккаунта (DSA ст. 16) — форма на сайте с почтой для ответа.

## 7. Админка (экраны)

| Экран | Содержимое |
|---|---|
| Очереди | Вкладки по §2, счётчики, просроченные выделены |
| Карточка случая | Снимок, история жалоб, история автора (прошлые решения), действия §3–4, поле обоснования |
| Пользователь | Профили аккаунта (без приватного содержимого), санкции, апелляции; поиск по нику — с записью в журнал |
| Журнал | Все решения и просмотры медиа сотрудниками, фильтр по сотруднику и цели |
| Настройки правил | Скрытые темы, зарезервированные ники и стемы, лимиты, тексты обоснований |
| Документы | Редактор правовых текстов (уже есть: `documents-admin.js`) |
| Статистика | Для отчёта о прозрачности (DSA ст. 15): число жалоб, решений, время реакции — без персональных данных |

## 8. Что строить и в каком порядке

1. `staff_role` + вход сотрудника с второй проверкой + журнал (перенести роли из старых `feture_operator_*`).
2. Очередь медиа на проверке и решение approve/reject/label — нужна уже сейчас: без сканера всё медиа ждёт сотрудника.
3. Жалобы и случаи (§3, §6), санкции (§4).
4. CSAM-процедура (§5) — до подключения сканера и до любых публичных медиа.
5. Апелляции и обоснования, форма для людей без аккаунта.
6. Статистика прозрачности.
