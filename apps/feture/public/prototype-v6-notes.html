Что это за версия

V6 — связанный кликабельный прототип для обсуждения и переноса в существующий React/TypeScript/AppBase. Это не замена production backend: вход, проверки, доступы, события, симпатии и оплаты в прототипе иллюстрируются на вымышленных данных. Серверные ACL и реальные аккаунты этой работой не изменены. В React перенесение и backend-подключение остаются отдельной работой. Вся текущая сессия сбрасывается при перезагрузке; язык/тема не равны сохранению доменных данных.

Проверено исходное live-представление V5: Лента, Люди, Чаты, Я, собственный профиль, редактор. Отдельно проверены исходники всех разделов, состояния и переходы. Ошибки privacy/chat/block/undo подтверждены независимым воспроизведением кода, а не только визуальным впечатлением.

Сценарии проверки

1. Вход/регистрация → минимальный профиль → обычное личное пространство. Проверить ошибки, отказ, отсутствие ненужной публикации.

2. Лента → автор → профиль → баночки → объяснение общего. Публичные и скрытые поля не смешиваются.

3. Люди → симпатия → взаимность в Чатах → диалог → архив/прекращение/блок. Права не возникают от наличия записи.

4. Я → карта → интерес/граница/видимость → профиль. Граница не равна нулю интереса.

5. Опрос → назад → пропуск → результат → выбранное применение. Черновик сохраняется, карта не меняется автоматически.

6. События → RSVP/видимость → заявка/адрес/билет → редактор. Все статусы принадлежат конкретному событию.

7. Сообщества → правила → вступление → обсуждение → управление. Чужие личные данные недоступны ведущему.

8. Пара → приглашение → ожидание → общие решения. Одного клика одного участника недостаточно для второго согласия.

9. Материал → файл → аудитория → статус проверки. Не представлять локальный выбор за загрузку.

10. Настройки → язык/тема/уведомления/данные/приватность. Отказы и ошибки не теряют ввод.

Где код и что переносить

Исходники: apps/feture/prototype/v6/; сборщик tools/build-prototype-v6.mjs; результат public/prototype-v6.html. Все изменения сделаны в V6, V5 оставлен для сравнения.

При переносе в React использовать эти состояния и действия через текущий AppBase и существующие domain API, не копировать симуляцию проверок и сетевых успехов. Одни и те же серверные permission проверки обязательны на чтении и записи. Разделённые privacy поля должны приходить уже отфильтрованными с сервера, а не скрываться CSS. Никакого нового auth, SQL или общей инфраструктуры этот прототип не вводит.

Каталог — продуктовый старт для редакторской проверки, не автоматическое копирование всей таксономии FetLife. Ориентир: справка о фиксированных вариантах профиля, каталог гендеров. Собственные свободные значения не изменяют общий справочник.

Файлы/геолокация в этой HTML-версии остаются в памяти сессии. Реальная загрузка, модерация фото, общая база городов/геокодер и серверное принуждение правил знакомств требуют существующих domain API при переносе. Не считать локальную проверку настоящим разрешением backend. Города, введённые вручную, не получают выдуманные координаты. Городской режим не показывает выдуманные километры; «Рядом» требует примерной точки и сопоставимых координат кандидата.

Проверки текущего пакета: typecheck, build, smoke; 176 DOM-рендеров RU/EN; отдельные проверки browser history/replace/черновиков, закрытого возраста, обязательного фото, 10-балльной шкалы, округления координат, жеста/отмены/повторного решения. Независимое read-only ревью без оставшихся существенных блокеров. Результат последующей проверки опубликованной версии записывается в PR.
