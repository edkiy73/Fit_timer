# Fit Timer — контекст проекта

Домашний таймер тренировок. PWA на русском, женская аудитория по умолчанию, телефон —
основной и единственный сценарий использования.

## Устройство

- **Всё приложение — один файл `index.html`** (~9600 строк, ~550 КБ): разметка, стили и вся
  логика внутри. Сборки нет, зависимостей нет, фреймворков нет. Правки идут прямо в этот файл.
- `sw.js` — service worker: страница отдаётся network-first (свежая версия приходит сама),
  статика cache-first. Поэтому обновление у пользователя не требует чистки кэша.
- `manifest.webmanifest`, `icon-*.png` — установка на главный экран.
- Экраны — секции `<section class="screen" id="scrXxx">`, переключение через `show('scrXxx')`,
  полный список в массиве `screens`. Видимостью управляет ТОЛЬКО класс `hidden` через
  `setShown(el, on)` — инлайновый `display` ломает flex-раскладку.
- Хранилище — `kvGet/kvSet` (IndexedDB с откатом на localStorage). Ключи с суффиксом профиля:
  несколько пользователей на одном устройстве.
- Иконки — инлайновые SVG из объекта `ICONS` + функция `icon(name)`. Новые иконки берём оттуда,
  а не из эмодзи и не из внешних наборов.

## Экраны

`scrMenu` (главная), `scrStore` (магазин программ), `scrStart` (перед стартом),
`scrWork` (тренировка), `scrFinish` (итог),
`scrBuilder` (конструктор программы), `scrProgSettings` (настройки программы),
`scrExercise` (упражнение), `scrExAI` / `scrExEdAI` (упражнение через ИИ),
`scrImages` (картинки), `scrText` (создание программы через ИИ), `scrYouTube` (из видео),
`scrEditAI` (доработка программы через ИИ), `scrHelp`, `scrStats`, `scrUserEdit`, `scrOnboard`.

## Что нельзя ломать

- **Формат обмена с ИИ.** Промт (`AI_PROMPT`, `EX_ANSWER_FORMAT`) и парсер `parseProgramText`
  — одна система. Ключи «УПРАЖНЕНИЕ:», «ФОРМАТ:», «ШАГ:», «ПОТОЛОК:», «ЗАМЕНА:» и прочие
  меняются только парами: промт и парсер одновременно, иначе ответы нейросети перестают
  распознаваться. Тот же формат умеет `programToText` — программа выгружается обратно в текст.
- **Прогрессия.** Считается по пройденным тренировкам, а не по календарю. Итоговое значение =
  база упражнения + шаги программы × шаг оси + ручная поправка, но не выше потолка.
  `progFrom` у упражнения — сколько шагов программы ему не засчитывается (замены стартуют
  со своей базы). Календарное поле `progLast` — легаси, писать его нельзя.
- **Две темы.** Тёмная и светлая (`body.light`), обе обязаны выглядеть законченно.
- **Офлайн.** Приложение должно работать без сети: внешних ресурсов, кроме шрифтов, нет,
  и у шрифтов обязателен системный fallback.

## Фичи, которые должны остаться

Программы (несколько вариантов по дням или по очереди), конструктор упражнений с разминкой,
кругами и подходами, три формата упражнения (повторения / повторения и вес / время),
автопрогрессия с потолком и двойной прогрессией, подсказка «можно усложнить» с заменой через ИИ,
создание программы через ИИ (текст, свой ключ Gemini, YouTube), доработка программы через ИИ,
генерация картинок и пиктограмм, тренировка с озвучкой, гонгом, отдыхом и превью следующего
упражнения, hands-free (голос/хлопок), правка веса после подхода, пауза и возврат к прошлому шагу,
незавершённая сессия, финал с итогом и картинкой для шеринга, статистика, календарь, вес, фото
прогресса, достижения, серии, несколько профилей, уведомления по расписанию,
экспорт/импорт программ ссылкой и файлом, обучение,
магазин готовых программ (каталог `STORE_ITEMS` в том же текстовом формате, что и ответы ИИ:
покупка = `parseProgramText` + сохранение, поэтому купленная программа ничем не отличается
от собранной руками; обложки рисуются в SVG на месте, внешних картинок нет).

## Как проверять изменения

Только в реальном браузере — тестов в проекте нет.

```bash
python3 -m http.server 8123        # из корня репозитория
```

Playwright уже установлен: `playwright-core` в скретчпаде, chromium —
`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`. Окно 412×900 (телефон).
Сценарии-драйверы лежат в скретчпаде сессии (`smoke.js`, `flow.js`, `wa.js` и т.п.) — они
проходят онбординг, импортируют программу, гоняют тренировку до финала и снимают скриншоты.
Обязательно ловить `pageerror`: приложение падает молча, экран просто не переключается.

**Шрифты в песочнице не грузятся** (Google Fonts заблокирован), поэтому на скриншотах видны
системные шрифты, а не Oswald/Rubik. Это ожидаемо и не является багом вёрстки — но и у
пользователя без сети должно быть красиво, поэтому fallback-стек обязателен везде.
